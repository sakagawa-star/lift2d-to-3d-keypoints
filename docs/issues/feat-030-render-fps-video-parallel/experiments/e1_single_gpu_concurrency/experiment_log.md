### 予測（実行前に記録）

### 実測・照合

実行: 2026-08-10 21:17 頃、`tmp/run_phase1.sh`（exit 0、総所要 65.8秒、チャンク6個すべて 500/500 描画）

| 項目 | 予測 | 実測 | 照合 |
|---|---|---|---|
| t1 | 0.022（許容 0.018〜0.028） | **0.02188 秒/フレーム**（チャンク1〜5: 54.7s/2500f。各チャンク 10.6/10.6/11.3/11.2/11.0秒） | 一致 |
| M1 | 約 2.5 GiB | **628 MiB**（PID 604005 の最大値） | **乖離（過大予測）**。PLY 139MB のガウシアンはVRAM上でもコンパクトで、CUDAコンテキスト込みでも628MiBに収まった。予測は経験則の粗い当てで、実測が正。VRAM収容判定には実測値を使う |
| GPU使用率中央値 | 約 70% | **36%**（平均34.0%、min 4% / max 40%、定常区間 n=109） | **乖離**。「GPUが遊ぶ」という方向は正しいが程度を過小評価。定常時でもGPUは約1/3しか使われておらず、ループの約2/3はCPU側（float32 6.2MB/フレームのGPU→CPU転送、uint8変換、ffmpegパイプ書き込み）が占める。並列余地は予測より大きい |

乖離2件はいずれも「並列余地の過小評価」方向であり、実験の前提（チャンク並列で重なりを作れる）を弱める方向ではない。原因の解釈を上記のとおり特定し、Phase 2 に進む。

**VRAM収容判定（criteria §2.2）**: 2×M1 + D + 1GiB = 2×0.61 + 0.48 + 1.0 = **2.71 GiB ≤ 15.9 GiB** → Phase 2 実施可（3×M1 でも 3.32 GiB で Phase 3 も実施可）

## Phase 2: 2プロセス同時

### 予測（実行前に記録）

| 項目 | 予測値 | 根拠 |
|---|---|---|
| t2a, t2b | 各 0.023〜0.025 秒/フレーム | GPU使用率36%より、2プロセスのGPU要求合計は約72%で飽和しない。CPU側もコア数28に対し余裕。単独比の劣化はGPUコンテキスト切替と転送帯域の競合分のみと推定 |
| R2 | 約 1.8（1.6〜2.0） | 上記が成り立てばほぼ線形スケール。閾値 1.30 を上回る見込み |
| 定常区間の重なり率 | ≥ 0.95 | 同一負荷を5秒以内に起動するため |

### 実測・照合

実行: 2026-08-10 21:19 頃、`tmp/run_phase2.sh`（p2a/p2b とも exit 0、全チャンク 500/500 描画）。両プロセスの起動時刻差は 0.001秒（ログ1行目のタイムスタンプ差）

| 項目 | 予測 | 実測 | 照合 |
|---|---|---|---|
| t2a | 0.023〜0.025 | **0.02940 秒/フレーム**（チャンク1〜5: 73.5s/2500f） | **乖離（予測より劣化大）** |
| t2b | 0.023〜0.025 | **0.02944 秒/フレーム**（チャンク1〜5: 73.6s/2500f） | **乖離（同上）** |
| R2 | 約 1.8（1.6〜2.0） | **1.487**（S1=45.70 f/s, S2=67.98 f/s） | **乖離（予測レンジ下限を下回る）** |
| 重なり率 | ≥ 0.95 | **0.997**（intersection 73.6s / union 73.8s） | 一致（≥ 0.80 で測定成立） |

**乖離の原因分析**: Phase 2 中のGPU使用率は中央値 49%（平均 47.7%、max 67%、定常重複区間 n=147）で、単独時36%→2プロセスで72%という予測（単純加算）に達していない。GPUは飽和していないのに各プロセスが約34%遅くなったことから、律速は「GPU容量の枯渇」ではなく**プロセス間のCUDAコンテキスト時分割**と推定される。GeForce では MPS なしだと別プロセスのカーネル・転送は並行実行されず時分割で直列化されるため、互いのGPU区間が待ち合いになり、線形スケールしない。予測はこの直列化コストを織り込んでいなかった（利用率の単純加算モデルが誤り）。判定への影響: R2 の実測は locked 閾値 1.30 を上回っており、判定は予測乖離に依存しない。

- プロセス別VRAM: 628 MiB × 2（単独時と同一。VRAM競合なし、合計 1.42 GiB + デスクトップ 0.17 GiB）

## 総合判定

| 判定項目 | 基準（locked） | 結果 |
|---|---|---|
| R2 | ≥ 1.30 → Go | **R2 = 1.487 → Go** |
| VRAM収容 | §2.2 | 2プロセス合計 1.42 GiB ≪ 15.9 GiB。M1=628MiB より計算上は10プロセス超も収容可 |
| Phase 3 | グレー判定時のみ実施 | Go 確定のため**実施せず**（criteria どおり） |

**結論: Go。案C（チャンク並列）は単一GPU（RTX 5060 Ti）でも効果があり、2ワーカーで約1.49倍のスループット。feat-030 のスコープに単一GPU高速化を含める。**

参考（判定外の示唆、設計フェーズへの申し送り）:
- フルNPZ（19.4万フレーム）の見込み: 単独実測ベース約71分 → 2ワーカーで約48分相当
- GPU使用率は2プロセスでも49%であり、3ワーカー以上で追加の伸びが得られる可能性がある（本実験では未測定。ワーカー数の最適値は設計時に検討）
- CUDAコンテキスト時分割が律速のため、CUDA MPS の利用で更に伸びる可能性があるが、本番（A100・複数GPU）では1GPU=1ワーカーが基本形であり必須ではない
