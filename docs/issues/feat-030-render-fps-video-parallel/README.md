# feat-030: render_fps_video.py のチャンク並列レンダリング

- **ステータス**: Closed（2026-08-11 手動テスト合格）
- **起票日**: 2026-08-10
- **由来**: feat-027 の旧FR-006（複数GPU並列）を後続案件に分割した決定（2026-08-07 人レビュー）の後続。

## 概要

`phase4/render_fps_video.py` は現在、チャンク（フレーム数固定の区間MP4）を単一プロセスで直列にレンダリングしている。本案件は、チャンクを複数ワーカープロセスに分配して並列レンダリングする機構（案C）を扱う。

- **ローカル機（gtune2、RTX 5060 Ti 16GB ×1）**: 全ワーカーを同一GPUに割り当てる単一GPU並列（GPUの遊び時間をCPU作業と重ねて埋める）
- **本番（A100 サーバー、GPU 7枚）**: ワーカーをGPU 0〜6 に割り当てる複数GPU並列

チャンクの独立性（自己完結の区間MP4＋チャンク単位の完成判定・再開）は feat-027 の設計（design.md ADR-5）で維持済みのため、分配機構の追加で並列化できる構造になっている。

## 調査フェーズ（完了）

実装に入る前に、**単一GPU上でのチャンク並列に効果があるか**（ユーザー指示 2026-08-10）を実験 e1 で測定した。

- `experiments/e1_single_gpu_concurrency/criteria.md` — 判定基準（2026-08-10 locked、codex-01→02 収束）
- `experiments/e1_single_gpu_concurrency/experiment_log.md` — 予測・実測・照合・判定
- **結果（2026-08-10）: Go（R2 = 1.487 ≥ 1.30）**。2ワーカー同時実行で合計スループット約1.49倍（単独 0.0219 → 各 0.0294 秒/フレーム、GPU使用率 36%→49%、VRAM 628MiB/ワーカー）。単一GPU高速化を本案件スコープに含める
- 次ステップ: requirements.md / design.md の作成（ヒアリング → Codex レビュー → 人レビュー）
