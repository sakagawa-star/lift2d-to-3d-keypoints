# feat-030 ヒアリング記録

- 日付: 2026-08-10
- 前提: 実験 e1（`experiments/e1_single_gpu_concurrency/`）で「単一GPU上のチャンク並列は合計スループット約1.49倍（2ワーカー）」の Go 判定済み

## 決定事項

| # | 論点 | 決定 |
|---|---|---|
| 1 | スコープ | **複数GPU対応を含める**。分配機構は共通で、ローカル（RTX 5060 Ti ×1）は同一GPUに複数ワーカー、A100 サーバー（GPU×7）は別GPUに1ワーカーずつ。複数GPU固有経路（GPU ID 別割当）のローカル検証は同一ID指定に限られる点は手動テストで明記する |
| 2 | CLI 形式 | **`--gpus` リスト**（例: `--gpus 0,0` = GPU 0 に2ワーカー、`--gpus 0,1,2,3,4,5,6` = 7GPU に1ワーカーずつ）。リストの要素数＝ワーカー数。既存 `--gpu` は後方互換で維持し `--gpus` と排他 |
| 3 | 既定動作 | **現行と同じ直列**（`--gpus` 未指定なら従来どおり単一プロセス・インプロセス直列。既存の使い方・YAML設定がそのまま動く）。並列は明示指定時のみ |
| 4 | 失敗時挙動 | **即時中止**（1ワーカー失敗→他ワーカーも停止して終了コード1。書きかけチャンク .tmp は破棄。完成済みチャンクは保持され再実行で続きから再開） |

## 由来・関連

- feat-027 の旧FR-006（複数GPU並列）の後続案件（2026-08-07 人レビューで分割決定）
- ユーザーの当初の関心は「このPC（単一GPU）でレンダリングを並列化できるか」（2026-08-10）。実験 e1 で効果を確認したうえで、複数GPU対応も同一の分配機構でカバーできるためスコープに含めることになった
