# feat-035 Step 2 実験基準: 28ペアマッチ数測定と連結性判定（p0_pair_connectivity）

作成日: 2026-08-17 / ステータス: **locked**（2026-08-17、codex-11〜12 で高・中ゼロに収束）

## 位置づけ

本実験は**基準を測ることがゴールの実験**（測定）であり、パラメータの合格判定は行わない。ただしロードマップ Step 2 に事前定義された **Go/No-Go 判定**（下記 §4。閾値ではなく連結性の構造判定）を含む。N_PAIR_MIN の最終採用値はここでは決めず、Step 7（FR-008）の実験で決定する（本実験での閾値変更は暫定扱い）。

## 1. 答える問い（事前定義）

- Q1: inuyama 実写8枚の全28ペアについて、MASt3R（`--resolution full`）の有効マッチ数 N はいくつか（全ペアの一覧）
- Q2: N ≥ N_PAIR_MIN=50 で採用したペア集合のグラフは、cam05520125/126 を含む1つの連結成分に8台全てを含むか
- Q3: Q2 が No の場合、8台が連結する最大の暫定閾値 N_PAIR_MIN' はいくつか（判定手順: 50 から 5 刻みで下げ、最初に8台連結となる値。5 未満まで下げても連結しない場合は「連結不能」と記録）
- Q4: OOM・エラーになったペアはあるか（あれば一覧と理由）

## 2. 実験手順

1. `adjust_extrinsics_multiview.py` の Stage P（`run_pair_matching`）で 28 ペアを実行する（`--resolution full`、OOM 時は design §2.2 の通り `--resolution 1280x720` で1回再試行）
2. 各ペアのマッチ数・status を記録し、Q1〜Q4 を集計する
3. 中間 NPZ は `<tmp_dir>/pair_<camA>_<camB>.npz` に保存し、Step 7 での再利用に備える

## 3. 直前予測（実行直前に experiment_log.md へ記録する項目の枠）

- P1: N ≥ 50 となるペア数（28 中いくつか）
- P2: 最小マッチ数となるペアの見込み（どの2台か）と、その N の予測値
- P3: Q2（8台連結）の Yes/No 予測
- P4: Q2 が No の場合の暫定閾値 N_PAIR_MIN' の予測値（候補: 45, 40, …, 5 のいずれか、または「連結不能」）
- P5: Go/No-Go の予測
- P6: OOM またはエラーになるペア数と該当ペアの予測

予測の根拠には Step 1 実測（近接ペア 254、対面に近いペア 279）を用いてよい。

## 4. Go/No-Go 判定（ロードマップ Step 2 の再掲。事前定義済み）

- **Go**: Q2 が Yes、または Q3 の暫定閾値 N_PAIR_MIN' が存在する（8台連結が成立する）
- **No-Go**: 暫定閾値をどこまで下げても8台が連結しない。この場合 BA 実装（Step 5）には進まず、ロードマップ記載の3選択肢（閾値リスク受容 / 対象縮小 / グローバル初期化への差し戻し）をユーザーと協議する
- Go/No-Go の判定結果はユーザーの承認を得てから次ステップに進む

## 5. 記録

- 実測・予測との照合・判定は `experiment_log.md` に記録する
- 乖離（予測と実測の食い違い）があった場合は原因を特定してから次フェーズに進む（CLAUDE.md 実験プロトコル準拠）

## 対象外

- マッチの空間分布・精度の評価（本実験はマッチ数と連結性のみ。品質は Step 3 以降の PnP inlier / BA 残差で評価される）
- N_PAIR_MIN の最終採用（Step 7 / FR-008）
