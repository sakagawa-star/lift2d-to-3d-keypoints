## 2. 検証測定（レンダ vs 実写ずれ）

- レンダ: `render_keypoints.py --near-plane 0.25 --no-keypoints --distort`（cage_refined_all8.toml、8台）→ `renders/still_<cam>.png`

### 測定値の解釈（診断）

- ずれの分布は全台で**二峰性**: 0〜2px の鋭いピーク（構造エッジ: 止まり木・フレーム・アクリル縁）と 15〜50px の広い裾（床・天面の**金網領域**）
- 矢印可視化（`renders/shifts_<cam>.png`。緑<5px/黄<15px/赤≥15px）で、大ずれ点は金網の周期パターン上に集中し方向がランダム → 格子ピッチへの **NCC 誤ロック**が原因で、ポーズ誤差ではない
- p0_bootstrap（真のずれ 15〜43px）では真の変位が誤マッチと同程度以上だったため中央値が意味を持ったが、1px 水準に収束した本結果では金網誤マッチが中央値を支配する。**中央値の台間比較は金網の画面占有率の差を反映しているだけ**であり、整合の実態は overlay と <5px モード（全台 1〜2px 水準）が示す
- 全中央値と上段除外中央値の大小逆転（例: cam05520125）は、上段が無地の壁（勾配ほぼゼロ→自明マッチでずれ0）か金網かの構図差によるもの
