# feat-035 Step 3 実験基準: ブートストラップ測定（p0_bootstrap）

作成日: 2026-08-17 / ステータス: **locked**（初回 lock: codex-13〜14。改訂1: `--init-cameras` 明示指定、codex-15〜16 で再 lock。改訂2: §4 目視ゲートを初期化妥当性に改訂、codex-17〜20 の計画修正レビューで収束し再 lock: 2026-08-18。**旧ゲートでの NG 判定の記録は experiment_log.md に保持し、書き換えない**）

## 位置づけ

本実験は**基準を測ることがゴールの実験**（測定）であり、inlier 数・残差の合格ラインは定めない（測定値を記録し、将来の基準策定の材料とする）。ステップの**進行可能条件**のみ、ロードマップ Step 3 / requirements FR-002 で事前定義済みのものを用いる（§4）。

## 1. 答える問い（事前定義）

- Q1: 未較正6台（cam05520128, cam05520129, cam41520554, cam41520556, cam41520557, cam41520558）それぞれについて、ブートストラップの成否・使用ペア（どの較正済みカメラとのペアで成功したか）・ゲート通過対応点数・PnP inlier 数・inlier 再投影 RMSE [px] はいくつか
- Q2: 成功カメラそれぞれについて、推定ポーズでの 3DGS レンダ（near_plane=0.25、歪みあり）と実写の特徴点ずれの中央値 [px] はいくつか（全特徴点の中央値と、画像上段 1/3 を除いた中央値の両方を記録する。上段は天面金網の視点依存レンダ誤差が乗るため分けて記録する。測定方法は feat-026 調査で確立した手法: `goodFeaturesToTrack` 最大400点 + 勾配画像の NCC テンプレートマッチ〔パッチ32px・探索±50px・採択閾値0.45〕）
- Q3: 失敗カメラがある場合、その理由の内訳（対応点数不足 / PnP inlier 不足、試行したペアの一覧）

## 2. 実験手順

1. Stage P の既存マッチ NPZ（p0_pair_connectivity/tmp。再実行しない）を用い、Stage B（`bootstrap_cameras`）を実行する。初期ポーズは `--init-toml cage_refined.toml --init-cameras cam05520125 cam05520126` で与える（**`--init-cameras` の明示指定は必須**。cage_refined.toml は全8カメラのセクションを含み、未精緻化6台には無効ポーズが残っているため、省略すると全カメラが較正済み扱いになり Stage B がスキップされる〔2026-08-17 の初回実行で顕在化した事象〕）
2. 成功カメラごとに `render_keypoints.py --near-plane 0.25 --no-keypoints --distort` でレンダし、Q2 の測定を行う
3. 結果とレンダ比較画像をユーザーに提示する（目視確認）

## 3. 直前予測（実行直前に experiment_log.md へ記録する項目の枠）

- P1: ブートストラップ成功台数（6台中いくつか）
- P2: PnP inlier 数の範囲（最小〜最大の予測）
- P3: 成功カメラのずれ中央値の範囲予測 [px]（「全特徴点」と「上段 1/3 除外」の両方）
- P4: 失敗するカメラの予測（該当なし予測も可。あればカメラ名と理由）
- P5: ゲート通過対応点数の範囲（最小〜最大の予測）
- P6: PnP inlier 再投影 RMSE の範囲予測 [px]

## 4. 進行可能条件と目視確認（事前定義済みの再掲）

- **進行可能条件**: 次の両方を満たすとき Step 3R（Stage R 反復精緻化）へ進む。(1) 6台中1台以上がブートストラップ成功（失敗カメラは除外して続行し、レポートに記録する。FR-002）、(2) 成功カメラの比較画像が下記の目視判定項目を満たす（**目視 NG のカメラが1台でもあれば進行を停止し、調査に戻る**。ロードマップ Step 3 準拠）
- **目視確認の判定項目**（**初期化妥当性**。改訂2〔2026-08-18〕でロードマップ Step 3 と同時改訂）: レンダと実写で同一の構造が対応して視認でき、Q2 の全特徴点ずれ中央値が **50px 以下**であること（Stage R の反復精緻化の収束域。feat-026 は 5cm/2° 摂動〔同水準の画素ずれ〕からの収束を実証済み）。1px 水準の「二重像なし」判定は Step 3R（p0_stage_r）で行う
- **事後解釈の禁止との整合（改訂2の適用範囲）**: 2026-08-17 の実測（experiment_log.md「実測」「照合」「判定」節）は**旧基準で NG のまま保持し、書き換えない**。新基準（初期化妥当性）は本改訂の再 lock 後に行う**改訂2の再実行**から適用する。改訂2の再実行は experiment_log.md に「改訂2」の別セクションを設け、直前予測→実測→照合→判定を新規に記録する（Stage B は決定的処理のため同一結果が見込まれるが、判定はあくまで再実行の実測に対して行う）
- 全6台失敗の場合は理由を添えて報告し、方針をユーザーと協議する

## 5. 記録

- 予測・実測・照合を `experiment_log.md` に記録する。乖離があれば原因を特定してから次フェーズに進む
