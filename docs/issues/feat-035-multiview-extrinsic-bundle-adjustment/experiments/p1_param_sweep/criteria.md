## 位置づけ

本実験は**合格判定ではなく基準値の測定をゴールとする**（design §3）。各パラメータを走査してホールドアウト残差等を記録し、採用値を事前定義の規則（§4）で決める。採用値はユーザー承認を経て本体定数に反映する（roadmap Step 7）。

前提知見（step6_mvp 追加測定 2026-08-25）: 既定値構成でのホールドアウト残差中央値は BA後 0.895px、BA前 0.920px であり、BA の改善幅は 0.025px。したがって**本実験の主目的は「感度の測定と既定値の妥当性確認」**であり、大幅な改善は期待しない（この予断は予測に使ってよいが、判定規則〔§4〕は結果に依らず適用する）。

## 1. 走査計画（事前定義）

走査方式は **one-at-a-time**（1パラメータのみ変更し、他は既定値に固定）。ベースライン（全て既定値）を含め全17設定。共通条件: inuyama 8台、`--seed 5000` 固定、Stage P マッチ NPZ・Stage A アンカー NPZ はキャッシュ再利用（GPU 不要。マッチ・アンカーの再生成はしない）。

| # | パラメータ | 走査値（太字=既定値） |
|---|---|---|
| 0 | ベースライン | 全て既定値 |
| 1 | EPI_TOL_PX | 1.5 / **3.0** / 5.0 / 8.0 |
| 2 | N_PAIR_MIN | 30 / **50** / 100 |
| 3 | HUBER_PX | 1.0 / **2.0** / 4.0 |
| 4 | W_CROSS（W_ANCHOR=1.0 固定） | 0.5 / **1.0** / 2.0 / 5.0 |
| 5 | HOLDOUT_RATIO | 0.1 / **0.2** / 0.3 |
| 6 | THETA_SIGMA_DEG | 7.5 / **15.0** / 30.0 / 交会角重み無効（w_k=1） |

- 実行方法: 実験ドライバスクリプトで本体モジュールの定数を設定ごとに差し替え、Stage F → ホールドアウト分割 → 三角測量 → BA → ホールドアウト評価を実行する（本体コードは変更しない）
- 連結性不成立・エラーとなる設定は「不成立」として記録し、採用候補から除外する（例: N_PAIR_MIN=100 は cam41520554 系ペア〔生存57/79点〕が落ちて連結性が壊れる可能性が高い）

## 2. 記録項目（設定ごと。design §3）

- ホールドアウト残差の**中央値**・**90%点** [px]（n_points, n_residuals も併記）
- **収束反復数**（nfev）と status、BA 最終コスト
- フィルタ後採用ペア数・連結成否（EPI_TOL_PX・N_PAIR_MIN の走査では生存数・生存率のペア別一覧も記録）
- クロス3D点数 M、非悪化フォールバック発動数

注意（比較可能性の限定）: EPI_TOL_PX・N_PAIR_MIN・HOLDOUT_RATIO を変えるとホールドアウト集合自体が変わるため、これらの走査での残差比較は「同一集合上の比較」ではない。この限定は結果の解釈に明記する。

## 3. 直前予測（実行直前に experiment_log.md へ記録する項目の枠）

- P1: ホールドアウト残差中央値が最も動くパラメータの予測
- P2: 全設定での中央値の範囲予測 [px]
- P3: 連結性不成立となる設定の予測（該当なし予測も可）
- P4: 最終的な採用値の予測（パラメータごと）

## 4. 採用値の決め方（事前定義。design §3）

- パラメータごとに、**ホールドアウト残差中央値が最小**の設定値を採用する。同率（0.001px 未満の差は同率とみなす）の場合は**既定値を優先**する
- 連結性不成立・エラーの設定値は採用候補から除外する
- **coverage-aware 制約（EPI_TOL_PX・N_PAIR_MIN）**: これらはホールドアウト集合の構成自体を変えるため、難しい対応点・ペアを落とした設定が見かけ上良く見える。採用候補は「連結性成立」に加えて「**フィルタ後採用ペア数がベースライン（既定値設定）以上、かつホールドアウト点数（n_points）がベースライン以上**」の設定に限定し、その中で中央値最小を採用する（該当候補が既定値のみなら既定値を維持する）
- HOLDOUT_RATIO は評価集合サイズが変わり中央値の直接比較が成立しないため、上記規則の適用対象外とし、**既定値 0.2 を維持**する（走査は感度の記録のみを目的とする）
- 採用値はユーザー承認を経て本体定数に反映する（コード変更は Sonnet 委任。roadmap Step 7）

### §4b 結合検証（追補〔改訂1〕2026-08-25。**今後の採用手順に適用する再発防止規則**）

- one-at-a-time 走査で決めた採用値の**組み合わせ**は、反映前に結合検証を行う: 採用組み合わせで BA を実行し、(1) 収束（status ≥ 1）し、かつ (2) ホールドアウト残差中央値が「走査中の単独最良値 + 0.01px」以下であること
- 結合検証に不合格の場合、**単独改善幅が最小のパラメータから順に既定値へ戻し**、合格する組み合わせのうちホールドアウト残差中央値が最小のものを採用する（戻し・比較の実測はすべて experiment_log.md に記録する）
- 追補の経緯（本規則の遡及適用ではないことの明記）: 当初採用（HUBER_PX=1.0 + W_CROSS=2.0 + w_k=1）は HUBER_PX×W_CROSS の相互作用（実効比 W_CROSS×典型残差/HUBER_PX が約2超で Huber 飽和により勾配退化）で反映後再検証の BA が停滞した。これは当初 criteria の方法上の盲点であり、**今回の採用値改訂（HUBER_PX=2.0 に戻す。実測: status=2、中央値 0.8684px）自体は本規則の適用実績ではなく、分解診断の実測に基づくユーザー承認済み（2026-08-25）の差し戻し**である。本規則は次回以降の採用手順から適用する

## 5. 任意項目の採否（design §3。criteria 作成時に決める）

**アンカーマッチャーの MASt3R 比較（GS-CPR 先例）: 不採用**。理由: (1) アンカーは LoFTR で既に全台上限 3000 点に到達しており点数不足がない、(2) step6_mvp 追加測定で BA のポーズ感度自体が 0.025px と極小であり、アンカーマッチャー変更が採用値を変える見込みが薄い、(3) MASt3R アンカーの生成には GPU 実行と新規実装（レンダ↔実写の MASt3R 呼び出し）が必要でコストに見合わない。将来、別シーンでアンカー不足カメラが出た場合に再検討する。
