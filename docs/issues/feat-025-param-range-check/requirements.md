# 要求仕様書: feat-025 estimate_camera_params.py 推定パラメータの範囲チェック（警告出力）

## 1.1 プロジェクト概要

- **何を作るのか**: `phase0/estimate_camera_params.py` の K未知モード（通常モード）の推定結果に対し、内部パラメータ・歪み係数が妥当範囲を外れた場合に警告を標準出力へ表示する機能。
- **なぜ作るのか**: 過去に p1（接線歪み係数）が 0.5 以上という物理的にありえない値で推定されたが、基準値を知らなかったため長期間異常に気づけなかった。RMSE が小さくてもパラメータ相殺（過学習）で個々の値が異常になり得るため、値そのものの妥当性チェックが必要。
- **誰が使うのか**: 本プロジェクトでカメラキャリブレーションを行う開発者・解析担当者。
- **どこで使うのか**: `phase0/` ディレクトリでの CLI 実行（Linux、Python 3.10、uv 環境）。

## 1.2 用語定義

| 用語 | 定義 |
|---|---|
| K未知モード | `--intrinsic-toml` を指定しない通常モード。内部パラメータ・歪み係数・外部パラメータをすべて推定する |
| K既知モード | `--intrinsic-toml` 指定時のモード。内部パラメータは TOML から読み込み、外部パラメータのみ推定する |
| 範囲チェック | 推定されたパラメータ値が本仕様で定義する閾値範囲内にあるかの判定 |
| 警告 | 範囲外のパラメータについて標準出力に表示するメッセージ。処理は継続し、終了コードは変更しない |
| 接線歪み係数 | Brown-Conrady 歪みモデルの p1, p2。レンズとセンサの傾きに由来し、通常はごく小さい値になる |
| 有理モデル | `--wide` 指定時の8係数歪みモデル（k1〜k6, p1, p2）。分子・分母の放射係数が相殺し合うため個々の値の範囲では妥当性を判定できない |

機能設計書・コード内でも上記と同じ用語を使う。

## 1.3 機能要求一覧

### FR-001: 推定パラメータの範囲チェック

- **機能名**: 推定パラメータの範囲チェック
- **概要**: K未知モードの最適化完了後、下表の各パラメータについて範囲判定を行う。
- **入力**: 推定結果（fx, fy, cx, cy, k1, k2, p1, p2, k3）、画像サイズ（img_width, img_height）、実行モード情報（--fix-center の有無、--wide の有無、--zero-tangent の有無、歪み係数を推定したか）
- **出力**: 範囲外パラメータの一覧（内部データ。表示は FR-002）
- **チェック項目と閾値**（S = max(img_width, img_height) とする）:

| No | 項目 | 正常範囲 | チェックの適用条件 |
|---|---|---|---|
| 1 | fx | 0.3×S 以上 3.0×S 以下 | 常時 |
| 2 | fy | 0.3×S 以上 3.0×S 以下 | 常時 |
| 3 | fx/fy 比 | 0.9 以上 1.1 以下 | 常時 |
| 4 | cx | img_width/2 ± 0.10×img_width | `--fix-center` なし（推定時のみ） |
| 5 | cy | img_height/2 ± 0.10×img_height | `--fix-center` なし（推定時のみ） |
| 6 | \|k1\| | 1.0 以下 | 歪み係数を推定し、かつ `--wide` なし |
| 7 | \|k2\| | 1.0 以下 | 歪み係数を推定し、かつ `--wide` なし |
| 8 | \|p1\| | 0.01 以下 | 歪み係数を推定し、かつ `--zero-tangent` なし |
| 9 | \|p2\| | 0.01 以下 | 歪み係数を推定し、かつ `--zero-tangent` なし |
| 10 | \|k3\| | 1.0 以下 | 歪み係数を推定し、k3 を推定するモード（`--k3` あり）かつ `--wide` なし |

- 補足:
  - `--wide`（有理モデル）では放射係数 k1〜k6 の個々の値では妥当性を判定できないため、放射係数のチェック（No.6, 7, 10）は行わない。p1, p2（No.8, 9）はチェックする。
  - 歪み係数が0固定（点数不足）の場合、固定値0はチェック対象外（No.6〜10 をスキップ）。
  - K既知モードは本機能の対象外（TOML から読み込んだ値は推定値ではないため）。
- **受け入れ基準**: 上表の各項目について、範囲外の値を与えたとき当該項目が警告一覧に含まれ、範囲内（境界値ちょうどを含む）のとき含まれないことがユニットテストで確認できる。

### FR-002: 警告の表示

- **機能名**: 範囲チェック結果の表示
- **概要**: FR-001 の結果を、推定結果表示（再投影誤差の後）と Calib_scene.toml 形式出力の間に `[パラメータ範囲チェック]` セクションとして標準出力に表示する。
- **入力**: FR-001 の範囲外パラメータ一覧
- **出力**（標準出力、日本語）:
  - 範囲外が1件以上ある場合: 各項目につき1行、「⚠ 警告: {パラメータ名} = {推定値} が正常範囲 [{下限}, {上限}] を外れています」の形式で表示し、末尾に対処ヒントを1回表示する。ヒント文は実行モードで切り替える（`--wide` と `--zero-tangent` は併用不可のため、実行可能な対処のみを提示する）:
    - `--wide` なしの場合: 「→ 点対応の誤り・点配置の偏り・パラメータ相殺（過学習）の可能性があります。--zero-tangent / --fix-center の使用を検討してください。」
    - `--wide` ありの場合: 「→ 点対応の誤り・点配置の偏り・パラメータ相殺（過学習）の可能性があります。--fix-center の使用、または標準モデル（--wide なし）への切り替えを検討してください。」
  - すべて範囲内の場合: 「✓ すべてのパラメータが正常範囲内です」を1行表示する
- **受け入れ基準**: 範囲外の値を含む推定結果で警告行とモードに応じた対処ヒント行が表示されること、全て範囲内の推定結果で「✓」行のみが表示されることを、標準出力を捕捉する自動テストで確認できる。

### FR-003: 既存動作の非破壊

- **機能名**: 既存の入出力・終了コードの維持
- **概要**: 警告の有無にかかわらず、推定処理・TOML/CSV出力・終了コードは変更しない。警告は表示のみで処理を中断しない。
- **入力**: なし（制約的要求）
- **出力**: なし
- **受け入れ基準**: 範囲外の警告が出るケースでも `run_estimation` の戻り値が 0 であり、標準出力に「Calib_scene.toml 形式」「camera_params.csv 形式」の両セクションが従来どおり表示されることを、標準出力を捕捉する自動テストで確認できる。

## 1.4 非機能要求

- **パフォーマンス**: 範囲チェックは単純な比較演算のみであり、追加処理時間は 1ms 未満（実測不要、設計上明らか）。
- **対応環境**: 既存と同一（Linux、Python 3.10、uv 管理の phase0 環境）。GPU 不要。
- **信頼性**: 範囲チェック自体が例外を送出して推定結果の出力を妨げてはならない。
- **セキュリティ**: 該当なし。

## 1.5 制約条件

- 新規ライブラリは追加しない（NumPy・標準ライブラリのみで実装可能）。
- 既存の CLI オプション体系・出力フォーマット（TOML/CSV セクション）を変更しない。
- 閾値はコード先頭の定数（UPPER_SNAKE_CASE）として定義する。
- `--wide` と `--zero-tangent` の併用は既存 CLI がエラーにするため、本機能の対象外とする（この組み合わせの動作は定義しない）。
