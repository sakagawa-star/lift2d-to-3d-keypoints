## 背景・変更理由

- 現行の codex exec バッチ方式は、レビューごとに新規プロセスを起動し `-o` + full.log + `resume` でセッションを管理する運用で、(1) 過程ログ（full.log）の管理が煩雑、(2) 定型指示（瑣末な指摘の抑止・重要度分類）を毎回依頼文に書く必要がある、(3) `resume` のセッションID管理が必要、という手間があった
- テンプレート側は fmcs-utils での運用実績をもとに、Herdr の隣接ペインで対話モードの codex を常駐させる方式へ移行した。定型指示は AGENTS.md（Codex CLI が起動時に自動で読む）へ永続化され、会話の文脈保持はストリーム（常駐エージェント）が担い、`/new` による「全文ゲート」（新しい目での最終確認）が制度化された
- 本リポジトリのレビュー運用をテンプレートと揃え、以後の案件（feat-036 以降）で新方式を使えるようにする
