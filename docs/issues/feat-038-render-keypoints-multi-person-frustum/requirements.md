# feat-038 要求仕様書: render_keypoints.py 複数人全員のFPS視錐台の同時描画

作成日: 2026-10-20
基準: `docs/REQUIREMENTS_STANDARD.md`
入力資料: 2026-10-20 ヒアリング（結果は `README.md` の「ヒアリングで確定した要件」に記録）

## 1. プロジェクト概要

- **何を作るのか**: `phase4/render_keypoints.py` の動画モードで、`--fps-person all` を指定すると、描画している全人物の FPS 視錐台（頭部キーポイントから求めた一人称カメラの視野を表す四角錐ワイヤフレーム）を同じ画像に同時に描けるようにする
- **なぜ作るのか**: feat-037 の複数人モードでは視錐台を `--fps-person` で選んだ1人分しか描けない。病室内の複数人（患者と医療スタッフ）がそれぞれどこを見ているかを1本の映像で確認したい
- **誰が使うのか**: 本プロジェクトの研究者
- **どこで使うのか**: phase4 venv（Linux、torch/gsplat、CUDA GPU 必須）。開発・動作確認はローカル機（gtune2、RTX 5060 Ti）で行う。コマンド例に付す `TORCH_CUDA_ARCH_LIST="9.0+PTX"` はローカル機向けの値（`CLAUDE.md` の「スクリプト実行」参照）

## 2. 用語定義

機能設計書・コード内でも同じ用語を使う。feat-037 で定義した用語（人物、人物番号、人物ラベル、複数人モード、1人モード、対象フレーム、欠席、観察カメラ）は feat-037 `requirements.md` 2章と同じ意味で使う。

| 用語 | 定義 |
|---|---|
| 視錐台 | `--fps-frustum` で描く FPS カメラの視錐台ワイヤフレーム（頂点5個・線分8本、マゼンタ）。feat-034 で定義したもの |
| 視錐台対象人物 | 視錐台を描く人物。`--fps-person` の値で決まる（整数なら その番号の1人、`all` なら全人物） |
| 全員指定 | `--fps-person all`（設定YAMLでは `fps_person: all`）の指定 |
| 番号指定 | `--fps-person` に整数を指定すること、または `--fps-person` の省略（既定 1） |

## 3. 機能要求一覧

### FR-001: `--fps-person` に `all` を指定できる

- **概要**: `--fps-person` の値として、従来の整数に加えて文字列 `all` を受け付ける
- **入力**: `--fps-person <整数 | all>`
- **出力**: 値の解釈結果（整数、または全員指定）
- **詳細**:
  - `all` は小文字の完全一致のみ受け付ける（`ALL`・`All`・前後に空白のある値は受け付けない）
  - `all` 以外の値は従来どおり整数として解釈する。整数として解釈できない値（例: `x`、`1,2`）は終了コード 2 のエラーにし、メッセージに「1 以上の整数または all」と指定値を含める
  - 整数の値域検査（1 以上・人物数以下、範囲外は終了コード 2）は従来のまま変えない
  - `--fps-frustum` なしでの指定、`--no-keypoints` との併用が終了コード 2 になる扱いは、`all` でも整数と同じ
  - 省略時の既定値は従来どおり 1（P1 のみ）
- **受け入れ基準**: `--fps-person all` がエラーにならない。`--fps-person ALL`・`--fps-person x` は終了コード 2。`--fps-person all` を `--fps-frustum` なしで指定すると終了コード 2
- **優先度**: Must

### FR-002: 全員指定で全人物の視錐台を描く

- **概要**: 複数人モードで全員指定のとき、全人物それぞれの頭部キーポイントから視錐台を計算し、同じ画像に描く
- **入力**: 各人物の頭部キーポイント（feat-034 の頭部7点）
- **出力**: 全人物の視錐台が描かれた連番PNG / MP4
- **詳細**:
  - 各人物の視錐台の計算方法は、番号指定で1人を描くときと同じ（feat-034・feat-037 の方式を人物ごとに適用する）
  - 色・線の太さ・オクルージョン判定は全人物で共通（色はマゼンタ `FRUSTUM_COLOR`、太さ `FRUSTUM_THICKNESS`。人物ごとの色分け・視錐台へのラベル追加はしない）
  - FOV（`--fps-camera` / `--fps-toml` で選んだカメラ1台）と奥行き（`--frustum-depth`）は全人物で共通
  - あるフレームで、ある人物が欠席、または頭部キーポイントの欠損・縮退で視錐台を計算できない場合、そのフレームではその人物の視錐台だけを描かない（他の人物の視錐台は描く）
  - 全人物の視錐台は、全人物のスケルトンと人物ラベルより下に描く（feat-034 の「視錐台が下」を維持）
  - 視錐台同士は人物番号の小さい順に重ねて描く（全員同じ色のため、重なり順は見た目に影響しない）
- **受け入れ基準**: 2人の入力で `--fps-person all` を指定すると、両人物の頭部から視錐台が描かれる。P2 だけが欠席するフレームでは P1 の視錐台だけが描かれる
- **優先度**: Must

### FR-003: 全員指定時の頭部マーカー構成チェック

- **概要**: 全員指定のとき、頭部7点のマーカー構成チェック（feat-034 FR-007 の 6）を全人物のファイルに対して行う
- **入力**: 各人物のマーカー名リスト
- **出力**: 不足時のエラーメッセージと終了コード 1
- **詳細**:
  - 頭部マーカーが1個でも欠けている人物が1人以上いれば、PLY / torch のロード前に終了コード 1 で終了する
  - 複数人モードのエラーメッセージは、欠けている人物ごとに1行ずつ、人物番号・ファイルパス・欠けているマーカー名を表示する（feat-037 の番号指定時のメッセージ形式と同じ）
  - 1人モードのエラーメッセージは既存形式（人物番号・ファイルパスを含まず、欠けているマーカー名だけを表示する）のまま変えない（FR-004 により `--fps-person 1` と同一）
  - 番号指定のときは従来どおり、指定した人物のファイルだけを検査する
  - 検査の順序: 複数人モードでは、全ファイルの読み込みと既存の入力検査（ファイルの読み込み失敗、ファイル内のフレーム番号重複、既知マーカーが1個も無いファイル。いずれも feat-037 の既存処理で、最初に見つかった1件で終了コード 1）がすべて通った後に、本要求の頭部マーカー構成チェックを行う。既存の入力検査で終了した場合、頭部マーカーの不足は表示しない（集約の対象は頭部マーカーの不足だけ）
- **受け入れ基準**: 2人の入力で P2 にだけ `Head` が無いとき、`--fps-person all` は終了コード 1 で、エラー出力に `P2` を含む。同じ入力で `--fps-person 1` は終了コード 0
- **優先度**: Must

### FR-004: 1人モードでの全員指定

- **概要**: 1人モードで全員指定したときは、`--fps-person 1` を指定したのと同じ動作にする
- **入力**: キーポイントファイル1個、`--fps-person all`
- **出力**: `--fps-person 1` 指定時と同一の出力
- **詳細**: 出力画像（連番PNG・MP4）・標準出力・終了コードが `--fps-person 1` 指定時と同一になる
- **受け入れ基準**: 同一入力で `--fps-person all` と `--fps-person 1` の出力PNGが一致し、標準出力も一致する
- **優先度**: Must

### FR-005: 設定YAMLでの全員指定

- **概要**: 設定YAML（`--config`、feat-033）の `fps_person` キーに `all` を書ける
- **入力**: 設定YAMLの `fps_person: all`
- **出力**: CLI の `--fps-person all` と同じ効果
- **詳細**:
  - 値の解釈規則は FR-001 と同じ（`all` は小文字の完全一致。それ以外は整数として解釈）。設定YAMLの簡易パーサーが行う値の前後の空白除去は従来どおり行われる
  - 解釈できない値は `設定YAML キー 'fps_person': <メッセージ>` の形式で終了コード 2（feat-033 の既存処理）
  - 優先順位（CLI > 設定YAML > 既定値）は feat-033 と同一
- **受け入れ基準**: `fps_person: all` で全員指定になる。`fps_person: 2` は従来どおり整数 2 になる。`fps_person: x` は終了コード 2
- **優先度**: Must

### FR-006: 実行時の表示

- **概要**: 視錐台の描画結果を、視錐台対象人物が2人以上のときは人物ごとに標準出力に表示する
- **詳細**:
  - 開始時の表示（`FPS視錐台: カメラ ..., 奥行き ... m`）は従来どおり1行表示する。視錐台対象人物が2人以上のときは、その直後に対象人物の一覧（例: `FPS視錐台: 対象人物 P1, P2`）を1行表示する
  - 終了時のサマリは、視錐台対象人物が1人のときは従来どおりの1行（`FPS視錐台: {描画数}/{対象フレーム数} フレームに描画` と非描画の内訳）。2人以上のときは人物ごとに1行ずつ、行頭を `FPS視錐台 P{番号}:` にして同じ内容を表示する
- **受け入れ基準**: 2人の入力で `--fps-person all` のとき、終了時に `FPS視錐台 P1:` と `FPS視錐台 P2:` の2行が表示される。番号指定のときの表示は変わらない
- **優先度**: Should

### FR-007: 番号指定の後方互換

- **概要**: 番号指定（`--fps-person` の整数指定・省略）と `--fps-frustum` なしのときの動作は、feat-037（bug-005 修正後）時点と同一とする
- **詳細**:
  - 出力画像（連番PNG・MP4）、標準出力、終了コード、既存オプションの挙動を変えない
  - **対象外（変わることを許容する）**: `--help` 表示の `--fps-person` の説明文、`--fps-person` に整数以外を渡したときのエラーメッセージの文言（argparse の `invalid int value` から本案件の文言に変わる。終了コード 2 は同じ）、`args.fps_person` の型（`int` に加えて文字列 `"all"` を取り得る）
- **受け入れ基準**: 既存テストが全件パスする（既存テストの期待値修正は行わない）。実データで番号指定の出力が変更前とバイト同一
- **優先度**: Must

## 4. 非機能要求

- **パフォーマンス**: 視錐台の事前計算（全フレーム一括）は人物数に比例して増える。フレームあたりの追加処理は視錐台の描画（1人あたり線分8本）のみとし、全員指定で人物数 N のときの視錐台描画時間は1人分の N 倍を目安とする。背景レンダリングは従来どおり1回のみ
- **メモリ**: 視錐台の頂点（フレーム数×5頂点×3成分の float64）を人物数ぶん保持する。上限は設けない
- **対応環境**: phase4 venv（Linux、CUDA GPU 必須。既存と同じ）
- **信頼性**: ある人物の視錐台を計算できないフレームがあっても処理を中断しない（そのフレームでその人物の視錐台を描かないだけ）

## 5. 制約条件

- 新規ライブラリは追加しない
- 変更対象は `phase4/render_keypoints.py` とテストのみ。`render_fps_video.py` / `npz_to_c3d.py` / `render.py` は変更しない
- 色・太さの定数（`FRUSTUM_COLOR` / `FRUSTUM_THICKNESS` / スケルトンの色定数 / `BONE_THICKNESS` / ラベル定数）は変更しない
- 視錐台の計算関数（`collect_head_points` / `compute_fps_poses` / `compute_frustum_vertices`）と描画関数（`draw_frustum`）は変更しない

## 6. 優先順位

- **Must**: FR-001〜FR-005, FR-007
- **Should**: FR-006
- **Won't（本案件ではやらない）**:
  - 人物ごとの視錐台の色分け
  - 視錐台への人物ラベルの追加
  - 人物ごとに異なる FOV・奥行きの指定
  - 一部の人物だけを選ぶ複数指定（例: `--fps-person 1,3`）
  - 頭部マーカーの無い人物を飛ばして描画を続ける動作
  - 静止画モード（`--no-keypoints`）の変更

MVP = Must 全件。

## CLI 仕様（要求レベル）

```bash
# phase4/ ディレクトリ。2人分の視錐台を同時に描く
TORCH_CUDA_ARCH_LIST="9.0+PTX" uv run python render_keypoints.py \
    data/Blender/point_cloud.ply data/Blender/Config_scene.toml \
    data/patient.c3d data/staff.c3d \
    --camera cam41520554 --fps-frustum --fps-camera FPSCamera --fps-toml data/Calib_FPSCamera.toml \
    --fps-person all --near-plane 0.5 --output-dir data/feat038_check --mp4

# 設定YAML
#   keypoints_path: data/patient.c3d; data/staff.c3d
#   fps_frustum: true
#   fps_camera: FPSCamera
#   fps_toml: data/Calib_FPSCamera.toml
#   fps_person: all
TORCH_CUDA_ARCH_LIST="9.0+PTX" uv run python render_keypoints.py --config run_keypoints.yaml
```
