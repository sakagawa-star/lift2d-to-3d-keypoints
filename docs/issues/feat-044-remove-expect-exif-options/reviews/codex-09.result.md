## 指摘

### 指摘1（高）前処理が写真情報ファイルを上書きできる

共用 YAML で photo_info と init_toml に同じ新規パスを指定し overwrite: true にすると、書き出しは成功し、前処理は写真情報を読んだ後そのパスを初期 TOML で置換する。photo_info が前処理の固定一時パス {出力パス}.tmp と一致する場合は overwrite: false でも写真情報が失われる。FR-002 と設計 §4.2.2 に、実パスや同一ファイルへの別名も含め、写真情報と前処理の最終・一時出力の衝突を処理前に終了コード 1 で拒否する規則を追加し、両ケースで元ファイルが保持されることをテストする。

### 指摘2（高）案件 README が、実行すると必ず失敗するオプションを合意済みとして案内する

README の「合意した方式」に書き出しの --overwrite が残っている。FR-001 と設計 §4.4 ではこの指定は終了コード 2。設計 §8 が案件 README の更新対象に挙げているのはステータスだけ。§8 に概要と CLI の更新を追加し、書き出しは既存パスを拒否し overwrite は前処理専用であることを明記する。

### 指摘3（中）空の出力パスを拒否する既存テストが、別のエラーで合格する

既存テスト 17 の YAML には必須の photo_info が無いため、必須項目の検査が先に終了コード 2 を返し、空の出力パスを拒否する処理が壊れてもテストは通る。テスト 17 に有効な photo_info を追加し、標準エラーに空値エラーと対象オプション名が出ることを確認する。
