## 指摘

### 指摘1（高）完了後も、現行仕様への案内から両ツールが拒否する YAML にたどり着く

feat-042 の要求仕様は、削除対象の 2 キーを推定が無視すると説明し、「現在の仕様」として feat-043 を案内している。その feat-043 の README と要求仕様 §7 には、2 キーを含む共用 YAML の実行例がある。設計 §8 どおりに更新しても、この案内と例が残り、例に従うと両ツールが終了コード 2 になる。§8 に、feat-042 の現行仕様への案内を更新し、feat-043 の README と §7 の例の直前に「現行版では 2 キーを削除する」と明記して更新済みの例へ誘導する作業を加える。

### 指摘2（中）実データ検証が、feat-043 の検証記録と異なるファイルを必須にしている

設計 §6.4 は job_s25.yaml と job_s25_* を feat-043 の手動テストの成果物として指定しているが、検証記録にあるのは job_feat043.yaml と feat043_*。検証記録どおりの成果物だけがある環境では、設計の手順は冒頭で中断する。§6.4 の入力、比較先、旧キー拒否に使う YAML を記録済みの組に統一する。複製する際は tmp_dir も検証用ディレクトリ配下に変更するか、複製から削除する。
