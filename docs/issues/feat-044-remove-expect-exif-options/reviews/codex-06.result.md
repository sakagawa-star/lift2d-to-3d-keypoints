## 判定

1. 未解消 — 書き出しの書き込みの安全性。上書きなしの経路は `open(out, "x")` で直接書くため、書き込みが途中で失敗すると空または不完全なファイルが残り、再実行すると既存ファイルとして拒否される。両経路で同じディレクトリの一時ファイルに書き切り、上書きなしの場合は os.link などで出力先が存在しない場合だけ公開する
2. 未解消 — 前処理からの Exif 焦点距離タグの分離。int() 変換は書き出し側へ移り Exif のない JPEG の CLI 受入手順も追加されたが、変更後の read_exif でも dict(exif) がタグ 0xA405 を取得する。FR-002 は「取得も行わない」と明記している。前処理の Exif 読み込みを必要な項目に絞るか、Pillow 内部での一括デコードを許容するなら、前処理が焦点距離タグを参照・変換せず異常値でも完走することを要件と受入試験に明記する
3. 解消 — 写真情報ファイルの配置（FR-004、設計 §8）
4. 新規（高）— 書き出しが読み込んだ共用設定 YAML を置換できる。photo_info: job.yaml と overwrite: true で --config job.yaml を実行すると、衝突検査は原本画像との比較だけなので job.yaml が置き換わる

## 対応

  - FR-001・設計 §4.1: `--overwrite` を削除。出力先が既に存在すれば終了コード 1（原本・設定YAMLは必ず存在するので書き換わらない。個別の衝突検査は不要になり削除）。書き込みは同じディレクトリの `mkstemp` に書き切ってから `os.link` で公開し、`finally` で一時ファイルを削除（§4.1.4）。`overwrite` は前処理だけのキーになり、書き出しの `IGNORED_KEYS` に追加
  - §6.2: No.3・13 を変更、No.14 に一時ファイルの残留確認を追加、No.15（公開失敗）・No.16（`--overwrite` は終了コード 2）を追加
- 2: FR-002 を「参照も変換もしない（Pillow が Exif をまとめて解釈する際に内部で読むことは許容）。異常値でも前処理は止まらない」に修正。§6.2 No.17（偽の PIL で inf を入れ、`read_exif` が例外を出さず戻り値に含めないこと）を追加
