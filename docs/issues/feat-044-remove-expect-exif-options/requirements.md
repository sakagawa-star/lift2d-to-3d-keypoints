# 要求仕様書: feat-044 前処理の Exif 依存の整理（写真情報ファイルの分離と expect 系オプションの削除）

## 1. プロジェクト概要

- **何を作るのか**:
  1. 原本画像の Exif から 35mm 換算焦点距離を読んで**写真情報ファイル**に書き出す新しいスクリプト `phase4/extract_photo_info.py`
  2. 前処理 `phase4/prepare_phone_photo.py` が、35mm 換算焦点距離を Exif ではなく写真情報ファイルから読むようにする変更
  3. 前処理の任意オプション `--expect-model` / `--expect-focal-mm`（設定キー `expect_model` / `expect_focal_mm`）と、それによる Exif 検査の削除
- **なぜ作るのか**（ユーザー判断 2026-11-26）:
  - 設定YAMLは人が手で書く。人が決める必要がある値だけを置き、Exif にある値を人が見て書き写す項目は置かない（書き写しは間違えるため）。`expect_model` / `expect_focal_mm` はこれに当たるので削除する
  - Exif から読むべき値は、設定YAMLではなく別のファイル（写真情報ファイル）に分ける。理由: 現状の前処理は 35mm 換算焦点距離を Exif から直接読むため、Exif の無い画像では使えない（終了コード 1）。写真情報ファイルに分ければ、Exif のある画像ではツールが自動で書き出し、Exif の無い画像では人が仕様書などを見て書けば前処理を使える
- **誰が使うのか**: 本プロジェクトの研究者（スマートフォン静止画のカメラパラメータ推定を行う人）
- **どこで使うのか**: phase4 の uv 環境（feat-041 と同じ）

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| 書き出し | `phase4/extract_photo_info.py`（本案件で新設） |
| 前処理 | `phase4/prepare_phone_photo.py`（feat-041 FR-001） |
| 推定 | `phase4/estimate_intrinsics_loop.py`（feat-041 FR-002〜FR-007） |
| 写真情報ファイル | 原本画像の撮影条件のうち、処理に必要で Exif から得られる値を書いたファイル。本案件では 35mm 換算焦点距離（キー `focal_length_35mm`）の 1 項目だけを持つ。書式は設定YAMLと同じフラットな `key: value`（`#` で始まる行はコメント） |
| 35mm 換算焦点距離 | Exif の `FocalLengthIn35mmFilm`（タグ 0xA405）。前処理の初期焦点距離の計算に使う（feat-041 FR-001 の式は変えない） |
| 共用設定YAML | 書き出し・前処理・推定に `--config` で渡す 1 つの設定YAML（feat-043 の共用を 3 ツールに広げる） |
| 相手のキー | 共用設定YAMLの中の、他のツール専用の設定キー。各ツールは黙って無視する（feat-043 FR-003） |
| 削除対象 | `--expect-model`（設定キー `expect_model`）と `--expect-focal-mm`（設定キー `expect_focal_mm`） |

機能設計書・コード内でも同じ用語を使う。

## 3. 機能要求一覧

### FR-001: 書き出し（写真情報ファイルの作成）

- **機能名**: Exif からの写真情報ファイルの書き出し
- **概要**: 原本画像の Exif から 35mm 換算焦点距離を読み、写真情報ファイルに書き出す
- **入力**: `--image <原本画像>`（必須）、`--photo-info <写真情報ファイルの出力パス。存在しない新しいパス>`（必須）、`--config <設定YAML>`（任意）。上書きのオプションは持たない（ユーザー判断 2026-11-26。codex-06）
- **出力**: 写真情報ファイル。内容はコメント行と `focal_length_35mm: {値}` の 1 行（値は Exif の整数値をそのまま）
- **詳細**:
  - 写真情報ファイルは上書きしない。`--photo-info` のパスが既に存在すれば（リンク先の無いシンボリックリンクも含む）終了コード 1。そのため、原本画像や設定YAMLなど既存のファイルを出力先に指定しても、それらは書き換わらない。再実行するときは、既にある写真情報ファイルをそのまま使う（書き出しを飛ばす）か、利用者が手で削除する（この案内は README に書く。エラーメッセージは「別の出力パスを指定してください」とし、削除を案内しない。原本画像や設定YAMLを誤って指定した場合に入力を消させないため。codex-07）
  - 次の場合も写真情報ファイルを書かずに終了コード 1: 原本画像を開けない、Exif に 35mm 換算焦点距離が無いか 0 以下（または数値に変換できない）。35mm 換算焦点距離が無い場合のメッセージには、写真情報ファイルを手で書く方法（書式）を含める
  - 写真情報ファイルは、全体を書き終えてから出力先のパスに現れるようにする（途中で失敗しても、不完全な写真情報ファイルを残さない。書き込みを確定する時点でも既存のファイルを上書きしない）
  - `--photo-info` が空の値なら終了コード 2
  - 原本画像・設定YAMLは変更しない。途中で書く一時ファイルが既存のファイル（原本やシンボリックリンクの先）を上書きしない（feat-041 NFR-004 と同じデータ保全。codex-05、codex-06）
  - 設定YAMLの扱い（優先順位、省略形の禁止、未知のキー、相手のキーの無視）は前処理・推定と同じ（feat-042 / feat-043）
- **受け入れ基準**: 10F の原本画像（Galaxy S25）から `focal_length_35mm: 23` が書き出される。Exif の無い画像では終了コード 1 で、ファイルは作られない
- **優先度**: Must

### FR-002: 前処理が写真情報ファイルから 35mm 換算焦点距離を読む

- **機能名**: 前処理の焦点距離の入力元の変更
- **概要**: 前処理に必須オプション `--photo-info <写真情報ファイル>`（設定キー `photo_info`）を追加し、初期焦点距離の計算に使う 35mm 換算焦点距離を、Exif ではなく写真情報ファイルから読む
- **入力**: 写真情報ファイル（書き出しが作ったもの、または人が書いたもの）
- **出力**: 初期 TOML・前処理後画像・2D 点 CSV（内容の作り方は変えない）
- **詳細**:
  - 写真情報ファイルと前処理の出力の衝突の拒否（何も書かずに終了コード 1）: 写真情報ファイルが、前処理の出力 3 つ（前処理後画像、初期 TOML、2D 点 CSV）またはそれらの書き込み途中の一時ファイルと同じファイルを指す場合（シンボリックリンク・ハードリンクによる別名を含む。`--overwrite` の有無に関係なく。写真情報ファイルを壊さないため。codex-09）
  - 写真情報ファイルの検査（どれかに当たれば、何も書かずに終了コード 1）: ファイルが無い・読めない・UTF-8 でない、`focal_length_35mm` 以外のキーがある、`focal_length_35mm` が無い、値が数値でない・有限でない・0 以下
  - 35mm 換算焦点距離は小数も受け付ける（人が仕様書の値を書く場合のため）
  - 前処理は Exif の 35mm 換算焦点距離のタグを参照も変換もしない（Pillow が Exif をまとめて解釈する際に内部で読むことは許容する）。タグに異常な値（例: inf）があっても前処理は止まらない（codex-05、codex-06）。Exif の無い画像でも、写真情報ファイルがあれば前処理を行える
  - 残る Exif 検査は、Exif に値がある場合だけ行う（値が無ければ検査しない。現状と同じ扱い）: `Orientation` が 1 以外、`DigitalZoomRatio` が 1.0 以外。縦長・正方形（幅 ≤ 高さ）の検査は画像サイズで行うので、Exif の有無に関係なく行う
- **受け入れ基準**: 書き出しが作った写真情報ファイルで前処理すると、従来（Exif から直接読んだ場合）と出力 3 つがバイト単位で一致する。Exif の無い原本 JPEG と人が書いた写真情報ファイルで、前処理の CLI が終了コード 0 で完走する
- **優先度**: Must

### FR-003: 削除対象の削除

- **機能名**: `--expect-model` / `--expect-focal-mm` の削除
- **概要**: 前処理の CLI オプション・設定キーの削除対象と、Exif の `Model` の一致検査・`FocalLength` の一致検査（許容差 0.05mm）を削除する
- **詳細**:
  - 削除対象を CLI で指定すると argparse の未知の引数として終了コード 2。設定YAMLに書くと未知のキーとして終了コード 2（書き出し・前処理・推定のどれに渡しても）
  - 旧名・互換用の受け入れは残さない（前処理は 2026-11-25 に作ったもので、利用者は本プロジェクトの研究者だけ）
- **受け入れ基準**: 前処理の `--help` に削除対象が出ない。削除対象を書いた設定YAMLは 3 ツールとも終了コード 2
- **優先度**: Must

### FR-004: 共用設定YAMLの 3 ツールへの拡張

- **機能名**: 名前の統一と相手のキーの無視
- **概要**: 書き出し・前処理・推定の 3 つに 1 つの共用設定YAMLを渡せるようにする。同じ値には 3 ツールで同じ名前を付ける（feat-043 FR-001 の規則）
- **詳細**: 名前の表（CLI と設定キーの違いは `--` の有無と `-` / `_` だけ）

| 中身 | CLI | 設定キー | 書き出し | 前処理 | 推定 |
|---|---|---|---|---|---|
| 原本画像 | `--image` | `image` | 必須（読む） | 必須（読む） | 相手のキー |
| 写真情報ファイル | `--photo-info` | `photo_info` | 必須（書く） | 必須（読む） | 相手のキー |
| 上書き許可 | `--overwrite` | `overwrite` | 相手のキー | 任意（前処理の出力 3 つ） | 相手のキー |
| カメラ名 | `--camera` | `camera` | 相手のキー | 必須 | 必須 |
| 原本座標の 2D 点 CSV | `--points-2d-original` | `points_2d_original` | 相手のキー | 必須 | 相手のキー |
| 前処理後画像のディレクトリ | `--images-dir` | `images_dir` | 相手のキー | 必須（書く） | 必須（読む） |
| 初期 TOML | `--init-toml` | `init_toml` | 相手のキー | 必須（書く） | 必須（読む） |
| 前処理後の 2D 点 CSV | `--points-2d` | `points_2d` | 相手のキー | 必須（書く） | 必須（読む） |
| 3D 基準点 CSV | `--points-3d` | `points_3d` | 相手のキー | 相手のキー | 必須 |
| 3DGS PLY | `--ply` | `ply` | 相手のキー | 相手のキー | 必須 |
| 推定の出力先 | `--out-dir` | `out_dir` | 相手のキー | 相手のキー | 必須 |
| 推定の中間ファイル置き場 | `--tmp-dir` | `tmp_dir` | 相手のキー | 相手のキー | 任意 |

  - 書き出しは上書きを持たないので、`overwrite` は前処理だけのキー（書き出し・推定は無視する）
  - 3 ツールのどれにも無いキーは未知のキーとして終了コード 2
  - 写真情報ファイル（`photo_info`）は、前処理の出力（`images_dir`、`init_toml`、`points_2d`）と同じく、推定の `out_dir`・`tmp_dir` の配下に置いてはならない（書き出しや前処理がそのディレクトリを先に作り、推定が「既に存在する」として終了コード 1 になるため。feat-043 FR-001 の配置制約と同じ。人が手で書く場合も同じ。codex-05）
  - 写真情報ファイルを人が書いた場合（Exif の無い画像）は、書き出しを実行しない（前処理と推定だけを実行する）。共用設定YAMLは同じものを使える
- **受け入れ基準**: 表の全キーを書いた 1 つの共用設定YAMLを、書き出し・前処理・推定の 3 つに `--config` で渡せる
- **優先度**: Must

## 4. 非機能要求

- **後方互換**（意図した変更。ユーザー判断 2026-11-26）:
  - 前処理に必須の `--photo-info` が増える。従来の前処理のコマンド・設定YAMLは、写真情報ファイルを用意して `--photo-info` を足す必要がある
  - 削除対象を書いた設定YAML・コマンドは終了コード 2
  - それ以外の挙動（出力の内容、終了コード、推定の処理）は変えない
- **パフォーマンス**: 変化なし（書き出しは数秒以内）
- **対応環境**: phase4 の uv 環境。ユニットテストはルートの uv 環境の `uv run pytest` で実行できること（既存方式。Pillow はルート環境に無いため、Exif の読み込みは差し替えて試験する）
- **セキュリティ**: 該当なし

## 5. 制約条件

- 新規ライブラリなし（Exif の読み込みは既存の Pillow）
- 初期焦点距離の式・切り抜き・2D 点の変換（feat-041 FR-001）は変えない
- 写真情報ファイルの項目は 35mm 換算焦点距離の 1 つだけ（ユーザー判断 2026-11-26。向き・デジタルズームは入れない）

## 7. 使い方（要求レベル）

```bash
# 1. 書き出し（Exif のある画像。Exif の無い画像では写真情報ファイルを手で書き、この手順は飛ばす。写真情報ファイルが既にある場合も飛ばす）
uv run --project phase4 python phase4/extract_photo_info.py --image <原本画像> --photo-info <写真情報ファイル（存在しない新しいパス）>
# 2. 前処理
uv run --project phase4 python phase4/prepare_phone_photo.py \
  --image <原本画像> --photo-info <写真情報ファイル> --camera <カメラ名> \
  --images-dir <前処理後画像の出力ディレクトリ> --init-toml <初期TOML> \
  --points-2d-original <原本座標の2D点CSV> --points-2d <前処理後座標の2D点CSV> [--overwrite]
# 3. 推定（変更なし）
# 共用設定YAMLを使う場合は、3 つとも --config <共用設定YAML> だけでよい
```

写真情報ファイルの例（書き出しが作るもの。手で書く場合も同じ書式）:

```yaml
# 写真情報ファイル（extract_photo_info.py が Exif から書き出し。feat-044）
focal_length_35mm: 23
```

共用設定YAMLの例:

```yaml
camera: s25_20261124_152436
image: phase4/data/10F/s25_original/20261124_152436.jpg
photo_info: phase4/data/10F/job_s25_photo_info.yaml
points_2d_original: phase0/data/points_2d_10F.csv
images_dir: phase4/data/10F/job_s25_images
init_toml: phase4/data/10F/job_s25_init.toml
points_2d: phase4/data/10F/job_s25_points_2d.csv
points_3d: phase0/data/kijunten_locations_10F.csv
ply: phase4/data/10F/point_cloud.ply
out_dir: phase4/data/10F/job_s25_out
```
