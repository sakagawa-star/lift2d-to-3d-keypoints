# feat-023 要求仕様書: estimate_camera_params.py 接線歪みゼロ固定オプション（--zero-tangent）

## 1.1 プロジェクト概要

- **何を作るのか**: `phase0/estimate_camera_params.py` に、接線歪み係数 p1, p2 を 0 に固定し放射歪み係数（k1, k2、`--k3` 併用時は k3 も）のみを推定する CLI オプション `--zero-tangent` を追加する。
- **なぜ作るのか**: 全係数同時最適化では、画像端に基準点が偏在するデータで接線歪み係数が「モデル誤差の吸収弁」となり物理的にありえない値（例: E0085-01 で p2 = 0.052。通常のレンズは |p1|, |p2| < 0.001 のオーダー）に収束する。この歪み係数はピンホール投影（歪み未対応のレンダラ）と整合しないカメラパラメータを生む。接線歪みを 0 に固定することで異常値の発生源を断つ。
- **誰が使うのか**: 本プロジェクトでカメラキャリブレーションを行う開発者・研究者。
- **どこで使うのか**: Linux 上の CLI（`phase0/` ディレクトリで `uv run python estimate_camera_params.py ...` として実行）。

## 1.2 用語定義

本ドキュメントの用語は機能設計書・コード内でも同じ意味で使う。

| 用語 | 定義 |
|---|---|
| 放射歪み | レンズ中心からの距離に応じた歪み。係数 k1, k2, k3（OpenCV の distCoeffs の第1, 2, 5要素） |
| 接線歪み | レンズとセンサの組付けずれに起因する歪み。係数 p1, p2（OpenCV の distCoeffs の第3, 4要素） |
| 接線歪みゼロ固定 | p1 = p2 = 0 を最適化変数から除外し定数 0 として扱うこと。OpenCV の `CALIB_ZERO_TANGENT_DIST` フラグ相当 |
| 通常モード | `--intrinsic-toml` を指定しない K 未知の推定モード |
| K既知モード | `--intrinsic-toml` を指定し R, t のみ推定するモード |
| 主点固定 | `--fix-center` により cx, cy を画像中心に固定すること |

## 1.3 機能要求一覧

### FR-001: --zero-tangent オプションの追加

- **機能名**: 接線歪みゼロ固定オプション
- **概要**: CLI に `--zero-tangent` フラグを追加する。指定時、通常モードの歪み係数推定において p1, p2 を最適化変数から除外し、定数 0 として扱う。
- **入力**: コマンドライン引数 `--zero-tangent`（フラグ、引数なし）
- **出力**: p1 = p2 = 0 で推定されたカメラパラメータ（表示・TOML・CSV 出力の形式は FR-004 で定義）
- **受け入れ基準**: `--zero-tangent` 指定時の推定結果で、出力される p1, p2 が厳密に 0.0 であること。

### FR-002: 既存オプションとの組み合わせ

- **機能名**: モード組み合わせ
- **概要**: `--zero-tangent` は以下の組み合わせをサポートする。

| 組み合わせ | 推定される歪み係数 | 最適化変数の数 |
|---|---|---|
| `--zero-tangent` | k1, k2 | 12（fx, fy, cx, cy, k1, k2, rvec×3, tvec×3） |
| `--zero-tangent --fix-center` | k1, k2 | 10（fx, fy, k1, k2, rvec×3, tvec×3） |
| `--zero-tangent --k3` | k1, k2, k3 | 13 |
| `--zero-tangent --k3 --fix-center` | k1, k2, k3 | 11 |

- **入力**: 上記フラグの組み合わせ
- **出力**: 各組み合わせに応じた推定結果
- **受け入れ基準**: 上表の4組み合わせすべてで推定が完走し、p1 = p2 = 0.0 が出力されること。

### FR-003: 非サポートの組み合わせの拒否

- **機能名**: 組み合わせバリデーション
- **概要**: 以下の組み合わせはサポート外とし、明示的に扱いを定める。
  - `--zero-tangent --wide`: エラーとし、メッセージ「エラー: --zero-tangent と --wide は併用できません」を表示して終了コード 1 で終了する（重い処理の前に判定する）。
  - `--zero-tangent --intrinsic-toml <path>`: K既知モードでは歪み係数は TOML から読むため推定しない。既存の `--fix-center` 等と同様に警告「警告: --intrinsic-toml 指定時は --zero-tangent は無視されます」を表示し、`--zero-tangent` を無視して K既知モードを実行する。
- **入力**: 上記フラグの組み合わせ
- **出力**: エラーメッセージ + 終了コード 1（--wide 併用時）、警告メッセージ + K既知モード続行（--intrinsic-toml 併用時）
- **受け入れ基準**: 各組み合わせで上記のメッセージと動作が確認できること。

### FR-004: 出力形式の互換性維持

- **機能名**: 出力フォーマット互換
- **概要**: `--zero-tangent` 指定時も、標準出力の歪み係数表示・Calib_scene.toml 形式・camera_params.csv 形式は既存の 4 係数（`--k3` 時は 5 係数）レイアウトを維持し、p1, p2 の位置に 0.0 を出力する。distortions 配列の要素数・列構成を変えない。
- **入力**: `--zero-tangent` 指定での推定完了
- **出力**: `distortions = [k1, k2, 0.0, 0.0]`（`--k3` 時は `[k1, k2, 0.0, 0.0, k3]`）、CSV も同じ列構成で p1, p2 列に 0.0
- **注記**: 基準点数不足で歪み係数推定がスキップされた場合（FR-005）は、`--k3` 指定でも既存挙動どおり4係数レイアウトで出力する（現行コードの `estimate_distortion=False` 時の挙動を維持し、`--zero-tangent` はこの挙動を変更しない）。
- **受け入れ基準**: 出力 TOML を既存の下流ツール（`convert_toml_to_csv.py`、K既知モードの `--intrinsic-toml` 入力）がそのまま読めること（配列長 4 または 5 を維持）。

### FR-005: 最小基準点数の判定

- **機能名**: 最小点数チェック
- **概要**: 歪み係数を推定するか 0 固定にするかの判定点数を、`--zero-tangent` の変数削減に合わせて定める。

| 組み合わせ | 変数の数 | 最小点数 |
|---|---|---|
| `--zero-tangent` | 12 | 13 |
| `--zero-tangent --fix-center` | 10 | 10 |
| `--zero-tangent --k3` | 13 | 14 |
| `--zero-tangent --k3 --fix-center` | 11 | 11 |

  点数が最小点数未満の場合は既存動作と同様、歪み係数をすべて 0 に固定して推定する（この場合 `--zero-tangent` の有無で結果は変わらない）。
- **入力**: マッチング済み基準点数
- **出力**: 判定結果のログ（既存フォーマット「→ N点 >= M点: 歪み係数を推定します」）
- **受け入れ基準**: 各組み合わせで境界点数（最小点数ちょうど / 1点少ない）の分岐が上表どおりであること。

### FR-006: モード表示

- **機能名**: 実行時のモード表示
- **概要**: 実行ヘッダーの「歪みモデル:」表示とモード決定ログに、接線歪みゼロ固定であることを明示する（例: 「歪みモデル: 2係数（放射のみ）」「モード: 主点固定 + 接線歪みゼロ + k3なし（10変数）」）。
- **入力**: `--zero-tangent` フラグ
- **出力**: 標準出力のヘッダー・ログ
- **受け入れ基準**: `--zero-tangent` 指定時の標準出力から、接線歪みが 0 固定であることが読み取れること。

## 1.4 非機能要求

- **パフォーマンス**: 既存の推定と同等（変数が減るため最適化は同等以下の時間）。16 点程度の入力で 10 秒以内に完了すること。
- **対応環境**: Linux、Python 3.10、phase0 の uv 環境。GPU 不要。
- **信頼性**: 入力ファイルは読み取りのみで変更しない。`--zero-tangent` を指定しない場合の動作・出力は変更前と完全に同一であること（バイト単位で同一の標準出力）。
- **セキュリティ**: 該当なし。

## 1.5 制約条件

- 使用ライブラリは既存のもの（NumPy, SciPy `least_squares(method='lm')`, OpenCV `projectPoints` / `solvePnP`）に限定し、新規ライブラリを追加しない。
- 最適化手法は既存と同じ `scipy.optimize.least_squares(method='lm')` を使う（bounds 系の手法変更は行わない）。
- 変更対象ファイルは `phase0/estimate_camera_params.py` と `tests/`、ドキュメント（CLAUDE.md, BACKLOG.md, CHANGELOG.md）に限定する。`phase0/common.py` は変更しない。
