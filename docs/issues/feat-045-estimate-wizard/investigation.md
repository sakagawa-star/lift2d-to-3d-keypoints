# feat-045 調査・修正計画

## イテレーション1（2026-11-26 手動テスト）

### 1.1 不具合の特定

- **対応する要求ID**: FR-001（原本とジョブフォルダの指定）。要求仕様作成時のヒアリング漏れ（作業フォルダの説明と置き場所の規則が要求に無かった）
- **対応する設計セクション**: design.md §4.3 手順 2・3、§4.4
- **現在の動作**: ウィザードは作業フォルダを `ジョブフォルダのパス（存在しない新しいパス）:` の 1 行だけで聞く。何のためのフォルダか、何が入るか、相対パスの基準がどこかを表示しない。ユーザーが名前だけ（`20261126-01`）を入力すると、実行したカレントディレクトリ（リポジトリのルート）の直下にフォルダが作られた
- **期待する動作**（ユーザー指摘 2026-11-26）:
  - 「`ジョブフォルダのパス（存在しない新しいパス）:` これで何が分かるというのだ？」— 質問だけで、何を聞かれていて何が作られるのかが分かること
  - 「リポジトリ直下は、現状のルールだと git の管理下」— CLAUDE.md「テストデータ」の規則（データファイルは各 phase の `data/` に置く。git 管理外）に反する場所に作らないこと
- **エラーメッセージ**: なし（エラーにならずに、規則に反する場所へ作られる）

### 1.2 原因分析

- **原因箇所**: `phase4/estimate_wizard.py` `_wizard` 手順 2（`ask(input_fn, "ジョブフォルダのパス（存在しない新しいパス）")`）と、その後の検査（存在・改行・前後の空白だけ）
- **原因の説明**: 要求仕様書・機能設計書が、作業フォルダの説明文と置き場所の制限を定めていなかった。「ジョブフォルダ」は設計書の中だけで定義した言葉で、画面には説明が出ない
- **根本原因 or 表面的原因**: 根本原因（要求・設計の抜け）。実装は設計どおり

### 1.3 修正内容

**方針（ユーザー指摘 2026-11-26）**: 「まずパスの形式を受け付けているのが間違い」。作業フォルダはパスで受け付けず、**名前だけ**を聞き、場所はウィザードが決める（`phase4/data/EIL/{名前}/`。`phase4/data/` は git 管理外〔`.gitignore` 39 行目〕で、CLAUDE.md「テストデータ」の規則に合う）。これにより、相対パスの基準や置き場所の制限は問題にならなくなる。

**画面上の呼び方**: 「ジョブフォルダ」は画面に出さず「作業フォルダ」と呼ぶ（設計書内の用語「ジョブフォルダ」と同じもの。requirements.md の用語定義に併記する）。

   - 用語定義「ジョブフォルダ」に「場所は `phase4/data/EIL/{作業フォルダ名}/`（ウィザードが決める）。画面上は『作業フォルダ』と表示する」を足す
   - FR-001 の「ジョブフォルダのパス」を「作業フォルダの名前」に変える。詳細:
     - 名前を聞く前に、何のためのフォルダかを表示する（ウィザードが `phase4/data/EIL/` の下に新しく作ること、入力のコピー〔PLY を含む〕・確認用の画像・設定ファイル・3 ツールの出力をすべて保存すること）
     - 名前は英数字・`_`・`-` だけからなる 1 文字以上（正規表現 `^[A-Za-z0-9_-]+$`。例 `20261126-01`）。違反、または `phase4/data/EIL/{名前}` が既に存在する場合は理由を表示して聞き直す。`phase4/data/EIL/` が無ければ作る
