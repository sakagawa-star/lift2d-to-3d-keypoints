## 概要

`phase4/estimate_intrinsics_loop.py`（feat-041）でスマートフォン静止画のカメラパラメータを推定するまでの手間（設定YAMLを書く、ファイル名・ディレクトリ名を決める、入力を置き場所にコピーする）を減らす、対話式の CLI ウィザード `phase4/estimate_wizard.py` を作る。既存の 3 ツール（`extract_photo_info.py`・`prepare_phone_photo.py`・`estimate_intrinsics_loop.py`）は変更せず、ウィザードはそれらを順に実行する。

## ヒアリング結果（2026-11-26 ユーザー）

- 目的: 「`estimate_intrinsics_loop.py` の config ファイルを書いたり、ファイル名やディレクトリ名を決めたりするのが煩雑なので、今の仕組みのまま、追加でウィザードを作る」。YAML を作るだけでなく、2D・3D の基準点や PLY を良い感じの場所にコピーして、推定まで行う
- 形: CLI（GUI は作業量が多すぎる）
- 実行環境: Windows 11 の WSL2 上の Ubuntu 24。推定は RTX 5070 Ti / 5060 Ti のどちらかのある PC で動かす
- 2D 点は今は GIMP で原本に打っている（ウィザードの外の作業のまま）
- 2D 点を打てる範囲（前処理で 16:9 に切り抜かれて残る範囲）が分かる機能は必須。範囲は、原本に範囲を描き込んだ画像を書き出して示す（数値表示ではなく画像）
- 2D と 3D の基準点の名前（`基準_001` など）が一致しているかを確認する。2D 点を画像にプロットして人に確認してもらう。プロットは `phase0/visualize_points_2d.py` の描き方を参考にし、範囲入りの画像の上に描く
- 範囲の拡大はしない（2D 点を打つ GUI、別 PC の環境構築手順などはユーザーの要求外として扱わない）
