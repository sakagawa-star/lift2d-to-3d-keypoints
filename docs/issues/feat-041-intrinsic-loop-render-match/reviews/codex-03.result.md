## 指摘

### 1. 重要度：高 — 評価出力の命名が矛盾し、上書き防止の対象から実出力が漏れる

design.md §1.3 は `{camera}_eval.txt` と `{camera}_eval_blend.png` 等を定義しているが、§4.3.4 の接尾辞規約では、単一の prefix からこの組を生成できない。prefix=`{camera}_eval` なら統計ファイルは `{camera}_eval_eval.txt`、prefix=`{camera}` なら画像は `{camera}_blend.png` になる。§4.2.1 は §1.3 の 8 ファイルだけを上書き検査するため、どちらでも実出力の一部が検査対象から外れ、NFR-004 のデータ保全を保証できない。§9 の合否確認パスとも不整合になる。

修正案: 呼び出し時の接頭辞と 4 出力の名前を一意に定義し、§1.3、上書き検査、§4.3.4、§9 を統一する。出力パスの生成処理を検査と書き込みで共用する設計にすると確実。

### 2. 重要度：中 — 深度リフトの逆歪み変換が、許容範囲内でも数 px の誤差を生む

design.md §4.2.3 は既定の `cv2.undistortPoints` を使うが、その反復精度では §8 テスト 14 の復元精度を保証できない。ローカルの OpenCV で、許容範囲内の f=1280, cx=960, cy=540, k1=-0.3, k2=0、姿勢ゼロ、3D 点 (1.6, 0.8, 2.0)m を確認した。画像内の投影座標 (1738.24, 929.12) を設計どおりリフトすると、3D 復元誤差は約 2.56cm、再投影誤差は約 4.75px だった。正しい対応にも系統誤差を加え、2 回目以降の RANSAC しきい値 3px や同時推定に影響する。

修正案: 新規ループでは `undistortPointsIter` の反復数・精度条件と再投影による逆変換検査を定義し、この条件をテストに追加する。同条件では 100 反復・精度 1e-10 で復元誤差が 1e-12m 未満になった。最終精緻化の既存コードも同じ逆変換を使うため、変更禁止制約を維持するなら、呼び出し前の精度検査と不適合時の終了条件も必要。
