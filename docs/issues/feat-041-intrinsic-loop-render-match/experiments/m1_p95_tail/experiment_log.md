## m1b 追加測定: 最下段のずれの向き（2026-11-25、測定）

背景: ユーザー情報「3DGS 撮影は高さ約 150cm で水平移動、魚眼 3 方向同時（PortalCam）、下側はあまり撮っていない」。最下段の裾が、3DGS の再現不足（向きばらばら）か、カメラパラメータ・歪みモデルの不足（向きがそろう・放射方向にそろう）かを区別する。

### 指標（実行前に固定）

DIS の順方向フロー F（写真→レンダ。evaluate_overlay.flow_stats と同じ計算を再実行し、mag が一致することを確認）を、8x6 セル（240x180）ごとに、有効画素のうち裾（|F| > 3px）について集計する。

- 一貫性 C = |平均ベクトル| / 平均の大きさ（1 = 全画素同じ向き、0 付近 = ばらばら）
- 放射成分 Rr = 平均(F・r̂) / 平均|F|（r̂ は最終 TOML の主点から画素への単位ベクトル。+1 = すべて外向き、−1 = すべて内向き）
- 参考として、有効画素全体（裾に限らない）の平均ベクトル [px] もセルごとに出す

解釈の枠（実行前に固定）:

- **パラメータ側（系統的）**: 最下段 8 セルのうち 6 セル以上で C ≥ 0.5 かつ Rr の符号がそろう（隣接セルで向きが連続的に変わる）
- **3DGS 側（内容の違い）**: 最下段の C の中央値 < 0.5、または Rr の符号がセル間でそろわない
- どちらにも当てはまらない場合は「判別不能」と記録する

### 予測（実行直前）

ユーザー情報（下側の撮影不足）から、3DGS 側を予測する: 最下段 8 セルの C の中央値は 0.2〜0.5、Rr の符号は 8 セル中 5 セル以下でしかそろわない。

### 実測

スクリプト: scratchpad の `m1b_dir.py`（使い捨て）。再計算した F の大きさは flow_stats の mag と一致（`np.allclose` True、median 0.671）。

最下段（y 900〜1080）の裾:

| x | 0 | 240 | 480 | 720 | 960 | 1200 | 1440 | 1680 |
|---|---|---|---|---|---|---|---|---|
| 裾の画素数 | 33 | 359 | 619 | 846 | 3158 | 2690 | 1602 | 9307 |
| C | 0.57 | 0.47 | 1.00 | 0.96 | 0.86 | 0.75 | 0.74 | 0.93 |
| Rr | +0.04 | +0.36 | +0.79 | −0.94 | −0.84 | −0.65 | +0.68 | −0.69 |
| 有効画素全体の平均ベクトル [px] | (+0.11,+0.09) | (−0.27,+0.31) | (−0.43,+0.18) | (−0.24,−0.72) | (+0.11,−4.10) | (+0.26,−1.66) | (+1.07,−0.17) | (−0.73,−2.82) |

- C の中央値 0.81。C ≥ 0.5 は 8 セル中 7 セル
- Rr の符号は + 4 セル、− 4 セルで、そろわない。隣接セルで急に反転する（x 480 の +0.79 → x 720 の −0.94、x 1440 の +0.68 → x 1680 の −0.69）
- 他の段でも同じ傾向（セル内では C が高いが、Rr の符号はセルごとにばらばら）

### 照合

| 項目 | 予測 | 実測 | 一致 |
|---|---|---|---|
| 最下段の C の中央値 | 0.2〜0.5 | 0.81 | 外れ |
| Rr の符号がそろうセル数 | 5 以下 | 4（+4 / −4） | 一致 |

**事前の枠による判定**: 「3DGS 側」の条件（C の中央値 < 0.5、**または** Rr の符号がそろわない）を満たす（後者）。「パラメータ側」の条件（6 セル以上で C ≥ 0.5 **かつ** Rr の符号がそろう）は満たさない（後者が不成立）。

**予測が外れた点の解釈**: 向きが「画素ごとにばらばら」なのではなく、「セルの中ではそろっているが、セルごとに向きが変わる」。局所的な塊ごとにずれている状態で、画像全体に滑らかに広がる歪みモデルや主点の誤差（放射方向に連続して変わる）とは合わない。床・机の下・椅子などの面が、3DGS の中で局所的に違う位置に再現されていることと合う（ユーザー情報: 下側の撮影不足）。ただし「3DGS のどの部分の幾何が誤っているか」は直接は確かめていない。

### 注記（2026-11-25、codex-17 指摘4）

上の「事前の枠による判定」で使った分類（「パラメータ側」「3DGS 側」）は、条件が排他的でない（例: 正 6・負 2 のとき両方に当てはまる読み方がある）。また、この枠は criteria lock（Codex レビュー）を経ていない。そのため、この分類は判定として扱わず、investigation.md イテレーション2 の根拠には実測値（最下段の C の中央値 0.81、Rr の符号 正 4・負 4、隣接セルでの反転）だけを使う。原因は未特定である。原因側の判定を今後行う場合は、排他的な条件を事前にレビューしてから行う。

### 注記2（2026-11-25、codex-23 指摘4）

主点の一様なずれ（例: 水平方向の平行移動）でも、主点からの放射方向に射影すると左右で符号が変わり得る。したがって、Rr の符号がセルごとにそろわないという観測だけでは、歪み・主点などカメラパラメータの誤差を除外できない。m1b から言えるのは観測事実（最下段の C の中央値 0.81、Rr の符号 正 4・負 4、隣接セルでの反転）までで、原因は未特定である。
