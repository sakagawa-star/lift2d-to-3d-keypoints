## 1. 答える問い

イテレーション2 の実装（CONV_PX = 2.0、未収束時のループ結果 TOML 出力、合否基準を中央値のみに変更）が、10F の実データで、変更後の requirements.md の合格ラインと NFR-001 を満たすか。

**この実行で確認できる範囲**: 同じ 10F の入力での再実行なので、確認できるのは「固定した新仕様を実装が満たすこと」である。具体的には、10F で収束 → 最終精緻化 → 重ね合わせ評価まで進んだときの成果物・評価値・所要時間である。未収束時のループ結果 TOML の出力（終了コード 3 の分岐）はこの実行では確認できないので、design.md §8 テスト 19 で確認する。収束しきい値の境界はテスト 18、合否判定の境界はテスト 13・21 で確認する。収束した反復番号は予測との照合項目で、合否には使わない（codex-36 指摘3）。新しい基準そのものの妥当性（中央値がカメラパラメータの良否を表すこと）は、この実行では検証しない。また、基準は参考実行（`phase4/data/10F/feat041_out_it1_dump/conv2/`）と追加測定（`experiments/m1_p95_tail/`）の結果を見た後に決めたものである（investigation.md イテレーション2 §2.3）。

## 2. 判定閾値と合格ライン（数値）

コマンド（design.md §9 手順 6）の 1 回の実行で、次の**すべて**を満たせば合格とする。1 つでも満たさなければ不合格とする。

**正式な結果とする実行**: CLAUDE.md ステップ6 で実装担当（Sonnet サブエージェント）が design.md §9 手順 6 として行う 1 回の実行。これはステップ6 の実データ検証である。ユーザーはステップ7（手動テスト）でその出力を確認する（確認項目と完了条件は investigation.md イテレーション2 §2.5）。

**事前確認**: 実行前に、出力先 `phase4/data/10F/feat041_out_it2` と中間ディレクトリ `phase4/data/10F/feat041_tmp_it2` がどちらも存在しないこと（シンボリックリンクとしても存在しないこと。design.md §9 手順 6 の `test ! -e` と `test ! -L`）、入力ファイルがすべてその外にあることを確かめる（bug-006 の回避条件）。満たさなければ正式な実行を開始しない。

**記録**: 終了コードは、design.md §9 手順 6 のとおり、コマンドの直後に表示する `EXIT_CODE=` の値で確かめる（`|| exit_code=$?` と `printf` の形）（`/usr/bin/time -v` の Exit status 欄はシグナル終了時に 0 と表示されることがあるので使わない。`Command terminated by signal` の行が出たら不合格）。所要時間は `/usr/bin/time -v` の Elapsed (wall clock) time で確かめる。パイプ・ログファイルへの書き込みは使わず、これらの行はコマンドの出力から実験ログに書き写す。§2 の全 6 項目の実測値・確認結果と総合判定を `experiment_log.md` に記録する。

**数値の確認**: 合否の境界を確かめるため、小数 3 桁に丸めた行ではなく、eval.txt の `valid_ratio_raw` と `median_raw`（丸めない値）を使う。valid_ratio は `n_valid / (1920 × 1080)` と一致することも確かめる。

| # | 項目 | 合格条件 | 確認する出力 |
|---|---|---|---|
| 1 | 終了状態 | 終了コード 0（`EXIT_CODE=0`、`Command terminated by signal` の行が無い）、loop_report の終了状態が「成功」 | コマンドの出力、`feat041_out_it2/s25_20261124_152436_loop_report.txt` |
| 2 | 集計対象画素の割合 | `valid_ratio_raw` ≥ 0.10、かつ `valid_ratio_raw` = `n_valid / 2073600` | `feat041_out_it2/s25_20261124_152436_eval.txt` |
| 3 | 中央値 | `median_raw` ≤ 1.0px | 同上 |
| 4 | 判定の記載 | eval.txt の判定が「合格」で、合格ラインの行が `合格ライン: median <= 1.000 px（valid_ratio >= 0.100）。p95 は記録のみ` | 同上 |
| 5 | NFR-001 | 全体の所要時間 ≤ 60 分（`/usr/bin/time -v` の Elapsed (wall clock) time） | コマンドの出力（`/usr/bin/time -v`） |
| 6 | 成果物の読み取り | `feat041_out_it2/` の `s25_20261124_152436_final.toml` が `render_keypoints.load_cameras_toml` で読め、評価 4 ファイル（`_eval.txt`、`_eval_blend.png`、`_eval_checker.png`、`_eval_flowmag.png`）がすべて存在し、PNG 3 枚が `cv2.imread` で読めて 1920x1080 である（ステップ7 の確認に必要なため。codex-23 指摘2） | 左記のファイル |

- p95、mean、max は記録するが、合否には使わない
- 途中で失敗した場合は、到達しなかった項目を理由付きで「未実行」または「取得不能」と記録し、総合判定は不合格とする
- ステップ7 に進むのは総合判定が合格の場合だけとする。不合格なら、予測との乖離の有無にかかわらずステップ7 に進まない。合格で、予測と実測が乖離した項目があれば、その原因を特定して実験ログに記録してから進む。原因を特定できない場合は、合格でもステップ7 への遷移を保留し、ユーザーに報告する
- 再実行はしない（1 回の結果で判定する）。不合格の場合は、CLAUDE.md の手順 7 に従って investigation.md に次のイテレーションを追記する
