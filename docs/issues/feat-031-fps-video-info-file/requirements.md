# feat-031 要求仕様書: render_fps_video.py レンダリング情報テキストの自動保存

- 作成日: 2026-08-11
- 準拠: `docs/REQUIREMENTS_STANDARD.md`
- 由来: ヒアリング（`hearing-notes.md`、2026-08-11）

## 1.1 プロジェクト概要

- **何を作るのか**: `phase4/render_fps_video.py` の MP4 一括生成モードの完了時に、レンダリング結果の情報を `<MP4名>_info.txt` に自動保存する機能。
- **なぜ作るのか**: フルNPZ（約19.4万フレーム）の本番実行では所要時間・黒フレームの内訳等の情報が端末ログにしか残らず、端末を閉じると失われる。動画ファイルと対になる記録として残したい。
- **誰が使うのか**: てんかん患者観察研究のデータ処理を行う研究者（本プロジェクトのユーザー）。
- **どこで使うのか**: ローカル機 gtune2 および A100 サーバー（render_fps_video.py の実行環境）。

## 1.2 用語定義

| 用語 | 定義 |
|---|---|
| 情報ファイル | 本機能が保存するテキストファイル `<MP4名>_info.txt` |
| NaN黒フレーム | 頭部キーポイントに NaN があり、カメラポーズを計算せず黒画面で出力したフレーム（feat-027 仕様） |
| 縮退黒フレーム | 頭部キーポイントは有限値だが、ベクトル縮退・回転検証失敗によりカメラポーズを計算できず黒画面で出力したフレーム（feat-027 仕様。実行ログの「縮退」と同じ集計） |
| frame_id | NPZ の `frame_ids` 配列の値（動画フレームと1対1対応） |
| 連続区間圧縮 | 昇順の番号列で連続する部分を「始点-終点」にまとめる表記（例: `1200-1239, 35001, 47800-47989`。単独の番号は単独表記） |

機能設計書・コード内でも同じ用語を使う。

## 1.3 機能要求一覧

### FR-001: 情報ファイルの自動保存

- **概要**: MP4 一括生成モードで最終MP4の連結が成功したとき、情報ファイルを自動保存する。オプション指定は不要（常に保存する）。
- **入力**: なし（内部状態から生成）。
- **出力**: `--output`（または既定の出力パス）の拡張子を除いた名前 + `_info.txt`（例: `test_fps.mp4` → `test_fps_info.txt`）。MP4 と同じディレクトリ。既存の同名ファイルは上書きする。
- **制約**:
  - 連結（最終MP4生成）が失敗した場合は情報ファイルを書かない。
  - `--still-range` / `--dump-poses` の排他モードでは書かない。
  - 情報ファイルの書き出しは既存の `durable_replace()`（fsync 込みの耐久リネーム）で行う。
- **受け入れ基準**: MP4 生成成功時に `<MP4名>_info.txt` が生成され、失敗時・排他モードでは生成されない。

### FR-002: 記載項目と形式

- **概要**: 情報ファイルは UTF-8・`キー: 値` 形式（1行1項目）の日本語ラベルつきテキストで、以下の10項目をこの順で記載する。
- **出力**（記載項目の定義。値はこの実行の実測値）:

| # | 行 | 値の定義 |
|---|---|---|
| 1 | `動画ファイル: <名前>` | 最終MP4のファイル名（ディレクトリを除く basename） |
| 2 | `総所要時間: <S.S>秒` | この実行の総所要 wall-clock 秒（実行ログの「完了: 総所要」と同一値、小数1桁） |
| 3 | `描画フレーム平均: <値>` | 実行ログの「描画フレーム平均」と同一の文字列（直列=チャンク所要合算/描画フレーム、並列=実効秒/フレーム。描画0フレーム時は `N/A（描画0フレーム）`） |
| 4 | `総フレーム数: <N>` | 最終MP4の総フレーム数（NPZ のフレーム数 F。黒フレームを含む） |
| 5 | `フレームレート: <値>` | `--fps` の値 |
| 6 | `NaN黒フレーム数: <N>` | NaN黒フレームの件数（実行ログの「NaN欠損」と同一集計） |
| 7 | `NaN黒フレーム番号: <一覧>` | NaN黒フレームの frame_id を連続区間圧縮で列挙。0件なら `なし` |
| 8 | `縮退黒フレーム数: <N>` | 縮退黒フレームの件数（実行ログの「縮退」と同一集計） |
| 9 | `縮退黒フレーム番号: <一覧>` | 縮退黒フレームの frame_id を連続区間圧縮で列挙。0件なら `なし` |
| 10 | `解像度: <W>x<H>` | 出力動画の解像度（TOML 由来の width/height） |

- **受け入れ基準**: NaN・縮退を含む既知の入力に対し、10行すべてが上記の定義・順序・形式で出力される（連続区間圧縮・0件時の `なし` を含む）。

### FR-003: 再開実行時の値の意味

- **概要**: 再開実行（完成済みチャンクをスキップした実行）でも情報ファイルを保存する。「総所要時間」「描画フレーム平均」は**その実行**の実測値であり、スキップしたチャンクの過去の所要は含めない。NaN・縮退の件数・番号は NPZ 全体から算出するため実行のしかたによらず不変。
- **入力/出力**: FR-001/FR-002 と同じ。
- **受け入れ基準**: 全チャンク完成済みの再実行（描画0フレーム）でも情報ファイルが生成され、「描画フレーム平均: N/A（描画0フレーム）」、NaN・縮退項目は通常実行と同一の値になる。

## 1.4 非機能要求

- **パフォーマンス**: 情報ファイルの生成・書き出しがレンダリング完了処理に追加する時間は、フルNPZ規模（黒フレーム数百件）で1秒未満であること（文字列整形とファイル書き出しのみ）。
- **対応環境**: render_fps_video.py の既存要件と同じ（変更なし）。
- **信頼性**: 書き出しは `durable_replace()` を使用する。情報ファイルの書き出し失敗は最終MP4の成否に影響させない（MP4 は既に確定済みのため、エラーメッセージを表示して終了コード1とするが MP4 は残る）。
- **セキュリティ**: 該当なし。

## 1.5 制約条件

- 新規外部依存を追加しない（標準ライブラリと既存関数のみ）。
- MP4 生成の既存経路（チャンク処理・連結・再開・並列分配）に変更を加えない（情報収集のための引数追加・完了時の書き出し追加のみ）。
- 既存の実行ログ出力（stdout/stderr の文言）は変更しない（情報ファイルの保存を示すログ行の追加は可）。
- 既存 pytest が無修正で全件通ること。
