## 1. 背景と課題

### 1.1 現行手法

外部パラメータを推定したい実カメラ（内部パラメータ K・歪み係数 δ はチェスボード較正済み）に対し、以下を行っている:

1. 商用ソフトで 3D Gaussian Splatting（3DGS）再構成したシーン（PLY）を Blender に読み込む
2. 実カメラ画像に写っている特徴（直方体の頂点など）を目視で探す
3. 各基準点の 3D 位置を Blender 上で手動プロット、2D 位置を画像上で手動プロット
4. 1 カメラあたり 15〜20 点以上集め、既存の `estimate_camera_params.py --intrinsic-toml`（K既知モード: solvePnP + RANSAC + LM）で R, t を推定

### 1.2 課題

- **作業量**: 1 カメラあたり 20 点超の手動プロット。特に 3D 側（ガウシアンのもやの中で頂点をクリック）が最も時間がかかる
- **人的ミス**: プロットミスが推定精度を直接劣化させる。精度評価をしたいのに、測定自体が人的ミスで汚染される

### 1.3 環境条件（制約）

- 実カメラは**檻の外・壁際**に固定設置。カメラのすぐ後ろは部屋の壁
- 部屋が狭く、**格子状の檻**があり物体が多い。視点が少しずれるだけで見え方が激変する（総当たり的な視点探索は期待できない）
- 実カメラは**広角寄りのレンズ**（歪みが大きい）
- 3DGS は商用ソフト出力の **PLY のみ**。学習画像・COLMAP 中間データは入手不可
- 推定した R, t の用途は phase4 のレンダリング（3DGS シーン座標系内で整合すればよく、実世界スケールとの整合は不要）

## 2. 提案手法の概要

手動プロットを**初期値取得用の 5〜6 点のみ**に減らし、最終精度は以下の全自動リファインで確保する:

> 初期ポーズで 3DGS をレンダリング（色＋深度）→ 実写と学習ベースマッチャーで自動マッチング → レンダ側対応点を深度マップで 3D 化 → 2D-3D 対応（数百点規模）で PnP → ポーズ更新 → 収束まで反復

- 人の作業は「5〜6 点の手動プロット」のみ（現行比 7〜8 割減）
- 最終精度は自動対応数百点の平均で決まり、手動プロットの質は初期値にしか効かない
- Blender 上での仮想カメラ設定・3D 空間での試行錯誤は一切不要

### 2.1 先行研究（実績）

本構図は **GS-CPR（旧称 GSLoc, ICLR 2025）** のパイプラインと工程単位で一致する（初期ポーズで 3DGS レンダリング → MASt3R マッチング → 深度リフト → PnP）:

- 屋内 (7Scenes): 粗い初期ポーズを中央値 **0.8 cm / 0.25°** まで改善
- 屋外 (Cambridge Landmarks): 初期誤差 119 cm / 2.9° → 28 cm / 0.51°
- 単一 RGB クエリ＋粗い初期ポーズから one-shot リファイン可能と報告

参考文献:
- GS-CPR: Efficient Camera Pose Refinement via 3D Gaussian Splatting — arXiv:2408.11085, ICLR 2025 (https://arxiv.org/abs/2408.11085)
- 公式実装: https://github.com/XRIM-Lab/GS-CPR

### 2.2 採らなかった代替案と理由

| 代替案 | 捨てた理由 |
|---|---|
| COLMAP/SfM による三角測量＋登録 | 三角測量には基線を持つ複数仮想カメラの配置設計が必要。3DGS の深度マップがレンダリング 1 枚で 3D 座標を直接与えるため、多視点からの 3D 復元は冗長。マッチングも COLMAP 内蔵 SIFT ではドメインギャップ・格子繰り返しパターンに弱い見込み。ただし深度マップが信頼できないと判明した場合の**フォールバック**として保持 |
| 3DGS 学習画像・COLMAP モデルへの直接登録 | 商用ソフトのため中間データが入手不可（前提条件） |
| 目分量での仮想カメラ手動配置による初期化 | 3D 空間での試行錯誤を排除したい要求に反する。Blender の仮想カメラは実カメラの内部パラメータとの整合設定も必要で、5〜6 点プロットより手間も質も劣る |
| 候補視点の総当たり探索による全自動初期化 | 狭い部屋＋格子で視点鋭敏性が極めて高く、素朴なサンプリングでは近い視点を引けない見込み。5〜6 点 PnP で足りるため過剰投資 |
| 実写画像の undistort（画像全体の歪み補正） | 広角のため周辺部の引き伸ばし・補間ボケが大きく、計測の元データを加工することになる。§3 の通り「レンダ側に歪みを付与する」方式で回避 |

## 3. パイプライン定義（式・全変数）

### 3.0 共通記号

**座標系**

| 記号 | 意味 |
|---|---|
| W（ワールド系） | 3DGS シーン座標系。PLY のガウシアン位置が定義されている系。最終出力 R, t もこの系 |
| C（カメラ系） | カメラ光学中心が原点、+z が光軸方向。単位は W と同一 |

**定数（既知・全段固定）**

| 記号 | 型・次元 | 意味 | 出所 |
|---|---|---|---|
| H, W_img | 正整数 [px] | 実カメラ画像の縦・横画素数 | カメラ仕様 |
| f_x, f_y, c_x, c_y | スカラー [px] | 焦点距離・主点 | チェスボード較正 |
| K | 3×3 行列 | 内部行列 [[f_x,0,c_x],[0,f_y,c_y],[0,0,1]] | 同上 |
| δ = (k1,k2,p1,p2[,k3]) | **4 または 5 次元（無次元）** | 歪み係数（OpenCV 並び。k*: 半径方向、p*: 接線方向）。対象カメラのチェスボード較正は **5 係数 (k1,k2,p1,p2,k3)** を出力する（同一機種 osaka2 の較正ファイル `intrinsics_all.toml` で確認、M1 実験時にユーザー確認済み 2026-07-31）。本機能の対象は **4/5 係数**とし、それ以外（8/12/14）は入口で明示的にエラー（「未対応」と出力して終了）。8 は既存資産（`distortions_to_gsplat`、K既知モード）が受理するが、検証用の実レンズが存在せずテスト不能なため本機能ではスコープ外（既存資産側は変更しない）。将来 8 係数レンズを扱う場合は実データを伴う別 feat 案件で拡張する | 同上 |
| I_q | H×W_img×3 | 実カメラ撮影画像（**生のまま無加工**。q = query） | 撮影 |
| 𝒢 = {(μ_i, Σ_i, c_i, o_i)}, i=1..G | G 個の組 | 3DGS モデル。μ_i∈R^3: 中心（W系）、Σ_i∈R^{3×3}: 共分散、c_i: 色、o_i∈[0,1]: 不透明度。G: 数十万〜数百万 | 商用 PLY |

**推定対象**

| 記号 | 型 | 意味 |
|---|---|---|
| R ∈ SO(3) | 3×3（自由度 3） | W系→C系の回転 |
| t ∈ R^3 | 3 次元 [W系長さ単位] | W系→C系の並進。X_C = R·X_W + t |

**基本演算子**

(op-1) 歪み込み投影 π_δ(X; R, t): W系 3D 点 X∈R^3 → 実カメラ画素座標 u∈R^2

```
X_C = R X + t = (X_c, Y_c, Z_c)^T
x_n = X_c/Z_c,  y_n = Y_c/Z_c            （正規化画像座標、無次元）
r^2 = x_n^2 + y_n^2
x_d = (1 + k1 r^2 + k2 r^4 + k3 r^6) x_n + 2 p1 x_n y_n + p2 (r^2 + 2 x_n^2)
y_d = (1 + k1 r^2 + k2 r^4 + k3 r^6) y_n + p1 (r^2 + 2 y_n^2) + 2 p2 x_n y_n
（4 係数時は k3 = 0）
u = (f_x x_d + c_x,  f_y y_d + c_y)^T    [px]
```

OpenCV `projectPoints(X, rvec, tvec, K, δ)` と同一。

(op-2) 点の歪み除去 undist(u): 歪み画素座標 u∈R^2 → ピンホール画素座標 u^pin∈R^2。op-1 の (x_n,y_n)↦(x_d,y_d) の逆写像（反復法）を画素座標で包んだもの。OpenCV `undistortPoints(u, K, δ, P=K)` と同一。**画像でなく座標のみの変換なので補間誤差なし**。

### Stage 0: 入力検証（feat-026 入口）

既存資産（`estimate_camera_params.py` の K既知モードは 4/5/8/12/14 を、`distortions_to_gsplat` は 4/5/8 を受理する）は変更しないため、スコープ外係数の遮断は **feat-026 側の入口で行う**。TOML 読み込み直後に:

```
len(δ) ∉ {4, 5}  ⟹  「歪み係数は4/5係数(k1,k2,p1,p2[,k3])のみ対応」と出力し終了コード 1 で明示エラー
```

これを通過してから Stage 1 / Stage 2 に δ を渡す。この検証がないと、既存資産が 5/8 係数を受理してしまい、スコープ外係数が静かに通る。

| 入力 | 次元 |
|---|---|
| 内部パラメータ TOML（K, δ, size） | — |

| 出力 | 次元 |
|---|---|
| 検証済み K, δ | 3×3, 4〜5 |

### Stage 1: 初期化（唯一の手動段）

```
(R^(0), t^(0)) = argmin_{R∈SO(3), t∈R^3} Σ_{i=1}^{n0} || π_δ(X_i^man; R, t) − u_i^man ||^2
```

| 変数 | 型・次元 | 意味 | 出所 |
|---|---|---|---|
| n0 | スカラー | 手動対応点数 = **5〜6** | 運用 |
| X_i^man | n0×3 [W系] | 手動プロット 3D 基準点（現行運用と同じ、Blender 上） | 手動 |
| u_i^man | n0×2 [px] | 同基準点の**生画像 I_q 上**の画素座標 | 手動 |
| R^(0), t^(0) | 3×3, 3 | **出力**: 初期ポーズ | — |

**この段の目的と要求精度**: 初期化の目的は「大雑把な配置」のみであり、要求は**収束域に入ること**（§4.2(b-1) が与える上限: 位置 数 cm・角度 数度）だけである。それ以上の精度も外れ値耐性も要求しない。

- **外れ値なし前提**: n0 = 5〜6 点は慎重にプロットし、外れ値混入なしを前提とする。既存実装（`estimate_camera_params.py`）は 4〜5 点では RANSAC なしの SQPnP、6 点以上でのみ RANSAC が動くため、5 点時に外れ値検出は働かない——これは本設計では問題としない
- **初期値不良は下流で検出する**: 誤クリック等で初期ポーズが収束域を外れた場合、多くのケースでは Stage 3〜4 でマッチが激減し Stage 4 の失敗判定（N < 30）に落ちる。ただし**これは保証ではない**——初回は τ_px^(0) を緩めるため、周期構造・似た什器・平面壁面の誤対応が 30 点以上残り RANSAC コンセンサスを形成するケースはあり得る。silent failure の排除は Stage 4 単独でなく、**最終受理条件（Stage 7 の項を参照: N_in・RMSE・退化診断・レンダ重畳確認・複数初期摂動からの同一解収束）で担保する**。失敗時はプロットをやり直す（フォールバック運用）

実装 = 既存 `estimate_camera_params.py --intrinsic-toml` をそのまま使用。

以降 Stage 2〜7 は反復ループ（反復番号 k = 0, 1, 2, …）。

### Stage 2: レンダリング（3DGUT 経路による歪み付き直接レンダ）

gsplat の 3DGUT 経路（`with_ut=True, with_eval3d=True, packed=False` + radial/tangential 係数）で、**歪みモデル込みの画像・深度・α を直接生成**する。ワープ後処理は行わない:

```
w_i(v)  = α_i(v) T_i(v),   T_i(v) = Π_{j<i} (1 − α_j(v))
I_r(v)  = Σ_{i∈S(v)} c_i w_i(v)                      （+ 背景合成 (1−A(v))·bg）
A(v)    = Σ_{i∈S(v)} w_i(v)                           … 累積不透明度（αマップ）
D(v)    = Σ_{i∈S(v)} z_i w_i(v) / A(v)                … α正規化済み期待深度（expected depth）
```

| 変数 | 型・次元 | 意味 |
|---|---|---|
| v | 2 次元（画素格子上の全点、H×W_img 個） | **歪み画像側**の画素座標（実写 I_q と同一の投影幾何） |
| S(v) | 整数集合 | 画素 v に投影がかかるガウシアン添字集合（奥行き昇順）。3DGUT 経路では歪みモデル込みの射影で決まる |
| α_i(v) | ∈[0,1] | ガウシアン i の画素 v での実効不透明度（o_i と射影 2D ガウス値の積） |
| T_i(v), w_i(v) | ∈[0,1] | 透過率、ブレンド重み |
| z_i | スカラー [長さ] | ガウシアン i の C系奥行き = (R^(k) μ_i + t^(k)) の z 成分 |
| I_r | H×W_img×3 | **出力**: 歪み付きレンダ画像（r = render） |
| A | H×W_img ∈[0,1] | **出力**: αマップ。**A が小さい画素の D は正規化の分母が小さく不安定**（Stage 4 のゲート (iv) で使用） |
| D | H×W_img [W系長さ] | **出力**: 歪み付き期待深度マップ（**α正規化済み** Σwz/Σw。α ≈ 0 の背景画素は NaN とし Stage 4 のゲート (iv) で扱う） |

**実装（2026-07-31 訂正）**: gsplat 1.5.3 の 3DGUT 経路は render_mode="RGB+ED"（深度同時出力）を**受け付けない**（カーネルが channels==3 のアサーションで停止。案1実験の疎通確認で実機判明。当初の「`render_image(distort=True, return_depth=True)` をそのまま流用」という記述は誤りで、この組み合わせは一度も実行実績がなかった）。実装は **3DGUT レンダ2回**とする:

1. 色: `render_image(distort=True)`（feat-024、実行実績あり）
2. 深度+α: 各ガウシアンのカメラ座標奥行き z_i を3チャンネル複製した「色」として同一設定の 3DGUT レンダに流し、ブレンド出力 Σ(w·z) を α = Σw で除算して D を得る（上の定義式と同一。α > 1e-6 の有効画素に限り gsplat の ED と同一セマンティクス）。実装例: 案1実験の `render_depth_alpha_distorted`（`experiments/a1_synthetic/stage2_smoke_test.py`、codex-08 レビュー済み）

歪み係数の詰め替えは `distortions_to_gsplat` で実装済み（4 係数は radial = [k1,k2,0,0,0,0]、5 係数は radial = [k1,k2,k3,0,0,0]、いずれも tangential = [p1,p2] に展開される）。

**歪みの向きに関する設計判断**: 実写を undistort するのではなくレンダ側を歪み付きで生成する。理由: (1) 広角のため undistort は周辺部を大きく引き伸ばし補間ボケが生じ、マッチャーの特徴が劣化する、(2) 計測の元データ（実写）を一切加工しない、(3) 実写側の点座標の歪み処理は op-2（座標のみ・解析的）と π_δ（PnP が歪み込みで解ける）で完結する、(4) 3DGUT 直接レンダなら合成側にも補間誤差が乗らない（post-warp 方式を採らない理由）。

### Stage 3: マッチング

```
{ (u_q^(j), u_r^(j), s^(j)) }_{j=1..M} = Matcher(I_q, I_r)
```

| 変数 | 型・次元 | 意味 |
|---|---|---|
| Matcher | 関数 | 学習ベース 2 画像マッチャー（MASt3R / LoFTR。学習済みモデルの推論のみ、追加学習なし） |
| M | スカラー | 生マッチ数（期待値: 数百〜数千。シーン・レンダ品質依存） |
| u_q^(j) | M×2 [px] | 対応 j の**実写側**画素座標（生画像上） |
| u_r^(j) | M×2 [px] | 対応 j の**レンダ側**画素座標（歪み付きレンダ上） |
| s^(j) | M×1 ∈[0,1] | マッチャーの信頼度スコア |

### Stage 4: フィルタリング（4 ゲートの AND）

```
J = { j |  s^(j) > τ_s                               … (i)   信頼度ゲート
        ∧ Var_w[D](u_r^(j)) < τ_d^2                 … (ii)  深度平坦性ゲート
        ∧ || u_q^(j) − u_r^(j) || < τ_px^(k)        … (iii) 変位ゲート（反復依存）
        ∧ A(u_r^(j)) > τ_α ∧ D(u_r^(j)) ∈ [z_near, z_far] ∧ D(u_r^(j)) が有限 } … (iv) 深度有効性ゲート
N = |J|
```

| 変数 | 型・次元 | 意味 |
|---|---|---|
| Var_w[D](u) | スカラー [長さ^2] | u 中心の w×w 画素窓内の D の分散。**分散の評価は窓内の有効画素（ゲート (iv) を満たす画素）のみで行う**。深度不連続（格子シルエット・浮遊ガウシアン）の検出器 |
| w | スカラー [px] | 窓幅（例: 5） |
| τ_s | ∈[0,1] | 信頼度閾値（マッチャー推奨値に従う） |
| τ_d | スカラー [長さ] | 深度ばらつき許容値（例: シーン奥行きの 1〜2%） |
| τ_px^(k) | スカラー [px] | 変位許容値（**反復 k に応じた段階的引き締め**、下記） |
| τ_α | ∈[0,1] | α 下限（例: 0.5）。低 α 画素は期待深度の正規化分母が小さく深度が不安定なため棄却 |
| z_near, z_far | スカラー [長さ] | 深度の妥当範囲（シーン寸法から設定。floater・背景抜けの棄却） |
| J | 整数集合 | 生存対応の添字集合 |
| N | スカラー | **出力**: 生存対応数。**N < 30 で失敗と判定し中断**（手動点追加のフォールバックへ） |

**変位ゲートの段階的引き締め（初期誤差との整合条件）**: 初期ポーズの誤差（回転 Δθ、基線 B）による正しい対応の変位は最大 ≈ f·Δθ + f·B/Z_min。一律に τ_px < 格子ピッチ/2（15〜30 px 級）とすると、初期角度誤差 2〜3 度（f=1000 px で 35〜52 px の変位）の**正しい対応まで棄却してしまい矛盾する**。よって:

```
成立条件:  f·Δθ^(k) + f·B^(k)/Z_min < τ_px^(k)        （正しい対応を通す）
周期誤マッチ排除条件:  τ_px^(k) < 格子ピッチ[px] / 2   （k ≥ 1 でのみ課す）
```

- **k = 0（初回）**: τ_px^(0) は初期誤差上限から緩く設定（例: f·(数度) + f·(数cm)/Z_min ≈ 50〜100 px）。この時点では周期誤マッチ排除条件は満たせないが、§4.2(b-1) の通り初回は檻領域のマッチ自体が壊滅しており、非檻領域には周期構造がないため実害は限定的。残った誤対応は Stage 6 の RANSAC が受け持つ
- **k ≥ 1**: ポーズ精度が上がり正しい対応の変位が数 px 以下になるため、τ_px^(k) = 格子ピッチ/2 未満に引き締めて周期誤マッチを排除する（両条件が同時に満たせる）

### Stage 5: 深度 3D 化（レンダ側像点 → W系 3D 点）

対応 j ∈ J それぞれについて:

```
u_r^pin,(j) = undist(u_r^(j))                       … op-2（座標のみの変換）
d^(j)       = D(u_r^(j))                             … 歪み画像上の深度参照 [長さ]
X^(j)       = (R^(k))^T ( d^(j) · K^{-1} ũ_r^pin,(j) − t^(k) ),   ũ = (u_x, u_y, 1)^T
```

| 変数 | 型・次元 | 意味 |
|---|---|---|
| ũ_r^pin,(j) | 3 次元 | u_r^pin,(j) の同次座標（z=1 付加） |
| K^{-1} ũ | 3 次元（無次元） | 画素→正規化カメラ座標の逆投影方向ベクトル（z 成分 = 1） |
| d^(j) · K^{-1} ũ | 3 次元 [長さ] | **C系**での 3D 点（深度 d は z 成分値なので、この積で視線上の点が定まる） |
| (R^(k))^T (· − t^(k)) | — | C系→W系の逆変換 |
| X^(j) | N×3 [W系] | **出力**: 対応 j のシーン座標 3D 点 |

ここで使う R^(k), t^(k) は**レンダリングに使った仮想カメラのポーズであり定義上厳密に既知**（実カメラの真ポーズと違っていてよい。誤差の影響は §4.1 参照）。この段の出力が「手動プロット 20 点の機械的代替物（2D-3D 対応の自動生成）」である。

### Stage 6: ポーズ更新（PnP-RANSAC → インライア集合上の退化診断 → ロバスト最適化）

処理順序: **(6a) RANSAC でインライア集合 I を決定 → (6b) I 上で退化診断（fail なら棄却）→ (6c) I 上でロバスト最適化**。

**(6a) PnP-RANSAC**: `solvePnPRansac`（最小解 P3P）で仮ポーズとインライア集合 I ⊆ J を得る。

**(6b) 幾何退化診断（インライア集合 I 上で実施）**: 点数だけでは PnP の成立を保証しない。非檻領域（壁・床・什器）にマッチが偏る前提では、対応点が単一平面・細い帯・同一奥行きに集中して PnP が退化・不安定化し得る。診断は**必ず RANSAC 後のインライア集合 I に対して**行う——候補集合 J で診断すると、J に散らばった外れ値が λ_3/λ_1 や凸包面積を見かけ上良くし、実際の支持集合 I が単一平面でも診断を通過してしまうため（外れ値による退化隠蔽）。閾値割れは**失敗扱い**とする（診断値は最終出力にも含める）:

```
λ_1 ≥ λ_2 ≥ λ_3 = eig( Cov({X^(j)}_{j∈I}) )   … RANSACインライア3D点群の共分散固有値 [長さ^2]
条件1（体積性）:   λ_3 / λ_1 > τ_vol            （λ_3/λ_1 ≈ 0 は共面退化。**原則 fail 扱い**）
条件2（深度レンジ）: max_{j∈I} d^(j) − min_{j∈I} d^(j) > τ_z   （同一奥行き集中の検出）
条件3（画像分布）:  {u_q^(j)}_{j∈I} の凸包面積 / (H·W_img) > τ_area  （画面の一隅への集中の検出）
```

| 変数 | 型 | 意味 |
|---|---|---|
| Cov({X}) | 3×3 行列 | RANSAC インライア 3D 点群の標本共分散（W系） |
| λ_1..λ_3 | スカラー [長さ^2] | その固有値（降順）。点群の広がりの主軸成分 |
| τ_vol, τ_z, τ_area | スカラー | 退化判定閾値（design で確定。実験 A/C の実データで較正する） |

**平面退化を原則 fail とする理由**: K既知の PnP は数学上は平面配置でも可解だが、本手法は非檻領域（壁・床・什器）のマッチに頼る前提のため、**単一平面（例: 壁一面）への偏りは現実的な主失敗パターン**であり、点数・深度レンジ・画像分布が十分でも外部パラメータの精度評価としては危険。よって λ_3/λ_1 < τ_vol は原則 fail とする。平面配置をどうしても許容する必要が生じた場合は、planar 専用モードとして (1) IPPE / `solvePnPGeneric` で複数解を列挙、(2) 解の分離量の確認、(3) 最終レンダ重畳の再一致、(4) ホールドアウト点での再投影検証、による曖昧性棄却を必須条件とする（本スコープでは planar モードは実装しない。要件化する場合は別途 design で定義）。

**(6c) ロバスト最適化**（退化診断通過後、I 上で実施）:

```
(R^(k+1), t^(k+1)) = argmin_{R∈SO(3), t∈R^3} Σ_{j∈I} ρ( || π_δ(X^(j); R, t) − u_q^(j) ||^2 )
```

| 変数 | 型・次元 | 意味 |
|---|---|---|
| I ⊆ J | 整数集合 | RANSAC（solvePnPRansac、最小解 P3P）が選んだインライア集合 |
| ρ(·) | 関数 | ロバスト損失（Huber 等）。RANSAC をすり抜けた少数誤対応の影響を抑圧 |
| u_q^(j) | 2 次元 [px] | 実写側像点（**生座標のまま**。歪みは π_δ 側が背負う） |
| R^(k+1), t^(k+1) | 3×3, 3 | **出力**: 更新ポーズ |
| N_in = \|I\|, RMSE | スカラー 2 個 | **出力**: 診断値（インライア数、インライア再投影 RMSE [px]） |

**実装スコープ注記**: 既存 K既知モードは `solvePnPRansac` → `solvePnP` 精密化であり、ロバスト損失 ρ を含む最適化（Huber 等）は**存在しない**。本段の ρ 付き最適化は**新規実装**である。実装は「ロバスト非線形最小二乗」= `scipy.optimize.least_squares(method='trf', loss='huber')`（または `'soft_l1'`）とする。**`method='lm'` は `loss='linear'` のみ対応**（SciPy の仕様）のため、LM 法とロバスト損失は併用できない——本段は LM でなく TRF を用いる。RANSAC 部は既存資産と同型のため流用可。

### Stage 7: 収束判定

```
Δθ^(k) = arccos( (tr((R^(k))^T R^(k+1)) − 1) / 2 )     … 回転更新量 [rad]（測地距離）
Δτ^(k) = || t^(k+1) − t^(k) ||                          … 並進更新量 [W系長さ]
Δθ^(k) < ε_R ∧ Δτ^(k) < ε_t  ⟹ 終了、さもなくば k ← k+1 で Stage 2 へ
```

| 変数 | 型 | 意味 |
|---|---|---|
| ε_R, ε_t | スカラー | 収束閾値（例: 0.05°、シーンスケールの 0.1%） |
| k_max | 正整数 | 最大反復数（例: 5）で打ち切り。実用上 2〜3 周で収束見込み（GS-CPR は 1 周でも成立と報告） |

**最終受理条件**: 収束しただけでは結果を受理しない。silent failure（誤対応コンセンサスによる誤収束）排除のため、以下を**すべて**満たした場合のみ受理とする:

1. N_in ≥ 下限（例: 30）かつ インライア再投影 RMSE ≤ 上限（例: 2 px。値は design で確定）
2. 幾何退化診断（Stage 6a）を最終反復でも通過していること
3. **レンダ重畳確認**: 最終ポーズでのレンダリングと実写の重畳画像を出力し、構造物（格子等）のずれを目視確認する（診断画像として常に保存）
4. **複数初期摂動からの同一解収束**（自動検算）: 最終ポーズに小摂動（例: 位置 ±数 cm・角度 ±数度の数通り）を加えた初期値から再実行し、全ケースが同一解（差 < ε_R, ε_t 相当）へ収束すること。誤対応コンセンサスによる偽解は摂動に対して不安定なため、これで棄却できる

**最終出力**: R, t（6 自由度、W系）+ 診断値（N_in, RMSE, {Δθ^(k), Δτ^(k)} 履歴, 退化診断値, 重畳画像, 摂動検算結果）

### 全体データフロー

```
手動 n0=5〜6組 ──PnP──▶ (R^(0),t^(0)) [6自由度]
                            │◀─────────────────┐
PLY [Gガウシアン] ──render+distort──▶ I_r [H×W×3], D [H×W]  │
実写 I_q [H×W×3]（生）──match──▶ M組 [M×5]                │
                     ──filter──▶ N組 [N×4]  (N≤M)          │

                     ──PnP-RANSAC→退化診断→ロバスト最適化──▶ (R^(k+1),t^(k+1)) ─未収束┘
                                          │収束
                                          ▼
                              最終 R,t [6自由度] + 診断値
```

## 4. 成立性の解析

記号: 焦点距離 f [px]、シーン奥行き Z、初期ポーズと真ポーズの位置差（基線）B、深度マップ誤差 δd、マッチング誤差 σ_m [px]、対応数 N。

### 4.1 実現可能側の根拠

**(a-1) 深度誤差は基線に比例してしか効かない（本手法の核心）**

深度で持ち上げた 3D 点はレンダリングカメラの**視線上**に必ず乗る。深度が δd 狂うと点は視線に沿って滑るが、それを基線 B だけ離れた実カメラへ投影したときのずれは視差の差分:

```
ε_depth ≈ f · B · δd / Z^2
```

数値例: B = 5 cm（5〜6 点 PnP 初期値）、δd = 5 cm（悲観値）、Z = 2 m、f = 1000 px → ε ≈ 0.63 px（マッチング誤差と同等以下）。さらに反復でポーズが更新され B → 数 mm になると、この項は **B に比例して消滅**する。つまり深度マップが多少汚くても収束点は正しい（不動点が真値になる構造）。これが多視点三角測量（深度誤差がそのまま 3D 誤差になる）より原理的に有利な点であり、反復ループ（Stage 7 → Stage 2）を持つ理由。

**(a-2) 収束時の到達精度はマッチング誤差で決まる**

N 点 PnP の誤差伝播（最小二乗の標準理論）より、回転誤差 σ_R ≈ (σ_m/f)·√(C/N)、並進誤差 σ_t ≈ Z·σ_R（C: 点配置の条件数依存係数、良配置で数〜10）。σ_m = 1 px、f = 1000、N = 200、C = 25（保守値）で回転 ≈ 0.02°、並進 ≈ 0.7 mm（Z = 2 m）。GS-CPR の実測 0.8 cm / 0.25° はこれより一桁緩い（実環境のマッチ品質を反映）が、手動 20 点方式（σ_m = 1〜2 px、N = 20、3D プロット誤差が別途加算）を上回る見込み。

### 4.2 実現不可能となる条件

**(b-1) 檻の格子によるオクルージョン非相関化 — 初期値精度の上限を与える**

格子（距離 Z1）越しに背景（距離 Z2）が見える画素では、視点が B ずれると格子と背景の重なりが

```
Δ = f · B · | 1/Z1 − 1/Z2 |
```

だけずれる。数値例: Z1 = 1 m、Z2 = 3 m、f = 1000 → Δ ≈ 0.67·B[mm] px。B = 10 cm で 67 px。格子ピッチが画像上 30〜60 px なら、初期位置誤差 ≈5〜10 cm を超えた時点で檻領域の見え方は「別の画像」になりマッチが全滅する。

帰結: (1) 目分量初期値（30 cm 級）では檻領域は使えない。5〜6 点 PnP 初期値（数 cm）が必要な理由。(2) 設計としては**檻以外（壁・床・什器）のマッチで成立する前提**に置く。画面内に檻以外の領域が十分写っていないカメラでは本手法は成立しない（不成立条件）。

**(b-2) 深度の外れ値率が RANSAC の破綻点を超える場合**

格子はシルエット境界（深度不連続）の密度が極めて高く、境界画素の深度は α 混合で狂う。外れ値が過半を超えると RANSAC ごと破綻する。対策 = Stage 4 の深度平坦性ゲート（ii）で持ち上げ前に棄却。棄却後の N が 30 を割るなら不成立と判定する。

**(b-3) 繰り返しパターンの周期誤マッチ**

格子は周期構造なので「1 周期ずれた誤対応」が**互いに整合して** RANSAC のコンセンサスを形成し得る。対策 = Stage 4 の変位ゲート（iii）で τ_px < 格子ピッチ/2 に制限。これも初期値が (b-1) の精度を満たしていることが前提。

**(b-4) レンダリング品質の破綻 — 設計で救えない唯一のリスク**

実カメラは檻の外・壁際にあり、商用ソフトの 3DGS 学習撮影がその位置の近くを通っていない場合、その視点からのレンダリングは外挿となり品質が崩壊する（3DGS は学習視点近傍でしか品質を保証しない）。壁際は撮影経路が物理的に通りにくく、**本環境で最も現実的な不成立シナリオ**。式では判定できず、実験（§5 実験 A）でのみ確認できる。

## 5. 実装前の検証実験（この順で実施）

### 実験 A: ドメインギャップ検証＋摂動回復検証（最優先）

- 内容（2 段階）:
  - **A-1（マッチング成否）**: 既存の手動 20 点方式で推定済みのポーズを使い、Stage 2 の2パス方式（色: `render_image(distort=True)`、深度+α: `render_depth_alpha_distorted`）で 1 枚レンダリング。実写 1 枚とのマッチングを SIFT → LoFTR → MASt3R の順で試し、マッチ数・分布（檻領域/非檻領域）・Stage 4 各ゲートの生存数を確認する
  - **A-2（摂動回復）**: 推定済みポーズに**既知の摂動**（例: 位置 ±3〜10 cm、角度 ±2〜5 度の数通り）を加えた初期値から Stage 2〜7 を回し、元ポーズへ戻るかを測る。マッチ数だけでは「幾何的に整合した誤対応が間違った PnP 解を作る」ケースを検出できないため、**end-to-end の回復性で判定する**
- 判定指標（セットで見る）: マッチ数 N、RANSAC インライア率、再投影 RMSE、**ポーズ回復量（摂動前ポーズとの残差 Δθ・Δτ）**、退化診断値（λ_3/λ_1、深度レンジ、画像分布）
- 合格条件: 全摂動ケースで元ポーズ近傍（目安: 位置 1 cm・角度 0.1 度以内。値は design で確定）へ収束すること
- 不合格時: 本手法は不成立として棄却（COLMAP 系フォールバックの再検討または現行手法の改善に転換）
- 推定済みポーズ起点のため初期値取得の問題と切り離して (b-4) と収束性だけを測れる。A-2 は Stage 3〜7 の簡易実装を要するが、それ自体が本実装のプロトタイプになる

### 実験 B: 少点数 PnP の初期値精度検証（実装ゼロ・既存データのみ）

- 内容: 既存の 20 点超対応データから、(1) 全点で PnP → 基準ポーズ、(2) 5〜6 点をランダム抽出して PnP、を多数回繰り返し、基準ポーズとの差（位置・角度）の分布を測る
- 判定 1: 差の分布が (b-1) の要求（位置 数 cm・角度 数度）に収まるか → Stage 1 の成立性確認
- 判定 2: 差が phase4 用途で無視できるほど小さい場合、**リファイン段自体が不要**（5〜6 点 PnP のみで完了）という結論もあり得る。本パイプラインの必要性自体をこの実験が判定する

### 実験 C: 深度マップ品質検証（実験 A 通過後）

- 内容: 手動プロット済みの既知 3D 基準点について、レンダ深度から Stage 5 の式で逆算した 3D 座標と手動 3D 座標の差を測る
- 判定: δd の実測値を得て §4.1 の誤差見積りを実データで裏付ける。(b-2) の外れ値率も同時に観測
