## 背景: 何が分かっていないか（未知X）

**初期ポーズ（位置・角度）を真のポーズからどれだけ離して置いても、パイプライン全体（レンダ→マッチング→3D化→PnP→反復）を回した後に推定値が真値に収束するか——この範囲（収束域）は分かっていない。**

- pipeline.md §4.2(b-1) の「数cm・数度」は、一つの故障モード（変位ゲート）だけから、未実測の仮定値（部屋の寸法・格子ピッチ・ゲート幅）で机上逆算した推測値であり、実証されていない
- M1（実験B）はこの未実証の閾値を判定基準に使い、かつ合格ライン（試行の何%が収まれば合格か）を事前定義しないまま「条件付きGo」と述べた——判定として不成立（M1 の位置づけは「差の分布の実測」に留まる。`../m1/report.md` の補遺参照）
- 収束域はマッチャーの視点差耐性・誤対応の挙動・反復の縮小性の合成で決まり、式だけからは出ない。実測が必要

## Stage 2（疎通確認）— 実行前予測（記載済み・実行はセットアップ承認後）

**内容**: 真ポーズでレンダリングしクエリを生成。同じ真ポーズでもう一度レンダリングして比較する。

**予測**:
1. 同一ポーズ・同一入力の2回のレンダは画素一致する（差分最大絶対値 0、CUDA非決定性があっても ≤1/255 程度）。崩れたらレンダの非決定性の問題であり、以降の全比較の前提が崩れるため最初に確認する
2. レンダ画像は病室シーンとして成立した見えになる。崩れていたら座標規約か near_plane を疑う
3. αマップの大部分（>90%）が高α。低α領域が広ければ、以降のゲート(iv)で落ちる母数として記録する
