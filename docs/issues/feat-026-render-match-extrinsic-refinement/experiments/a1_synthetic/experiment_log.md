## 背景: 何が分かっていないか（未知X）

**初期ポーズ（位置・角度）を真のポーズからどれだけ離して置いても、パイプライン全体（レンダ→マッチング→3D化→PnP→反復）を回した後に推定値が真値に収束するか——この範囲（収束域）は分かっていない。**

- pipeline.md §4.2(b-1) の「数cm・数度」は、一つの故障モード（変位ゲート）だけから、未実測の仮定値（部屋の寸法・格子ピッチ・ゲート幅）で机上逆算した推測値であり、実証されていない
- M1（実験B）はこの未実証の閾値を判定基準に使い、かつ合格ライン（試行の何%が収まれば合格か）を事前定義しないまま「条件付きGo」と述べた——判定として不成立（M1 の位置づけは「差の分布の実測」に留まる。`../m1/report.md` の補遺参照）
- 収束域はマッチャーの視点差耐性・誤対応の挙動・反復の縮小性の合成で決まり、式だけからは出ない。実測が必要

## 未知Xの解き方（検討した案）

|---|---|---|---|

## Stage 2（疎通確認）— 実行前予測（記載済み・実行はセットアップ承認後）

**内容**: 真ポーズでレンダリングしクエリを生成。同じ真ポーズでもう一度レンダリングして比較する。

**予測**:
1. 同一ポーズ・同一入力の2回のレンダは画素一致する（差分最大絶対値 0、CUDA非決定性があっても ≤1/255 程度）。崩れたらレンダの非決定性の問題であり、以降の全比較の前提が崩れるため最初に確認する
2. レンダ画像は病室シーンとして成立した見えになる。崩れていたら座標規約か near_plane を疑う
3. αマップの大部分（>90%）が高α。低α領域が広ければ、以降のゲート(iv)で落ちる母数として記録する

## 実行記録

### 2026-07-31 Stage 2 実行1回目 — 失敗（想定外事象）

- 事象: `render_image(distort=True, return_depth=True)` が gsplat カーネルのアサーション `channels == 3` で停止（`rasterize_to_pixels_from_world_3dgs_fwd`）
- 原因: gsplat 1.5.3 の 3DGUT 経路（with_ut/with_eval3d）は render_mode="RGB+ED" 非対応。既存実績は「深度あり・歪みなし」（feat-016）と「歪みあり・深度なし」（feat-024）のみで、併用は一度も実行されたことがなかった。pipeline.md の「併用は実装済み」という記述はコードの見た目からの誤断定だった（codex レビューも見逃し）
- 対処（方式A、ユーザー承認済み）: 3DGUT レンダ2回方式に変更。深度は z_i を色として流しαで正規化（`render_depth_alpha_distorted`）。実装は codex-08〜10 でレビューし高・中ゼロに収束（指摘反映: 有効画素ゼロ時の失敗報告・ドキュメント整合・EDセマンティクス注記・pipeline.md 後段の旧記述差し替え）。pipeline.md Stage 2 の実装記述も訂正済み

### Stage 4〜6（ゲート→3D化→PnP、反復1回分）— 実行前予測（実行前に記載）

**内容**: Stage 3 のマッチ集合（1370件）に Stage 4 ゲートを適用 → 生存対応を深度で3D化（Stage 5）→ PnP-RANSAC + 精密化（Stage 6）→ 推定ポーズと真ポーズの誤差を測定。反復1回で初期誤差（5cm/2°）がどこまで縮むかを見る。

**実験用パラメータ（このステップで確定した値）**:
- ゲート(i)（マッチャー信頼度）: SIFT は信頼度スコアを持たないため**比率テストで代替済みとして適用しない**（学習ベースマッチャー導入時に有効化）
- ゲート(ii): 5×5 窓の深度分散、τ_d = シーン中央値深度の2%（0.06m）
- ゲート(iii): τ_px^(0) = 250px（式 f·Δθ + f·B/Z_min = 1218×0.0349 + 1218×0.05/0.53 ≈ 157px に、回転・並進の幾何合成の余裕1.5倍。実測最大変位166.7pxを覆う）
- ゲート(iv): α > 0.5、有限深度、z ∈ [0.5, 10] m
- Stage 6: solvePnPRansac(閾値8px, ITERATIVE) + solvePnP精密化（既存実装と同型）。ロバスト非線形最小二乗（Huber/TRF）は本実験では省略（phase4 環境に scipy がないため。誤対応除去は RANSAC が担う。本実装時は pipeline.md 通り実装する）

**予測**（Stage 3 実測: マッチ1370・深度有効1315・正解率79.2%・位置決め誤差中央値0.24px に基づく）:
1. ゲート生存数 N: **900〜1300**（正しいマッチはゲートでほぼ落ちず、粗大変位の誤マッチの一部が(iii)で落ちる）
2. RANSAC インライア: **1000〜1200**、インライア純度（oracle正解率）**>95%**（8px閾値なので5〜8pxの準誤マッチが少数混入し得る）
3. 退化診断: 本実験では**診断値の記録のみ**（閾値 τ_vol/τ_z/τ_area はこの実験群の実測から較正する予定のため、fail 判定には使わない）。予測値: 点は画面全体に分布・深度レンジ数m・λ3/λ1 は共面でない値（>0.01 のオーダー）
4. **ポーズ誤差（本命）**: 誤差伝播式 σ_R ≈ (σ_m/f)√(C/N) に σ_m=0.5px（保守値）、N=1000、C=25 で回転 ≈0.004°、並進 ≈ Z·σ_R ≈ 0.2mm。実際は誤対応の残留・点分布の偏りで悪化するため、**回転 ≤ 0.05°、カメラ中心位置 ≤ 5mm** を成立予測とする（初期誤差 2°/5cm から**1桁以上の縮小**）。インライア再投影RMSE ≈ 0.3〜1px
5. 外れた場合の疑い先: ポーズ誤差が予測より1桁以上悪い→インライア純度を確認（周期構造の整合誤マッチの残留）または深度バイアス（Stage 5）。系統的オフセット→Stage 5 の式・座標系。退化診断不通過→点分布（診断値を確認）

補足（角度摂動の定義、ユーザー指摘により明記）: 本マップの「角度」は**首振り型**——回転のピボットはカメラ光学中心自身、回転軸はカメラ座標系で表現した乱数固定軸（seed=1、パン/チルト/ロールの混合）。`R_new = R_δ @ R`、カメラ中心は位置摂動のみで移動。**注視点（シーン中の点）を中心とした軌道回転ではない**。首振り型は画像全体が f·Δθ で一様にずれる最悪の形であり、注視点固定型なら同じ角度でも変位は視差分のみで収束域はずっと広いはず。実運用の PnP 誤差は回転・並進が補償し合う（注視点固定型に近い）傾向があるため、本マップは保守側の測定。ただし手動点が画像内で偏った場合は首振り型の誤差が実際に出る（ユーザー経験則。Stage 1.5 の動機）。

### 粗整列レスキュー実験（Stage 1.5 候補の検証）— 実行前予測（実行前に記載）

**内容**: 収束域マップの失敗10ケース（位置5〜50cm × 角度20°/30°、同一seed=1）に対し、反復に入る前に**粗整列**を挿入する: 初期ポーズでレンダ → クエリとの生SIFTマッチ（比率テストのみ、変位ゲートなし）→ マッチ光線ペアの回転のみ Kabsch 整列（トリミング付き）で首振りずれを推定・補正 → 補正後ポーズから `run_pipeline` を回す。

**予測**:
1. **生マッチは大角度でも取れる**: SIFT は平行移動・面内回転に頑健なので、20°で数百件、30°でも100件以上（視野オーバーラップ減による低下はある）。これが取れなければ「ゲートでなくマッチングが律速」となり Stage 1.5 は成立しない
2. **Kabsch 補正後の残存角度誤差 < 3°**（残る誤差源は位置摂動による視差と誤マッチ。トリミングで誤マッチの影響を抑制）。位置誤差は補正されずそのまま（回転のみ整列）
3. 補正後は全ケースが収束域（角度≤10°・位置≤50cm）に入り、**run_pipeline で成功（0.2mm床に到達）**。30°側はオーバーラップ減で不確実性が高いが成功側に予測
4. 外れた場合の疑い先: 生マッチ不足→SIFT の視点差限界（学習ベースマッチャーの動機）。Kabsch 残差大→誤マッチ支配（トリミング閾値の調整）。補正後に反復失敗→残存誤差が収束域外（補正の反復適用を検討）
