## 1. 実験の問い

学習ベースマッチャー（LoFTR / MASt3R）は、実写クエリ vs 3DGS レンダのペア（病院シーン・5カメラ）で:

## 4. パイプライン定数（M3 と同一。変更禁止）

- M3 criteria §4 の全定数を継承する: K_MAX=5、N_MIN=30、収束判定 Δc ≤ 5mm（EPS_POS_M=0.005）かつ Δθ ≤ 0.05°（EPS_ROT_DEG）、変位ゲート・深度系ゲート（α・z範囲・分散・2×2広がり）・RANSAC PnP 設定のすべて
- SIFT の ratio 段（SIFT_RATIO=0.75）のみマッチャー固有のため、LoFTR は §3.1 の confidence 閾値、MASt3R は相互最近傍がこれに対応する。**変位以降のゲート・PnP・収束判定は一切変更しない**
- 除外内訳の逐次分類は depth_ok → α → z → 分散の順（M4-1 と同一の分離記録）

## 5. 実験構成（3フェーズ。順序固定・前フェーズ不成立なら打ち切り）

環境連携（固定）: レンダ・ゲート・PnP は phase4 環境のドライバが実行し、マッチャー推論は matcher_lab 環境の CLI スクリプトを subprocess で呼ぶ。受け渡しは PNG（画像）/ NPZ（マッチ座標）ファイルとする。

### フェーズ0: 疎通（判定なしの前提確認。不成立なら原因記録の上で中断）

- (a) **SIFT 再現**: P0 基準ポーズ k=0 のレンダを phase4 環境で生成し、SIFT マッチングを再実行して §3.3 の生マッチ数・N と全カメラ完全一致することを確認（決定論パイプラインの再現チェック。M4-1 フェーズ0 と同趣旨）
- (b) **マッチャー疎通**: LoFTR 両重み（outdoor / indoor_new）と MASt3R チェックポイントが**ローカルキャッシュからオフラインでロード可能**であること（§3.1/3.2 の sha256 と一致）を確認した上で、cam05520126 の実ペア（クエリ vs P0 レンダ）で LoFTR（2重み）・MASt3R を実行し、マッチが返ること・座標が画像範囲内であることを確認（数の判定はしない）
- (c) **逆写像検証（数値基準で合否判定）**: LoFTR fallback（採用時）と MASt3R の各逆写像について、(i) 既知グリッド点（原寸座標の格子点25点）を縮小座標系へ順写像 → 逆写像した round-trip 誤差が**全点 ≤ 0.5px**、(ii) 実マッチ座標の逆写像結果が**原寸画像範囲内率 100%**、の両方を満たすこと。加えて目視重畳画像1枚（クエリ・レンダに対応線を描画）で大域的な整合を確認する。MASt3R は導出した変換式（`true_shape`・テンソル形状・切り詰め量）を log に記録する
- (d) **再現性の記録**: 同一入力で LoFTR・MASt3R を各2回実行し、マッチ数・座標の差を記録する（GPU 推論の非決定性の有無。判定には使わず、以降の解釈の但し書きに使う）

### フェーズ1: マッチング段のオフライン比較（5カメラ × 全設定）

- P0 k=0 ペア（クエリ vs 基準ポーズレンダ）に対し、LoFTR 8設定 + MASt3R 1設定の各々で、段別内訳（生マッチ → 変位後 → 深度系後 = N。深度系は除外内訳つき）を5カメラ分記録し、§3.3 の SIFT 表と並記する
- 深度・ゲートの適用は phase4 環境で保存した中間生成物（深度マップ・α等）へのオフライン適用（M4-1 の `m4_1_sweep.py` 方式）
- **フェーズ2 進出条件（マッチャー単位）**: 当該マッチャーの少なくとも1設定で「5カメラ中3カメラ以上がゲート後 N ≥ 30」
- **フェーズ2 採用設定の選択規則（事前固定・一意に閉じる）**: 進出条件を満たす設定のうち (1)「5カメラの N の最小値」が最大のもの → (2) 同点なら N の5カメラ合計が大きい方 → (3) 同点なら confidence 閾値が高い方（外れ値混入が少ない側を優先）→ (4) なお同点なら重みは `indoor_new` を優先（病院屋内シーンに近い学習ドメインのため。codex-56 指摘のタイブレーク固定）
- 両マッチャーとも**フェーズ1 は必ず実施する**（LoFTR が進出条件を満たしても MASt3R のフェーズ1 は実施する。知見収集が本実験の目的のため）

### フェーズ2: E2E（P0・P1・P2 系列の成立性・同一解・一致性）

- フェーズ1 進出条件を満たしたマッチャー（採用設定は §5 の選択規則）で Stage 2〜7 を完走する
- 系列は M3 §5.2 の P0（無摂動）・P1・P2（5cm/2°、seed 11・12）の3系列。P3・P4 は実施しない（実写収束域の実測は M3 で取得済み。本実験の問いはマッチャー差し替えの成立性）
- 判定は M3 criteria と同一: 成立性（§5.1: 全反復 N ≥ 30、k_max=5 以内収束）、同一解（§5.2: P0・P1・P2 すべて成立 + 最大ペア間 1cm/0.1°）、一致性（§5.3: カメラ別 p95 閾値表。cam05520126: 2.55cm/0.35°、cam05520129: 2.29cm/0.46°、cam41520554: 1.84cm/0.39°、cam41520556: 2.05cm/0.44°、cam41520557: 2.40cm/0.41°）
- 診断値（RMSE・λ3/λ1・深度レンジ・凸包面積比）は M3 §5.5 と同じ暫定警告閾値で記録する（合否に使わない）

## 6. 判定基準（数値固定）

### 6.1 フェーズ1 適格（マッチャー単位）

- §5 フェーズ1 の進出条件のとおり: 少なくとも1設定で5カメラ中3カメラ以上がゲート後 N ≥ 30

### 6.2 M3b 全体の Go / No-Go

- **Go**: 少なくとも1マッチャーがフェーズ2 で「3カメラ以上が成立性 + 同一解 + 一致性をすべて満たす」（M3 §6 と同じ過半数基準）→ 檻シーン適用実験（別 criteria）の設計に進む根拠となる
- **No-Go**: 両マッチャーとも上記未達 → 候補3 の病院シーンでの限界を記録し、対処候補の再評価（`survey_lattice_problem.md` §5 の再検討: ゲート・リフトのアルゴリズム変更系等）へ
- 部分結果の扱い: LoFTR が No-Go でも MASt3R の評価は必ず実施する（逆も同じ）。マッチャー間の差自体が檻適用の選定材料になる

### 6.3 判定に使わないもの

- フェーズ0(d) の再現性記録、診断値、SIFT との速度差（実行時間は記録するが合否に使わない）

## 7. 試行回数の管理

- 各フェーズは各マッチャーにつき**1回実行**。再実行が許されるのは「実装欠陥が特定・修正・記録された場合」のみ（M4-1 §6 と同じ運用。結果を見てからの設定追加・閾値変更・重み変更による再実行は禁止）
- LoFTR の confidence 閾値・重み、MASt3R の subsample 等、§3 で固定した以外の水準を事後に追加しない
