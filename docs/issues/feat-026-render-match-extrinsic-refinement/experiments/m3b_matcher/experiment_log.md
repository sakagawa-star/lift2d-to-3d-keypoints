# M3b 実験ログ（予測 → 実測 → 照合）

criteria.md（locked 2026-08-02）§8/§9 に基づく記録。各フェーズの予測は**実行直前**に記す。

## フェーズ0: 疎通

### 予測（2026-08-02、実行前に記録）

1. **SIFT 再現**: 5カメラすべてで生マッチ数・N が M3 実測（§3.3 表）と**完全一致**すると予測する。根拠: パイプラインは決定論（M4-1 フェーズ0 で同種の再現チェックが全列完全一致した前例。レンダ・SIFT・ゲートに乱数依存なし）
2. **マッチャー疎通**: LoFTR 両重み・MASt3R ともロード成功しマッチ>0。**LoFTR は full（1920x1080）で OOM しない**と予測する。根拠: kornia LoFTR は linear attention で粗グリッドは 240x135、VRAM 16GB に対し余裕がある見込み（ただし実測未確認のため外れる可能性は相応にある。OOM した場合は criteria §3.1 の fallback 1280x720 に統一）
3. **逆写像検証**: round-trip ≤0.5px・範囲内率100% を**通過**すると予測する。根拠: 変換は解析的な線形写像（スケール+オフセット）であり、式が正しければ round-trip 誤差は数値誤差レベル
4. **再現性（記録のみ）**: LoFTR・MASt3R とも同一入力で**決定的（マッチ数同一・座標差 0px）**と予測する。根拠: 推論のみで dropout 等なし。ただし GPU の非決定カーネルで微小差が出る可能性あり（出た場合も判定には使わない）

### 実測（2026-08-02）

1. SIFT 再現: **5カメラ全列完全一致**（生マッチ・N とも）。TOML・重み・ckpt の同一性検証もすべて一致
2. マッチャー疎通: **LoFTR は full（1920x1080）で CUDA OOM** → criteria §3.1 の規則どおり全設定・全カメラを 1280x720 に統一。統一後は3マッチャーとも成功。cam05520126 のマッチ数: loftr_outdoor **6937** / loftr_indoor_new **379** / mast3r **2138**（参考: SIFT 生マッチ 300）
3. 逆写像検証: round-trip 最大 2.3e-13px（LoFTR）/ 1.1e-16px（MASt3R）、範囲内率 1.000 → 通過
4. 再現性: 3マッチャーとも同一入力でマッチ数同一・座標最大差 0.0000px（**決定的**）

### 照合

- 予測1・3・4は的中。**予測2（OOM しない）は外れ**: LoFTR full は 16GB でも OOM した（phase4 プロセスが CUDA メモリを保持した状態での同時実行だったことが一因の可能性。記録のみ）。fallback 規則が設計どおり機能し実験は続行
- 予測外の観測: LoFTR の重み間差が想定より極端（outdoor 6937 vs indoor_new 379、18倍）。屋内シーンだが outdoor（MegaDepth）が圧倒的に優位。フェーズ1 の重み間予測の根拠になる

## フェーズ1: マッチング段のオフライン比較

### 予測（2026-08-02、フェーズ0 の観測を根拠に実行直前に記録）

1. **生マッチ数（th=0.0、5カメラのレンジ）**: loftr_outdoor 3000〜9000 / loftr_indoor_new 100〜1000 / mast3r 1500〜3000。根拠: フェーズ0 の cam05520126 観測値がレンジ中央付近に来ると仮定
2. **重み間の優劣**: 全カメラで outdoor > indoor_new（フェーズ0 で18倍差）
3. **confidence 閾値の減衰**: th=0.2 は th=0.0 とほぼ同数（LoFTR 内部の粗マッチ閾値 0.2 が既に効いているため）。th=0.5 で 5〜8割残存、th=0.8 で 2〜6割残存
4. **ゲート後 N**: SIFT の通過率実測（raw→N 約78%）に対し、学習マッチャーは誤対応（大変位）混入があり得るため通過率 40〜80% と予測。N レンジ: loftr_outdoor@0.0 で 1500〜7000 / indoor_new@0.0 で 50〜800 / mast3r で 600〜2400
5. **進出判定**: loftr_outdoor 系と mast3r は「3カメラ以上 N≥30」を満たす（高確度）。indoor_new も満たす可能性が高いが不確実
6. **採用設定**: 選択規則により loftr_outdoor 系。minN が th=0.0/0.2 で同点なら閾値の高い 0.2 が選ばれると予測

### 実測（2026-08-02。詳細: m3b_stage_table.csv / m3b_result.txt）

- 生マッチ（th=0.0）: loftr_outdoor 5752〜8463 / loftr_indoor_new 379〜5555 / mast3r 2138〜2274
- ゲート後 N: loftr_outdoor@0.0 5432〜7943 / mast3r 1971〜2196（**SIFT の N 231〜340 の 20〜30倍**）
- 内訳の特徴: **変位ゲートの除外はほぼ 0**（学習マッチャーは P0 で大変位の誤対応をほぼ出さない）、α・z 除外は全設定で 0、除外は 2×2広がり（1〜4%）と分散（3〜7%）のみ。ゲート通過率は約90%（SIFT の78%より高い）
- 閾値減衰: th=0.2 は th=0.0 と完全同数（LoFTR 内部閾値 0.2 が既に適用済み）。outdoor は th=0.8 でも N 1612〜3448 で全カメラ適格
- indoor_new の弱点: cam05520126 のみ極端に弱い（raw 379、th=0.5 で 4、th=0.8 で 0）。他4カメラは数千。カメラ（視点）依存の不安定性
- **進出判定: LoFTR（8設定すべて適格）・MASt3R（5/5）とも進出**。採用設定は選択規則どおり **loftr_outdoor@0.2**（minN=5432。th=0.0 と同点→閾値高い方）

### 照合

- 的中: 予測2（全カメラで outdoor 優位）、予測3の th=0.2 同数、予測5（両者進出）、予測6（**採用 loftr_outdoor@0.2 まで的中**）
- 外れ: 予測1のうち indoor_new のレンジ（100〜1000 と予測 → 実測 379〜5555。フェーズ0 の cam05520126 が実は indoor_new の最悪ケースだった）、予測4の通過率上限（40〜80% と予測 → 実測 約90%。誤対応混入の想定が過剰に悲観的だった）
- 解釈: 檻問題の要因①（ratio 律速のマッチ枯渇）に対する候補3の狙い（母数増）は、病院シーンでは桁違いに達成される。カメラ依存の不安定性（indoor_new@126）は重み選定が効く実例

## フェーズ2: E2E（P0/P1/P2、loftr_outdoor@0.2 と mast3r）

### 予測（2026-08-02、実行直前に記録）

1. **成立性**: 両マッチャーとも 4〜5/5 カメラで成立（N は桁で余裕、PnP は安定）。リスクは M3 の cam05520129 で見た「解の微振動による K_MAX 内非収束」の再現（停止規則の偽陰性。起きた場合は失敗段を記録）
2. **同一解**: 成立したカメラでは P0/P1/P2 が同一解に収束する（摂動 5cm/2° は M2 収束域の十分内側）
3. **一致性**: 3〜5/5 カメラで p95 閾値内。M3 で FAIL だった cam41520554（二峰）が母数増で解消するかは不確実（解消すれば候補3の追加の価値の証拠になる）
4. **総合**: 少なくとも1マッチャーが PASS ≥3/5 → **M3b は Go** と予測
5. 診断値: RMSE は 1〜3px（SIFT 実測 0.9〜2.7px と同程度か、密マッチの座標量子化でやや高い可能性）

### 実測（2026-08-02。詳細: m3b_result.txt / m3b_history.npz）

- **loftr_outdoor@0.2: PASS 4/5**（126・129・554・557）。唯一の FAIL は cam41520556 の P0 が K_MAX=5 内で非収束（更新量 2.4〜5.9mm・角 0.066〜0.073° の微振動。予測1で挙げた「停止規則の偽陰性」パターンの再現。P1/P2 は収束しており解自体は安定）
- **mast3r: PASS 2/5**（554・557）。FAIL 3カメラ（126・129・556）はすべて**成立・一致は満たすが同一解判定のみ僅差で不合格**（最大ペア間 0.55〜0.73cm / 0.106〜0.197°。閾値 1cm/0.1° の角度側を僅かに超過）
- **M3 で FAIL だった cam41520554（二峰）が両マッチャーで PASS**（予測3の不確実要素が良い方向に解消。母数増が二峰問題を解消した実例）
- **M3 で偽陰性だった cam05520129 も LoFTR で PASS**（k=4 で収束）
- MASt3R の特徴的挙動: k=1 以降で更新量 0.00mm・RMSE 0.000px に固定される。解釈: subsample=8 グリッド+512解像度（原寸換算の量子 3.75px）の座標量子化により、整列後は u_q≒u_r の自己充足マッチとなり反復が固定点に達する。同一解判定の僅差不合格（系列間 ばらつき）も同じ量子化で説明がつく
- **M3b 総合判定（criteria §6.2）: Go**（loftr_outdoor@0.2 が PASS ≥3/5）

### 照合

- 予測4（**Go**）的中。予測2（成立カメラでの同一解）は LoFTR で的中、MASt3R では外れ（量子化起因の僅差超過という新知見）
- 予測1（成立 4〜5/5）: LoFTR 4/5 で的中（非収束1件のパターンまで予測どおり）。MASt3R は成立自体は 5/5
- 予測3（一致性 3〜5/5）: LoFTR 4/5・MASt3R 5/5 で的中。554 の二峰解消は「候補3の追加価値」の証拠として記録
- 予測5（RMSE 1〜3px）: LoFTR 収束時 1.1〜1.3px で的中。MASt3R の 0.000px は予測外（上記の量子化解釈）

### M3b の主要知見（檻適用に向けて）

1. マッチ母数は SIFT 比 20〜30倍（LoFTR）/ 7〜9倍（MASt3R）。ratio 律速の解消は病院シーンで実証された
2. E2E 品質は LoFTR（fine レベルの座標精度）が MASt3R（512+grid の量子化）より上。**檻適用の第一候補は loftr_outdoor**
3. MASt3R は母数・安定性は十分だが、同一解精度が criteria の 0.1° 基準を僅差で割る。檻で LoFTR が枯渇した場合の控えとして有効
4. LoFTR full 解像度は本環境（レンダプロセスと GPU 同居）では OOM → 1280x720 で運用。indoor_new 重みはカメラ依存の不安定性あり（採用外の記録）
