# M1（実験B）結果レポート: 少点数PnPの初期値精度検証

- 実施日: 2026-07-31
- スクリプト: `run_m1_experiment.py`（生データ: `results_trials.csv`、集計: `results_summary.txt`）
- 改訂履歴: 初版は誤ったTOML（`Calib_scene_osaka2.toml`、8係数、出自不明の推定結果とみられる）を内部パラメータとして使用していた。ユーザー指摘により正しいチェスボード較正ファイル `phase0/data/osaka2/intrinsics_all.toml`（5カメラ、5係数 k1,k2,p1,p2,k3）で全面再実行した。本レポートは再実行後の結果のみを記載する

## 実験条件

- データ: osaka2（**対象環境と同一カメラ機種**。対象環境はカメラ8台、osaka2は5台）
- 内部パラメータ: `phase0/data/osaka2/intrinsics_all.toml`（チェスボード較正済み、ユーザー指定）
- PnP実装: `phase0/estimate_camera_params.py` の `estimate_extrinsic` をそのまま使用（実運用と同一。6点以上=solvePnPRansac(閾値8px)+ITERATIVE精密化、4〜5点=SQPnPのみ）
- 全点PnPを基準ポーズとし、n0 ∈ {4,5,6,8,10} 点をランダム抽出したPnPとの差（カメラ中心距離・回転角）を各1000試行（seed=42）
- 判定基準: pipeline.md §4.2(b-1) の収束域 = 位置数cm・角度数度（<5cm&2°、<10cm&5° の2段で集計）

## 結果要約

| カメラ | 対応点数 | 外れ値率(基準RANSAC, 8px) | n0=5: <10cm&5° | n0=6: <10cm&5° | n0=6 明示的失敗 |
|---|---|---|---|---|---|
| cam05520126 | 30 | 5/30 (17%) | 92.2% | **96.3%** | 5/1000 |
| cam05520129 | 22 | 5/22 (23%) | 88.0% | 89.1% | 26/1000 |
| cam41520556 | 22 | 4/22 (18%) | 94.1% | **95.5%** | 13/1000 |
| cam41520554 | 17 | 8/17 (**47%**) | 25.0% | 42.9% | **746/1000** |
| cam41520557 | 36 | 16/36 (**44%**) | 37.7% | 28.2% | 315/1000 |

代表値（良好カメラ cam05520126、n0=6）: 位置差 中央値3.9cm / p95 9.6cm / 最大23.9cm、角度差 中央値0.55° / p95 1.2° / 最大3.2°。

n0=5 は RANSAC なしのため稀に破滅的な引きがある（cam41520556: 最大297cm。n0=6 では最大19cm）。n0=4 は全カメラで最大数mの破滅的な引きがあり不可。

## 解釈

1. **プロット品質が良ければ（外れ値率 ≦20%強）、5〜6点PnPは約9割以上の確率で収束域（<10cm&5°）に入る**。パイプライン Stage 1 の前提は成立し得る
2. **成績は点数ではなくプロット品質で決まる**。外れ値率44〜47%のカメラは n0=10 に増やしても収束域到達 34〜50% に留まる。良好カメラと不良カメラの差は歴然で、n0 の選択より「慎重にプロットする」ことが支配的
3. **既存の手動プロットデータの外れ値率は 17〜47% と高い**（8px閾値、5カメラ全てで17%以上）。「外れ値なし前提」は自然には満たされない。ただし本実験の母集団は「20〜36点を一括プロットしたデータ」であり、5〜6点だけを慎重にプロットする運用では品質を上げられる余地がある
4. **n0=6（RANSAC有効）は n0=5（SQPnPのみ）より安全**。良好データでは裾（最大値）が大幅に縮み、不良データでは「静かに悪いポーズを返す」代わりに明示的失敗が返る（cam41520554 で 746/1000 失敗）。**明示的失敗率はプロット品質の検出器としても機能する**——実運用で6点PnPが失敗したら、それはプロットやり直しのシグナル
5. 基準ポーズ自体が同じ手動データ由来であり真値ではない。特に外れ値率44〜47%のカメラでは基準ポーズの信頼性も低く、そこでの「差」の解釈には限界がある

## G1 判定への材料

- **条件付き Go を推奨**。条件は「プロット品質の担保」:
  - 手動プロットは **6点を標準**とする（5点は許容下限、4点は不可）。6点なら RANSAC が動き、品質不良が明示的失敗として現れる
  - 6点PnPが失敗（solvePnPRansac 失敗）した場合はプロットをやり直す運用を Stage 1 のフォールバックに明記する
- 外れ値率の高さ（17〜47%）は、pipeline.md の下流検出（Stage 4 の N<30、最終受理条件）が保険として必須であることを裏付ける
- pipeline.md の n0 記述（5〜6）は「**6点推奨・5点許容**」に更新する価値がある

## 制約・留保

- 代理データ（osaka2）による結果であり、対象環境（檻・壁際カメラ）の点配置制約は反映されていない
- 基準ポーズは真値ではない（全点解との相対差）
- 外れ値率はRANSAC閾値8pxでの判定であり、真のクリックミス率とは厳密には一致しない

## 仕様への注記

- 較正済みTOML（intrinsics_all.toml）の歪み係数は **5係数 (k1,k2,p1,p2,k3)** だった。pipeline.md は4係数限定（それ以外は入口エラー）としているため、**対象環境（檻）の較正が5係数で出力される場合は Stage 0 が弾いてしまう**。檻環境の較正出力が4係数か5係数かの確認が必要（5係数なら pipeline.md の対象を4/5係数に広げる小修正で対応可能。`distortions_to_gsplat` は5係数対応済み）

## 補遺（2026-07-31、実験後のレビューで判明した問題）

本レポートの「G1 判定への材料」「解釈」の各項は、次の理由により**判定としては不成立**であり、参考情報に格下げする:

1. **判定閾値（<5cm&2°、<10cm&5°）は実証されていない**。これは pipeline.md §4.2(b-1) の一つの故障モードから、未実測の仮定値（部屋の寸法・格子ピッチ・ゲート幅）で机上逆算した推測値である。パイプライン全体の実際の収束域（初期ポーズをどこまで離しても真値に収束するか）は未知であり、その実測は案1実験（`../a1_synthetic/`）以降で行う
2. **合格ライン（試行の何%が閾値内なら合格か）を事前に定義しないまま実験を実行した**。「条件付きGo」の推奨は事後解釈であり、撤回する
3. 「RANSAC が効く」「外れ値率17〜47%」の記述は、既存実装の再投影誤差8px閾値に対する点同士の不整合の観測であり、真のクリックミスの特定ではない。初期値に要求される精度基準がない現状では、これらの解釈に判定上の意味はない

**基準によらず残る実測事実**は以下の3点のみ:
- 抽出PnPと全点PnPの差の分布（`results_trials.csv` の実測値そのもの）
- 分布はカメラ間で大きく異なる（位置差中央値 3cm台〜13cm台）
- n0=4 では最大数百cmの引きが起きる

**G1 判定は保留**。収束域が実測で決まった後（案1以降）、本データと照合して判定をやり直す。
