### 照合: 予測は大きく外れた（乖離の記録と解釈）

- p95 は M1 参考値の約 **1/4**（±50% 予測を大幅に下回る縮小）。さらに M1 で「劣化データ」だった cam41520554/557 が他と同水準になった
- 外れ値（8px 基準）の激減: cam41520557 は 16/36（44%）→ **0/36**、cam41520554 は 8/17（47%）→ 3/17（18%）
- **解釈（実測から言える範囲）**: M1 の高い外れ値率は **intrinsics_all 条件下の系統的再投影誤差を大きく含んでおり、手動点そのものの品質指標として使うのは誤りだった**。Config_scene 条件では不整合が大幅に解消する（0〜18%）。系統誤差の由来（Config_scene の K・歪みがこれらの手動点と整合的に推定されている可能性が高い）は状況証拠であり、Config_scene の生成過程の資料では確認していない
- 教訓: 外れ値率・分布は「どの K・歪みの下での値か」を明示しないと品質指標として比較できない（findings.md §1.8 の注記対象）
- **criteria への影響**:
  1. §5.3 の閾値を実測 p95 で確定（当初案より約4倍厳しい物差しになる。物差しの論理は不変: 「基準ポーズの自己ばらつきと不可分なら一致」）
  2. §3 の層別根拠（M1 外れ値率による低信頼カメラ除外）が崩れた。Config_scene の下では全5カメラの点データが整合的（外れ値率 0〜18%）なので、判定対象を5カメラに拡大する（**M3 本実験の実行前・lock 前の改訂**であり、結果を見た事後変更ではない）
  3. §5.4 の inlier 名簿は M1 版でなく M3-0a 版（Config_scene の下での名簿）を使う

### cam05520129 振動の原因分析（2026-07-31）

- 実測: 振動した cam05520129（P0/P2）・cam41520554（P2）は k≥1（RANSAC 2px）のインライア率が 47〜63% と低く、収束したカメラ（70〜82%）と明確に分かれる。cam05520129 はゲート後 N=309〜346 と最多なのに約4割が「ゲート10pxは通るが2pxに整合しない」準誤マッチ
- メカニズム: 準誤マッチが多いと、RANSAC のインライア選択と反復ごとのマッチ集合入れ替わりで解のジッタ（実測 5〜13mm/0.1〜0.3°）が収束判定 ε（5mm/0.05°）を恒常的に上回る。解自体は基準近傍（差 0.26cm）に留まる＝**精度でなくジッタ振幅>εの問題**。P1 の収束（更新量 0.95mm）はジッタ分布の小さい側を引いた運
- **状況証拠（ユーザー情報、2026-07-31）**: cam05520129 の視野にはブラインドがあり画面の約1/4を占める。合成実験（findings §1.4）の「周期構造による準誤マッチ」仮説と整合する。**ただしこれは原因の確定ではない**（訂正: 当初「原因の確定」と記載したのは早計だった）。準誤マッチが実際にブラインド領域に空間集中しているかは未確認であり、別要因（当該視点のレンダ品質劣化、シーン全体のドメインギャップ等）も排除できていない
- 原因確定に必要な検証: 下記「診断D1」として実施（2026-07-31 ユーザー実施判断）

## 診断D1: cam05520129 準誤マッチの発生源特定（2026-07-31）

- スクリプト: `m3_diag_quasi.py`（Codex レビュー収束後に実行）
- 対象: cam05520129（P0 収束解ポーズ）。対照: cam41520557（同条件で高インライア率だったカメラ）
- 方法: P0 最終解のポーズで反復1回分（k≥1 条件: ゲート10px・RANSAC 2px）を再現し、ゲート通過マッチを「インライア」と「準誤マッチ（RANSAC外れ）」に分類。以下を測定・出力する
  1. **空間集中度**: 画像を 8×8=64 セルに分割し、準誤マッチ数の上位16セル（面積25%）に入る準誤マッチの割合 f_sp を測る
  2. **周期性署名**: 準誤マッチの変位ベクトル d=u_q−u_r の2Dヒストグラム（1pxビン）で、最頻ビン±1px に入る割合 f_per と、そのピーク変位量 |d_peak| を測る（周期構造の誤マッチは「格子ピッチ分ずれた一貫した変位」を示すはず。ランダムなドメインギャップ起因なら変位方向は等方に散る）
  3. **可視化**: 実写画像にインライア（緑）・準誤マッチ（赤）を重畳した PNG を出力し、集中領域がブラインドと一致するかを**ユーザーが目視確認**する（矩形指定が困難なため、領域指定の代わりに事後の目視確認とする。斜めのブラインドにも対応）
- **判定基準（実行前に定義。診断用の目安であり lock 級ではない）**:
  - **ブラインド（周期構造）起因を支持**: f_sp ≥ 50%（面積比25%の2倍）かつ f_per ≥ 25% かつ |d_peak| ≥ 2px、かつ目視で集中領域がブラインドと一致
  - **視野全体のドメインギャップ起因を支持**: f_sp が 25% 近傍（面積比並み）または f_per < 25%（変位が等方散乱）
  - 対照カメラ cam41520557 では f_sp・f_per とも 129 より明確に低いことを予測（そうでなければ「129 固有」の前提を疑う）
- **予測（実行前に記録）**: cam05520129 は f_sp 50%超・f_per 25%超・|d_peak| 2〜10px（ブラインドのピッチ相当）。cam41520557 は f_sp 40%未満・f_per 15%未満

### 収束判定 ε の妥当性検討（M3 実測の更新量から。新実験なし）

- 現行 ε（5mm/0.05°）は M2 合成条件で決めた値。合成でのジッタ床は 0.2mm 程度で ε に対し余裕25倍だった
- 実写での更新量の下げ止まり（ジッタ床）は 5〜13mm/0.07〜0.27°（cam05520129 P0）で、**ε がジッタ床より下にある**
- 機械的検算: ε を2倍（10mm/0.1°）にすると、M3 の**不成立6系列（129 P0/P2/P4・554 P2・556 P4・557 P4）は全て記録済みの反復内で収束判定を満たす**（各系列の更新量列から確認）
- ただし付随する事実: 129 の P0/P1/P2 の最終解は基準ポーズから 0.26/1.35/0.83cm とばらついており、ジッタは停止判定だけでなく**解そのものの再現性（同一解判定 1cm/0.1°）にも同じスケールで現れる**。ε の緩和は「成立性」を変えるが、ジッタの存在自体は他の診断値に残る

## 追加確認2: 内部パラメータの真値と数px不整合の在り処（2026-07-31）

- ユーザー情報: cam05520129 のチェスボード較正の再投影誤差は **0.2339px**（較正ファイルには誤差メタデータの記録なし。旧 Calib_scene_osaka2.toml には error=0.2753/0.5452 の形式で2カメラ分のみ記録があり、129 は含まれない）
- 手動対応点（22点）の再投影誤差の実測（cam05520129）:
  - a) intrinsics_all（チェスボード較正）の K/D + 全点PnP再フィット: 中央値 4.48px / RMSE 7.82px
  - b) Config_scene の K/D + 記載ポーズ: 中央値 2.48px / RMSE 3.27px
  - c) Config_scene の K/D + 全点PnP再フィット: b と**完全一致** → Config_scene の記載ポーズは、その K/D の下での全点 PnP 解そのもの
- 帰結: 内部パラメータは 0.23px 級で正確なので、**数px の不整合の在り処は手動2D点・3D基準点座標の側**。Config_scene の K（チェスボード値から fx +50px ≈ 4%）はその誤差を吸収した値とみられる
- ただし **K ミスマッチは 129 の非収束を説明しない**: Δfx は5カメラ共通（+47〜+120px）で、129（+50px）は小さい方から2番目。最大の cam41520557（+120px）は問題なく収束している

## 原因調査の結論（2026-07-31）

- **確定（非収束の直接原因）**: 更新量ベースの停止規則 ε=5mm/0.05°（M2 合成のジッタ床 0.2mm を基準に設定）が、**実写のジッタ床 5〜13mm/0.07〜0.27° より下にある**こと。解自体は基準ポーズの 0.26cm 以内に到達しており、故障の実態は「正しい解を認定できない偽陰性」
- 傍証: 129 の系列別の収束/非収束（P1・P3 ○ / P0・P2・P4 ×）は初期値の優劣と無関係（20cm 摂動の P3 が2反復で収束し、無摂動の P0 が非収束）。ε をまたぐジッタ下では収束判定がくじ引きになる、という機構と整合
- ジッタの機構: 反復ごとの (1) マッチ集合の入れ替わり、(2) RANSAC の抽選、(3) 準誤マッチ（2〜10px帯、実写で25〜40%）のどの部分集合が混入するかの変動、により解が毎回少し違う場所に着地する
- **未特定のまま保留**: 「129（と 554 の P2）の準誤マッチ率がなぜ他より高いか」。D1 でブラインド周期構造は不支持、K ミスマッチ単独犯もカメラ間比較で棄却。細い構造の深度不連続・レンダ品質等は仮説のまま。ジッタ源の低減は品質改善項目として保留リスト扱い（解は正しく求まっているため成立性のブロッカーではない）

## 方針決定: M3-1 サンプリング型停止判定の検証（2026-07-31 ユーザー承認）

- 方式: 停止判定（更新量<ε）を廃し、ゲート引き締め後に**固定 N 回反復して解をサンプリング**。解空間は6次元（位置3 + 基準解周りの so(3) 接空間3）。サンプル群から**頑健に中心を推定**（外れ値に引っ張られない合意クラスタ/幾何中央値ベース。単純平均・成分中央値は外れ値耐性がないため不採用=ユーザー指摘）し、**散らばり（分布の形）を診断値**とする。多峰性（RANSAC が2解釈を行き来）はそれ自体を検出対象とする
- 限界の明示: サンプリングで定量化できるのは精度（ばらつき）であり、正確度（系統的偏り）は測れない
- 失敗時の次策（事前に定義）: F1 分布が広すぎる → ロバスト重み付き最終推定（Huber/trf。RANSAC の二値選択を連続重みに置換しジッタの主機構を除去）/ F2 多峰 → 原因領域のマスク・学習ベースマッチャー（M3b）/ F3 中心の偏り → K・歪みの見直し（intrinsics_all でのレンダ再生成比較）・3DGS 改善 / F4 サンプル相関 → 複数チェーン並列。最終防衛線は roadmap の分岐（M3b → 3DGS 再撮影 → 手法棄却）
- 次の作業: M3-1 criteria 改訂案（N・クラスタ半径・受理閾値・偽陽性チェックを既存データから根拠付きで実行前に定義）→ Codex レビュー → 検証実験
- **M4 への含意（仮説段階）**: ブラインド起因が確定すれば、檻の格子（roadmap (b-3)、周期構造としてより過酷）で同じ故障モードが主リスクになる見込み。対策候補（M5 設計論点）: 周期構造領域のマスク、ロバスト損失、学習ベースマッチャー（M3b）、ジッタを考慮した収束判定（最終K回の平均解・解分散判定）
