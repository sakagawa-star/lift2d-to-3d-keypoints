## 1. 実験の問い（roadmap.md M3 から再掲）

クエリを実写に置き換えたとき、(1) マッチング・反復は成立するか、(2) 品質はどれだけ劣化するか、(3) oracle なしの診断値（N・RMSE・退化診断・摂動検算）は「基準ポーズとの一致・自己整合性」の代替指標として機能するか。

**測れるものの限界**: M3 に真値はない。判定はすべて「既存20点方式との一致」「自己整合性」「手動測量座標系との整合」であり、実品質（真値との差）ではない。

## 5. 判定基準（数値固定）

### 5.1 成立性（カメラごと）

無摂動系列（初期値=Config_scene の基準ポーズそのもの）で、以下を**すべて**満たせば成立:

1. 全反復でゲート後 N_in ≥ 30
2. k_max=5 以内に収束判定（Δc ≤ 5mm かつ Δθ ≤ 0.05°）を満たす

- 根拠: いずれも M2 で機能実証済みの値。実写での劣化度合いの測定が M3 の目的なので、閾値は M2 から動かさない
- 失敗時は失敗段（マッチ数 / ゲート / PnP / 発散）を記録する（silent failure でないことの確認を含む）

### 5.2 摂動検算（同一解収束と実写収束域）

各カメラで初期値を変えた5系列を実行する（摂動は M2 の `perturb_pose` と同方式・seed 固定）:

| 系列 | 摂動 | seed | 用途 |
|---|---|---|---|
| P0 | なし（基準ポーズ） | — | 成立性判定（§5.1）・一致性判定（§5.3）の主系列 |
| P1, P2 | 5cm / 2° | 11, 12 | 同一解判定（M2 収束域の十分内側） |
| P3 | 20cm / 5° | 13 | 実写での収束域縮小の観測（情報系列） |
| P4 | 50cm / 10° | 14 | 同上（M2 収束域の境界） |

- **同一解判定**: **P0・P1・P2 の3系列すべてが成立し**、かつ3系列の解の間で最大ペア間カメラ中心距離 ≤ 1cm かつ最大ペア間角度差 ≤ 0.1° なら「同一解」。**1系列でも失敗したら §5.2 は不合格**（成立した系列だけで判定して検算を骨抜きにしない）
  - 根拠: 1cm/0.1° は収束判定 ε（Δc ≤ 5mm・Δθ ≤ 0.05°、§4）のちょうど2倍。各系列は ε で停止するため、独立に収束した2解は ε 程度の分解能でしか比較できず、2ε 以内なら「同一解」とするのが分解能限界に即した判定。合成での収束床 0.01〜0.18mm / ≤0.003°（M2 実測）に対しては50倍以上のマージン。かつ §5.3 の一致閾値（p95 ≈ 1.8〜2.6cm / 0.35〜0.46°）より小さく、判定として機能する
- P3・P4 の失敗は M3 全体の合否に**数えない**（実写での収束域の実測データとして記録する）

### 5.3 一致性（20点方式ポーズとの差）

P0 の解と基準ポーズの差（カメラ中心距離・回転角）が、**そのカメラの「Config_scene の K・歪みで再計測した n0=10 再サンプリング分布の p95」**以内なら「一致」。

- **確定済み閾値（M3-0a 実測、2026-07-31 数値確定）**:

| カメラ | 位置差閾値 | 角度差閾値 |
|---|---|---|
| cam05520126 | 2.55 cm | 0.35° |
| cam05520129 | 2.29 cm | 0.46° |
| cam41520554 | 1.84 cm | 0.39° |
| cam41520556 | 2.05 cm | 0.44° |
| cam41520557 | 2.40 cm | 0.41° |

- 導出の記録: スクリプト `m3_0a_resample_p95.py`（codex-24〜25 レビュー収束後に実行）、n0=10・1000試行・seed=42（numpy 抽出と cv2.setRNGSeed の両方）、OpenCV 4.13.0 / NumPy 2.2.6。結果ファイル `m3_0a_results_summary.txt` / `m3_0a_results_trials.csv`、経緯は `experiment_log.md`
- 経緯: 初版は M1 公表値（intrinsics_all 版: 位置 7.5〜22cm・角度 0.98〜4.8°）の流用を予定していたが、M3 が使う Config_scene の K・歪みでの再計測（codex-22 指摘）の結果、p95 は約1/4に縮小した。M1 の広い分布は intrinsics_all 条件下の系統的再投影誤差を大きく含んでいた（`experiment_log.md` の照合参照）。閾値は再計測値で確定する
- 根拠: n0=10 の p95 は「同じ手動データの部分集合を選び直しただけで基準ポーズがどれだけ動くか」の実測。リファイン解との差がこの範囲なら、20点方式の自己ばらつきと区別がつかない＝「一致」と言える。これを超えたら「不一致」だが、**どちらが悪いかはこの物差しでは決められない**（§5.4 と目視で切り分ける）
- 注意: 基準ポーズは真値ではない。「一致」は正しさの証明ではなく「既存手法と統計的に不可分」の意味

### 5.4 手動点再投影整合（記録・切り分け材料。**Go/No-Go には使わない**）

- **独立検証データの確保可否（roadmap M3 の宣言に対する回答）**: **確保できない**。利用可能な手動2D-3D対応点は Config_scene.toml（基準ポーズ）の生成に使用済みとみられ、未使用点の存在を証明できない。また PLY の座標系も同じ手動データに由来する。したがって roadmap の分岐に従い、**M4/M7 の結論は「診断値ベースの運用受理」に限定する**（実品質の評価とは主張しない）。検証専用の追加手動プロット点を新規作成すれば独立化できるが、ユーザーの手動作業が必要なため、実施の要否は lock 承認時のユーザー判断に委ねる（実施する場合は本節を独立検証に格上げして再lock）
- 本節の指標は「独立検証」ではなく**手動点再投影整合**（パイプラインが参照しないデータとの整合の記録）である。基準ポーズはこれらの点に最適化されているため、この比較はリファイン解に**不利な保守的比較**であることに注意（リファイン解が真に良くても悪化に見え得る）
- **誤差の定義式**: 手動3D点を「評価対象ポーズ + Config_scene の K・歪み係数」で `cv2.projectPoints` し、手動2D点との距離の**中央値**を取る（外れ値の混入があり得るため平均は使わない）。全点中央値と、**M3-0a の基準ポーズ inlier 名簿**（`m3_0a_results_summary.txt` 記載。Config_scene の K・歪みの下での名簿）上の中央値の両方を記録する
- **記録**: inlier 名簿上の中央値について、（P0 の解での値）と（基準ポーズでの値）を比較し、悪化の有無と程度を記録する。悪化した場合は §6 の合否には影響させず、原因切り分け（PLY 座標系のずれ / リファイン不良 / 手動点の品質）の材料とする

### 5.5 診断値の記録と暫定警告閾値（合否に使わない。M4 受理条件の較正材料）

| 診断値 | 記録内容 | 暫定警告閾値 | 根拠 |
|---|---|---|---|
| 収束時 RMSE | 全系列・全反復 | > 2.0 px で警告 | 合成ノイズ床 0.244px・準誤マッチ混入時 1.56px（M2 実測）。2px は k≥1 の RANSAC 閾値＝インライア定義と整合 |
| 退化診断 λ3/λ1 | 全反復 | < 0.09 で警告 | M2 健全実測値 0.269 の 1/3 |
| 深度レンジ | 全反復 | < 1.4 m で警告 | M2 健全実測値 4.2m の 1/3 |
| 凸包面積比 | 全反復 | < 0.22 で警告 | M2 健全実測値 0.675 の 1/3 |

- 警告は記録のみで合否に使わない（閾値の較正こそが M3 の目的(3)。M3 の結果で「診断値と §5.3/§5.4 の一致・整合の相関」を検証し、M4 の受理条件を較正する）
- 1/3 という係数は「健全値から明確に離れた」ことの仮の目印であり、実測による較正対象であることを明記する

### 5.6 マッチャー切替（SIFT 不成立の判定と、別ブランチ化）

- **判定条件**: 判定対象5カメラのいずれかで、P0 系列が「k=0 のゲート後 N_in < 30」または「k_max=5 で収束せず」となったら、そのカメラで SIFT 不成立
- **本 criteria の Go/No-Go は SIFT の結果のみで判定する（§6）**。学習ベースマッチャーでの再試行は M3 の合否に**一切数えない**。マッチャー切替を行う場合は別ブランチ「**M3b**」とし、**実施前に M3b の criteria lock（マッチャー名・バージョン・入力・閾値・集計方法を固定した本書同等の文書）を作成してから**評価する（実験後に合否を動かす余地を残さない）
- M3b の候補と制約（参考情報）:
  - LoFTR 系: ライセンス確認の上、実験用に導入
  - MASt3R 系: **CC BY-NC-SA（非商用限定）**のため、商用利用可否を選定条件に含める
  - 依存導入は実験用に留める（正式導入・TECH_STACK 更新は M5）
- 5カメラすべて SIFT 成立なら M3b は行わない

## 6. M3 全体の Go / No-Go（実行前に固定。**SIFT baseline のみで判定**）

- **Go**: 判定対象5カメラ中 **3カメラ以上**（過半数）が「成立性（§5.1）+ 同一解（§5.2）+ 一致（§5.3）」をすべて満たす
- **No-Go**: 上記未満 → roadmap.md の切り分けフロー（レンダ品質 / マッチャー限界の切り分け → 3DGS 再撮影 / マッチャー変更（M3b、§5.6）/ 手法棄却）へ
- §5.4（手動点再投影整合）と §5.5（診断値）は合否に使わない（記録・切り分け・較正材料）
- 根拠: 過半数（3/5）成立なら手法の力学は実写でも機能していると言える。不成立カメラは個別要因（視点・シーン被覆・データ品質）の切り分けに回す。全数成立を Go 条件にすると、個別カメラの要因で手法自体を棄却する誤判定が起きる
