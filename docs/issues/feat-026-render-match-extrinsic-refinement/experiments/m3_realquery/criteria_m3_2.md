- 位置づけ: criteria_m3_1（locked）の検証で判明した検査の穴——**チェーン内は単峰でもチェーン間で解が割れる二峰性（cam41520554 で実測: 2つの安定解が 1.80cm/0.49° 離れて再現）を検出できない**——を塞ぐ改訂。M3-1 の判定（No-Go）は変更しない
- 目的との関係: 受理判定の役割は「怪しい外部パラメータを黙って渡さないこと」。不受理カメラは切り捨てではなく「再プロット・個別対応が必要」と運用者に明示する対象である

## 1. 方式（チェーン統合型合意判定）

- サンプリング手順・チェーン数は M3-1 と同一（初期値3系統: 無摂動 + 5cm/2° 摂動2系統、各チェーン k=0 → k≥1 で N_s=20 回サンプリング）
- 変更点: 合意クラスタ分析を**チェーンごとではなく、カメラごとに3チェーンの全 60 サンプルを統合（pooled）して行う**
  - クラスタ半径は M3-1 と同一: r_pos=2.0cm / r_ang=0.30°
  - **受理条件: pooled 占有率 f_c ≥ 0.7（= 60サンプル中42以上）**。根拠: M3-1 と同じ比率。3チェーン中1チェーン（20/60 ≈ 0.33）が別の場所に定着した場合、最大でも f_c ≈ 0.67 < 0.7 となり**構成上必ず不受理になる**（チェーン間二峰の検出がこの閾値設定の狙い）
  - 最終解 = pooled クラスタ内サンプルの平均（M3-1 と同じ anchor 相対の回転ベクトル平均）
  - 第2クラスタ占有率 ≥ 0.2 なら「二峰」と分類（不受理理由の運用者向け表示に使う）
- チェーンのいずれかがゲート等で明示的失敗した場合は従来どおりカメラごと明示的失敗

## 2. 検証方法（新規レンダ不要）

M3-1 で保存済みのサンプル（`m3_1_history.npz`。各系列20サンプルの全ポーズ）に対する**再分析のみ**で検証する（サンプリング自体は M3-1 と同一手順なので再実行不要。決定的な再計算）。

## 3. 判定基準（実行前固定）

以下を**すべて**満たせば M3-2 は Go（チェーン統合型を M5 設計入力として採用）:

1. **554 の検出**: cam41520554 が pooled f_c < 0.7 で**不受理**となり、第2クラスタ占有率 ≥ 0.2 の「二峰」として分類される
2. **他4カメラの受理**: cam05520126 / cam05520129 / cam41520556 / cam41520557 が pooled f_c ≥ 0.7 で受理され、**かつ第2クラスタ占有率 < 0.2**（強い副モードの禁止。M3-1 の単峰性基準と整合）、最終解が各カメラの基準ポーズと §5.3 p95 以内、かつ M3-1 の各チェーン中心解と r_pos/r_ang（2cm/0.3°）以内
3. **負対照**: M3-1 の負対照結果（k=0 明示的失敗）が本方式でも不受理のまま（統合の対象になるサンプルが存在しないため自明だが、判定として明記）

- 予測（数値）は実行直前に `experiment_log.md` に記録する
