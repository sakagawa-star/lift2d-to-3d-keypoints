## 1. 実験の問い

学習ベースマッチャーは檻シーン（パイロットカメラ cam05520125）で:

1. M4 の律速だった ratio 段の枯渇（生 ~4300 → ratio後 97〜109）を解消し、深度除外（変位通過分の 60〜75%）が残る前提でも**ゲート後 N ≥ 30 を3チェーンすべてで供給**するか（フェーズ1）
2. M4 と同一手順（6点PnP 初期値 + サンプリング型リファイン + チェーン統合合意）が **M4 と同一の判定基準で成立・受理**されるか（フェーズ2）

### フェーズ1: マッチング段のオフライン比較（3チェーン初期ポーズ × 9設定）

- 3チェーン（A=6点PnP解、B/C=+5cm/2° seed 11/12）それぞれの k=0 ペアに対し、9設定の段別内訳（生 → 変位後 → 深度系後 N。除外内訳つき）を記録し、§3.1 の SIFT 表と並記する（CSV 保存）
- **フェーズ2 進出条件（LoFTR）**: 少なくとも1設定で**3チェーンすべて N ≥ 30**（M4 §6.1 の成立性要求に対応）
- **採用設定の選択規則（事前固定・一意）**: 進出条件を満たす LoFTR 設定のうち (1) 3チェーンの N の最小値が最大 → (2) 同点なら N の3チェーン合計が大きい方 → (3) 同点なら confidence 閾値が高い方 → (4) なお同点なら indoor_new 優先（M3b の規則の3チェーン版）
- MASt3R も9設定の一部として**フェーズ1 は必ず記録**する（E2E に進むかはフェーズ3 の条件による）

### フェーズ2: E2E（M4 手順の完全再実行。マッチャー = フェーズ1 採用の LoFTR 設定）

- M4 criteria §5 と同一: 6点PnP 初期値 → 3チェーン各（k=0 → k≥1 条件で N_S=20 サンプリング）→ 60サンプル pooled クラスタ分析 → 受理判定
- 判定は **M4 criteria と同一**: 成立性（§6.1: 3チェーン k=0 成立 + 60サンプル収集 + silent failure なし）、受理（§6.2: 単峰高合意 f_c≥0.7 or 数値固定条件の仲裁二峰）、前提条件（§6.4: 6点PnP 初期解と最終解の差 ≤ 50cm/10°）

### フェーズ3（条件付き）: MASt3R での E2E 再試行

- **実施条件は §5 冒頭の遷移表に従う**（LoFTR 先行・不成立時のみ MASt3R。ユーザー確定仕様）: フェーズ1 で LoFTR 不適格かつ MASt3R 適格、またはフェーズ2 で LoFTR 未達かつ MASt3R 適格の場合のみ実施

- 実施時は MASt3R（1設定）でフェーズ2 と同一の E2E・同一判定

## 6. 判定基準（数値固定）

### 6.1 M4-2 全体の Go / No-Go

- **Go**: いずれかのマッチャーで「M4 §6.1 成立性 + §6.2 受理 + §6.4 前提条件」をすべて満たす（= M4 §7 の Go 定義をマッチャー差し替えで達成）→ 檻シーンの回復経路として候補3 が確定。M5（本実装設計）のマッチャー選定材料になる
- **No-Go**: LoFTR・MASt3R とも未達 → 候補3 は檻で不成立。残る経路（ゲート・リフトのアルゴリズム変更、候補4/5）の再評価へ（`survey_lattice_problem.md` §5）
- 判定に使わないもの: (b-1)〜(b-4)・診断値・実行時間・フェーズ0(c) 再現性記録

### 6.2 M3/M3b への回帰チェックについて

- **実施しない**。根拠: 本実験は檻データに対する新規実験であり、M3（SIFT）・M3b（病院）の入力・コード・判定に影響を与えない（m4_run 系のスクリプトは m3 系を import するのみで変更しない）。マッチャー差し替えの病院シーンでの妥当性は M3b で判定済み
