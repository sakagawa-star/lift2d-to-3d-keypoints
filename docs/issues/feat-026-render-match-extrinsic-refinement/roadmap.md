## M1: 実験B — 少点数 PnP の初期値精度検証

**このマイルストーンが答える問い**: (1) 5〜6 点 PnP は収束域（位置 数 cm・角度 数度）に入るか。(2) そもそもリファイン段は必要か。

- 内容: 既存の 20 点超対応データで、全点 PnP を基準ポーズとし、5〜6 点ランダム抽出 PnP との差（位置・角度）の分布を多数回測る（pipeline.md §5 実験 B）
- 必要なもの: 既存データ・既存スクリプトのみ。**新規実装ゼロ**（抽出と統計の使い捨てスクリプトのみ）
- 成果物: 差の分布（位置 [cm]・角度 [度]）、檻内/檻外など点配置による違いの観察

**ゲート G1**:
- **Go**: 分布の大部分が収束域内 → M2 へ
- **スコープ縮小**: 分布が phase4 用途で無視できるほど小さい → **リファイン不要と判定し、feat-026 を「プロット 5〜6 点への削減」のみに縮小**（M2〜M5 を飛ばして M6 へ。開発コスト最小で完了）
- **No-Go 側の対処**: 分布が収束域を大きく外れる → 手動点数を増やす（6〜8 点）か点配置の選び方の運用ルールで改善できるかを再検証。改善不能なら初期化方式の再設計（アイディア出しに戻る）

## M2: 実験A-1 — ドメインギャップ検証（本手法最大のリスクの直接測定）

**このマイルストーンが答える問い**: 実写 ↔ 3DGS レンダリングで特徴マッチングが成立するか（pipeline.md §4.2(b-4)。檻の外・壁際という学習視点から遠い可能性のあるカメラ位置で、レンダ品質が保てているか）。

- 内容: 既存の手動 20 点方式で推定済みのポーズを使い、`render_image(distort=True, return_depth=True)` で 1 枚レンダリング。実写 1 枚とのマッチ数・分布（檻領域/非檻領域）を測る
- 必要なもの: phase4 環境（実装済み関数の流用）＋まず SIFT（OpenCV、追加依存なし）
- 成果物: レンダ画像と実写の並置・重畳画像、SIFT でのマッチ数と分布
- 備考: SIFT で不足でも即 No-Go ではない（学習ベースマッチャーは M3 で試す）。ここでの主目的は**レンダ品質の目視確認**と難易度の見積り

**ゲート G2**:
- **Go**: レンダ品質が実写と対応付け可能な水準（構造物が視認でき、大きな欠損・破綻がない）→ M3 へ
- **No-Go**: レンダが外挿破綻している（壁際視点で品質崩壊）→ **本手法は不成立として棄却**。代替: (a) 3DGS の再撮影・再構築（実カメラ位置付近の視点を撮影経路に含める）、(b) COLMAP 系フォールバック（pipeline.md §2.2）、(c) 現行手法の改善（feat-026 を M1 の結果次第でプロット削減のみに縮小）

## M3: マッチャー選定と環境構築

**このマイルストーンが答える問い**: どのマッチャー（SIFT / LoFTR / MASt3R）が本環境で最良か。新規依存をどの環境に導入するか。

- 内容:
  - M2 の画像ペアで SIFT / LoFTR / MASt3R のマッチ数・誤対応率・分布を比較
  - 依存導入の検証: LoFTR/MASt3R は PyTorch 系。phase4 の torch 環境（cu128、`TORCH_CUDA_ARCH_LIST` 制約あり）に同居できるか、別環境が要るかを確認
  - ライセンス確認（MASt3R は CC BY-NC-SA 4.0 = **非商用限定**。本件の用途が商用に当たる場合は LoFTR 等の商用可ライセンスに限定する必要あり——選定の重要な制約条件）
- 成果物: マッチャー比較表（マッチ数・分布・実行時間・依存・ライセンス）、選定結論、環境構築手順メモ
- 備考: この時点の環境構築は実験用。正式な依存追加（TECH_STACK.md 更新）は M6/M7 で行う

**ゲート G3**:
- **Go**: いずれかのマッチャーで非檻領域に十分なマッチ（目安: フィルタ前で百点級）が取れ、ライセンス・環境の制約を満たす → M4 へ
- **No-Go**: 全マッチャーで不足 → G2 と同じ代替分岐へ

## M4: 実験A-2 — 摂動回復の end-to-end 検証（プロトタイプ）

**このマイルストーンが答える問い**: パイプライン全体（Stage 2〜7）が既知摂動から正しいポーズへ収束するか。silent failure（誤対応コンセンサス）は起きないか。

- 内容: Stage 2〜7 の簡易実装（プロトタイプ）を作り、推定済みポーズ＋既知摂動（位置 ±3〜10 cm、角度 ±2〜5 度）から回復するかを測る（pipeline.md §5 実験 A-2）
- 必要なもの: M3 で選定したマッチャー環境。Stage 4 のゲート・Stage 5 の lift・Stage 6 の PnP は数式 1 本ずつの使い捨て実装
- 成果物: 摂動ケースごとの回復量（Δθ・Δτ）、インライア率、RMSE、退化診断値、反復回数
- 備考: **このプロトタイプが本実装（M7）の設計の実測根拠になる**（閾値 τ_* の較正値、反復回数の実態、失敗モードの観察）

**ゲート G4**:
- **Go**: 全摂動ケースで元ポーズ近傍（目安: 位置 1 cm・角度 0.1 度以内）へ収束 → M5 へ
- **条件付き Go**: 一部ケースのみ失敗 → 失敗条件（摂動の大きさ・方向）を特定し、初期値要求を厳しくする（M1 の結果と突き合わせて手動点数・配置ルールを調整）ことで回避可能なら Go
- **No-Go**: 広範に発散・偽解収束 → ゲート設計の見直し（pipeline.md の Stage 4/6 再設計）に戻る。改善不能なら棄却

## M5: 実験C — 深度マップ品質検証

**このマイルストーンが答える問い**: 3DGS 深度から逆算した 3D 座標の誤差 δd は誤差収支（pipeline.md §4.1）の想定内か。

- 内容: 手動プロット済みの既知 3D 基準点について、レンダ深度から Stage 5 の式で逆算した 3D 座標と手動 3D 座標の差を測る。外れ値率（α 低画素・シルエット画素）も観測
- 必要なもの: M4 のプロトタイプ＋既存の基準点データ
- 成果物: δd の実測分布、外れ値率、τ_α・τ_d・z_near/z_far の較正値
- 備考: M4 が通っていれば実質的に確認作業（M4 の成功自体が深度の実用性の証拠）。順序を M4 の前に入れ替えてもよい

**ゲート G5**:
- **Go**: δd が誤差収支の想定内 → M6 へ
- **No-Go**: 深度が広範に信頼不能 → COLMAP 三角測量フォールバック（pipeline.md §2.2 の留保）へ Stage 5 を差し替える再設計

## リスクと分岐の要約

| リスク | 検出場所 | 対処 |
|---|---|---|
| 5〜6 点 PnP が収束域に入らない | M1/G1 | 点数・配置ルール調整、初期化再設計 |
| リファイン不要と判明 | M1/G1 | スコープ縮小（プロット削減のみで完了。最良の結末の一つ） |
| レンダ品質の外挿破綻（最大リスク） | M2/G2 | 3DGS 再撮影 / COLMAP 系 / スコープ縮小 |
| 全マッチャーでマッチ不足 | M3/G3 | 同上 |
| マッチャーのライセンス制約（MASt3R 非商用） | M3/G3 | 商用可マッチャーに限定して選定 |
| torch 環境の依存衝突 | M3/G3 | 別 uv 環境の新設（phase0/phase4 と同様の独立管理） |
| 偽解収束（silent failure） | M4/G4 | ゲート再設計、初期値要求の厳格化 |
| 深度の信頼性不足 | M5/G5 | COLMAP 三角測量フォールバックへ差し替え |

## 進め方の原則

- M1〜M5 は「安いものから、かつ致命的リスクを早く」の順（M1: コストゼロ → M2: 最大リスクの直接測定）
- 各実験の結果は案件フォルダに記録し（`experiments/` サブフォルダ等）、M6 のドキュメントから参照する
- M6 以降は CLAUDE.md の機能追加フローを厳守（実験フェーズの使い捨てコードは本実装に流用しない。設計書から書き直す）
