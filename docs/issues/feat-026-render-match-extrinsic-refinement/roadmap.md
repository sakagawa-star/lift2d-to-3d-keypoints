## v1 からの改訂理由

1. **判定基準の欠陥**: v1 の G1 は「収束域（位置数cm・角度数度）」という未実証の閾値と未定義の合格ラインに依存していた。「分かっていないこと（収束域）」を分かっている前提で書いていた
2. **実際の進行との乖離**: 収束域を実測するための「案1（完全合成検証）」は v1 に存在しないまま実施され、旧 M4（摂動回復E2E）・旧 M5（深度品質）の大部分を合成条件で先取りした
3. **新要素の欠落**: Stage 1.5（粗整列）、角度摂動の定義と方向依存性、「判定基準を実験前に定義する」プロセス自体が v1 になかった

## 原則（全マイルストーン共通）

- 各マイルストーンは「**答える問い**」「**実行前に数値で定義する判定基準**」「**予測→実行→照合の記録先**」を持つ。**基準が未知の場合は"基準を測ること自体"をそのマイルストーンのゴールにする**（未知を既知のように扱わない）
- 実験・実装は「各ステップ直前に予測を立て、実行し、照合する」方式で進める（乖離が出たらその段を疑う）
- 実装（実験スクリプト含む）は Codex レビューを重要度「高・中」ゼロに収束させてから実行する
- 設計拡張（Stage 1.5 等）は候補として実験で実証してから正式化する（正式化の判断は requirements/design 段階）

## M1: 少点数PnP差分布の実測 — 【完了】

- **問い**: 5〜6点PnPは全点PnPからどれだけずれるか（分布の実測。**合否判定はしない**——判定に使える収束域が当時未知だったため。v1 の「G1 判定」は撤回済み、`experiments/m1/report.md` 補遺参照）
- **結果**: 代理環境 osaka2（対象環境と同一カメラ機種）5カメラ・各1000試行。良好データ（点間不整合率 ≤23%）で中央値 3〜5cm/1°未満、劣化データ（44〜47%）で中央値 9〜13cm/2°超。n0=4 は破滅的（最大数百cm）
- **この数字の使い道**: M4 の総合判定で、M2/M3 の実測収束域と突き合わせる

## M2: 案1 合成条件でのパイプライン実証 — 【完了】

- **問い**: (1) パイプラインの力学（Stage 2〜7）は成立するか、(2) 収束域（未知X）はどこまでか、(3) silent failure は起きるか
- **条件**: 阪大病院シーン（PLY・204万ガウシアン）、クエリ=真ポーズからの合成レンダ（ドメインギャップゼロ）、SIFT
- **結果**（詳細: `experiments/a1_synthetic/experiment_log.md`、蒸留: `findings.md`）:
  - 力学成立: 反復2回で 5cm/2° → **0.17mm/0.0027°**（RMSE はSIFTノイズ床 0.24px に到達）。段階的引き締めの必要性と効果を定量実証
  - 収束域: **首振り型の角度のみが律速**（≤10° は位置50cmでも成功、≥20° はゲート全滅）。粗整列（Stage 1.5 候補）で**角度30°・位置50cmまで拡張**（レスキュー10/10）
  - silent failure: 35ケース（マップ25+レスキュー10）で**ゼロ**。失敗は全て明示的
  - 深度リフト精度 0.24px（旧M5「深度品質」の合成条件分を吸収）、摂動回復（旧M4）も吸収
- **限界（M3以降に持ち越し）**: 摂動方向固定・単一シーン・ドメインギャップゼロ。oracle 採点（真値既知の全マッチ採点）は実写では使えない

## M3: ドメインギャップ検証（実写クエリ）— 【完了: 本実験 Go + 補足検証（M3-1/M3-2/D2/D3）完了】

- **本実験（2026-07-31、詳細: `experiments/m3_realquery/`）**: criteria lock（codex-22〜28 収束・ユーザー承認）の下で実施し **Go（PASS 3/5）**。実写でもパイプラインの力学は成立（P0 収束 4/5、収束時 RMSE 0.90〜1.24px、20cm/5° 摂動から回復、silent failure なし）
- **判明した設計課題と解決**: 実写のジッタ床（5〜13mm）が収束判定 ε（5mm、合成基準）を上回る停止規則の偽陰性（cam05520129）→ **サンプリング型停止判定**へ改訂。チェーン単位判定（M3-1）はチェーン間二峰（cam41520554、2解が1.77cm離れて再現）を見逃すため No-Go → **チェーン統合型合意判定（M3-2）で Go**（554 を「二峰」として検出、他4カメラ受理）
- **二峰の解明と仲裁（D2/D3）**: 554 の二峰は「ほぼ交わらないマッチ部分集合（Jaccard 0.10）が残差互角の解を支える」構図。手動点再投影による仲裁（差1.36px ≥ 事前閾値1.0px）で **A モードを採用**。運用フロー「サンプリング→統合合意→受理/二峰は手動点仲裁」が確立（M5 設計入力。詳細: findings.md §1.10）
- 以下は実施前の計画（記録として保持）:

- **問い**: クエリを実写に置き換えたとき、(1) マッチング・反復は成立するか、(2) 品質はどれだけ劣化するか、(3) oracle なしの診断値（N・RMSE・退化診断・摂動検算）は「基準ポーズとの一致・自己整合性」の代替指標として機能するか
- **測れるものの限界（明示）**: M3 に真値はない。20点方式の推定ポーズとの差・ホールドアウト再投影・レンダ重畳の目視は、いずれも「既存基準との一致」と「自己整合性」であり、実品質（真値との差）そのものではない。従って M3 で較正する受理条件が保証するのは「既存20点方式との整合性」まで。独立検証データ（下記）が確保できた場合に限り、実品質相関の検証に格上げする
- **独立検証データの確保（criteria lock 時に可否を確定）**: 候補は (a) Config_scene.toml の生成に使っていないホールドアウト2D-3D対応点、(b) 検証専用に追加する手動プロット点。確保できない場合、M4/M7 の結論は「精度を評価できる」ではなく「**診断値ベースの運用受理に限る**」と明記する
- **条件**: 阪大病院シーンは **PLY・推定ポーズ（Config_scene.toml）・実写画像（phase0/data/osaka2/images/）が揃っており、手動作業ゼロ**で実施可能。カメラ5台分を独立に試せる
- **M3-0: criteria lock（実験実行前の必須ステップ）**: M2 実測値から数値を導出し、`experiments/m3_realquery/criteria.md` に**固定してから**実験を開始する。lock 後の変更は理由を記録して再lock する（実験結果を見てからのなし崩しの変更は禁止）。固定する項目:
  - 成立性: ゲート後 N_in の閾値・収束判定 Δτ の閾値・最大反復数
  - 一致性: 20点方式ポーズとの差の閾値（M1 の差分布を物差しに導出）、複数初期摂動からの同一解判定の閾値と摂動セット
  - 診断値: RMSE の受理閾値、退化診断（λ3/λ1・深度レンジ・凸包比）の暫定閾値（M2 健全ケースの実測値を起点）
  - ホールドアウト誤差（実施する場合）: 誤差の定義式と閾値
  - マッチャー切替: SIFT 不成立の判定条件と、LoFTR / MASt3R 系への切替手順（旧M3 のマッチャー選定を統合。**MASt3R は CC BY-NC-SA=非商用限定**のライセンス制約を選定条件に含める。依存導入は実験用に留め、正式導入は M5 で TECH_STACK 更新）
  - 記録先: `experiments/m3_realquery/experiment_log.md`（予測→実行→照合）
- **No-Go 時**: レンダ品質・マッチャー限界の切り分け→ 3DGS 再撮影 / マッチャー変更 / 手法棄却の分岐（v1 の G2/G3 の分岐を継承）

## M4: 対象環境（檻）パイロット — 【パイロット実施済み: baseline No-Go（2026-08-01）。次の分岐はユーザー判断待ち】

- **実施結果（2026-08-01、詳細: `experiments/m4_cage/`）**: criteria lock（codex-42〜44 収束・ユーザー承認）の下でパイロットカメラ cam05520125 の baseline を実施し **No-Go（成立性不成立）**。3チェーンとも k=0 で「ゲート生存 N=14〜26 < 30」の明示的失敗（silent failure なし）
- **Stage 0（疎通）は良好**: 6点PnP 成功（inlier 5/6、手動点再投影中央値 2.23px）、レンダ有効画素率 1.000、SIFT数比 1.05〜1.20、重畳目視で座標系整列良好 → レンダ品質 (b-4) に問題なし＝「3DGS 再撮影」分岐の根拠なし。なお初回実行は手動3D点2点（可動構造物上）のプロットミスで6点PnPが明示的失敗し、固定4点PnP+leave-one-out で切り分けてユーザーがデータ修正した（実測: 固定点は K・2D・3D が 1.6〜4.4px で整合）
- **失敗モード（(b-2)(b-3) の実測が特定）**: ①ratio 律速のマッチ枯渇——生候補 ~4300 → ratio後 97〜109（M3 実写 258〜446 の 1/3〜1/4。格子・金網の周期構造で記述子が曖昧化）、②深度系ゲートが変位通過分の 60〜75% を除外——NaN/2×2広がり 40〜55% + 分散 20〜27%（細線構造のシルエット・格子越し背景。M2/M3 の連続面シーンで較正されたゲートが細線シーンでは通過点を残さない）。首振り誤差ではないため Stage 1.5 は適用対象外（レスキュー実行せず）
- **次の分岐（ユーザー判断待ち）**: 対処候補はマッチ枯渇側（マッチャー変更等）と深度除外側（ゲート定数の近接シーン再較正等）の2系統。いずれも実施する場合は別実験として criteria lock してから（M4 の No-Go 判定は不変）
- **M4-1（深度ゲート定数の近接シーン再較正、候補1）実施済み: フェーズ1 で No-Go（2026-08-02。criteria_m4_1.md locked・codex-52〜55 収束）**。12組グリッド（広がり5〜20% × 分散2〜8%）に適格組（3チェーン N≥30）なし。実測が確定させた事実: ①真NaN除外は0件（除外の実体は全量「広がり超過」）、②広がり緩和は分散ゲートに全量再捕捉される（var固定で spread を4倍にしても N が1件も動かない冗長関係）、③分散緩和のみ N を動かすが最大緩和でも B=24<30 で飽和。**除外点は較正ミスマッチではなく真の深度不連続（細線・格子のシルエット跨ぎ）であり、定数再較正では回復しない**。残る回復経路はマッチ母数の増加（候補3: マッチャー変更）またはゲートのアルゴリズム変更（詳細: `experiments/m4_cage/experiment_log.md` M4-1 節、`m4_1_sweep_table.csv`）
- **先行研究・製品調査と対処候補の評価（2026-08-02）は `survey_lattice_problem.md` に記録**: XGRIDS（LCC Studio/PortalCam）の解は LiDAR 融合でありマッチング問題を回避している（移植不可）。要因①の標準解は学習ベースマッチャー（LoFTR/MASt3R。GS-CPR 採用実績）、要因②のアルゴリズム側参照は UGS-Loc（不確実性重み付け）。MASt3R のライセンス（CC BY-NC-SA）は本プロジェクト（大学研究・非商用）では障害なし。評価の結論: **候補3（マッチャー変更）が本命**（実施判断はユーザー待ち）
