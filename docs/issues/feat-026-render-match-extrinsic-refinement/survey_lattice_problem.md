# 調査記録: 格子状檻問題の先行研究・対処候補の評価（2026-08-02）

M4 baseline No-Go（findings §1.11）を受けて実施した文献・製品調査と、対処候補の評価の記録。
調査の経緯: ユーザーの指摘「格子状の構造物は日常に一般的に存在するので先行研究があるはず」
「商用ソフト（XGRIDS LCC Studio）は同じ檻環境で 3DGS 再構成に成功している」から出発した。

## 1. 前提事実（ユーザー提供）

- 檻の 3DGS 再構成には **XGRIDS 社の LCC Studio** を使用しており、撮影機材は同社の
  **PortalCam**。つまり檻環境の 3DGS 化は商用ソフトで成立済み
- 本プロジェクトの目的は**大学の研究（てんかん患者の観察。映像 2〜3 日分から 3D キーポイント生成）**で、
  利益が発生する要素はない → **非商用ライセンスのモデル・コードを使用可能**（§4）

## 2. 調査(a): XGRIDS 関係者の公開文献

### 製品側の結論: 檻問題は「解いた」のではなく「センサーで回避」している

- LCC Studio（Lixel CyberColor）は同社独自の **Multi-SLAM（LiDAR+カメラ+慣性の融合）**で、
  カメラポーズと形状を LiDAR 側から得て 3DGS を学習する構成
- PortalCam は 96ch LiDAR（85万点/秒）+ 12MP×4 カメラの LiDAR 中心機材
- → 檻シーンでの「画像特徴マッチング」問題はそもそも発生しない。**我々（実写 vs レンダの
  単一ペアマッチング）にはこの解は移植できない**
- ただし「シーンが本質的に不可能」の悲観シナリオは棄却できる: 出来上がった PLY は
  細線構造を再現できており、M4 の (b-4) 実測（有効画素率 1.000、SIFT数比 1.05〜1.20）とも整合

### 学術論文側: XGRIDS 創業者兼CEO Kaiyong Zhao 氏の論文群

所属 "XGRIDS, Shenzhen, China" は CF-NeRF の著者欄で確認。一貫した思想は
「**疎な記述子マッチング＋ratio test を使わず、密な（画素単位の）整合で解く**」:

| 論文 | 内容 | 我々への関連 |
|---|---|---|
| CF-NeRF (AAAI 2024, arXiv:2312.08760) | カメラパラメータなしの増分 NeRF 再構成。ポーズ回復は測光整合 | 疎マッチング回避の思想 |
| RA-NeRF (arXiv:2506.15242, 2025) | 複雑軌道下のポーズ推定。測光整合+光フロー駆動のポーズ正則化 | 同上（ratio test 不使用） |
| VoxelMap++ (2023) | LiDAR オドメトリ | 製品の LiDAR 系譜の確認 |
| EASNet (2022) / SphereDepth 系 | 密ステレオ・パノラマ深度 | 密深度推定の系譜 |

- **檻・格子・細線問題を直接扱った論文は同グループには存在しない**（調査時点）

## 3. 調査(b): 周辺研究

### 要因①（ratio 律速のマッチ枯渇）への先行解 → 候補3の裏付け

- **LoFTR**（CVPR 2021, arXiv:2104.00680）: detector-free（特徴点検出も ratio test もなし）。
  Transformer の大域文脈で局所記述子の曖昧さを解消し、**繰り返しパターン・低テクスチャでの
  対応取得を明示的な設計目標**とする。ライセンス Apache 2.0
- **MASt3R**（ECCV 2024）: LoFTR 系をさらに上回る性能報告。**先行研究 GS-CPR が採用している
  マッチャーそのもの**（我々の SIFT は依存追加回避のための簡略化だった）
- 檻の ratio 枯渇（生候補の 97.5% が落ちる）は、疎マッチャー固有の既知の弱点が
  最悪条件で顕在化したものであり、学習ベースマッチャーは標準解

### 要因②（深度不連続点の除外）への先行解

- **UGS-Loc**（arXiv:2603.16538「Rethinking Pose Refinement in 3D Gaussian Splatting under
  Pose Prior and Geometric Uncertainty」）: レンダ深度の信頼性は一様でないという同じ問題意識に対し、
  Fisher 情報で**画素単位の深度信頼度マップ**を作り、二値ゲートで捨てる代わりに
  **PnP の対応点サンプリングを信頼度で重み付け**する。M4-1 の実測（除外点は真の深度不連続で、
  定数緩和では救えない——findings §1.12）を踏まえると、ゲートの**アルゴリズム変更**side の
  参照実装として最有力
- 細線構造（フェンス・電線・格子）は 3DGS でも既知の難物（DET-GS 等の深度・エッジ考慮の
  正則化研究が継続中）。「image de-fencing」という研究系譜が存在する程度に一般的な問題

### 第3系統（参考。現候補リスト外）

- **GSLoc**（arXiv:2410.06165）: マッチング自体を使わず、レンダリング勾配の逆伝播で
  レンダ画像と実写を直接位置合わせする密整合方式（coarse-to-fine + ぼかしカーネルで非凸性緩和）。
  XGRIDS CEO の論文群と同じ思想系統。疎マッチングの枯渇も深度ゲートも構造的に発生しない

## 5. 対処候補の評価（2026-08-02。M4-1 No-Go 反映後）

M4 の段別実測: 生候補 ~4300 → ratio後 97〜109 → 変位後 66〜78 → 深度系後 14〜26（必要 30）

| 候補 | 内容 | 評価 |
|---|---|---|
| 候補1 | 深度ゲート定数の近接シーン再較正 | **実施済み・No-Go（M4-1、findings §1.12）**。除外点は真の深度不連続であり定数では回復しない。この選択肢は消えた |
| 候補2 | ROI 指定（ユーザー発案） | 未着手。マッチ母数をさらに減らす方向のため単独では成立性に寄与しにくい |
| 候補3 | マッチャー変更（LoFTR / MASt3R） | **本命**。律速段（ratio）を直接解消し、母数増で深度除外率も数で吸収できる唯一の候補。GS-CPR の実績・文献の裏付けあり。事前確認事項: (i) phase4 torch 環境への依存追加と gtune2 CUDA 制約（sm_120/JIT）との干渉、(ii) 実写 vs レンダのドメインギャップ実測 |
| 候補4 | リファインなし運用の評価 | 保留 |
| 候補5 | 人工ランドマーク+再スキャン | 保留 |
| （新規参考） | ゲート/リフトのアルゴリズム変更（UGS-Loc 型の不確実性重み付け、有効画素のみ補間） | M4-1 の含意から浮上。候補3 で母数が増えても檻領域の点を活用したい場合の発展形 |

- 根拠の詳細（数字・理由3点）: 候補3 が律速段を攻撃する唯一の候補であること、証拠の質
  （GS-CPR 同構図での MASt3R 実績）、SIFT が元々先行研究からの簡略化だったこと
- **次の実施判断はユーザー預かり**。実施する場合は確立フロー（criteria 作成 → Codex 収束 →
  ユーザー承認 lock → スクリプト → 予測 → 実行 → 照合）に従う
