# feat-026 検証フェーズの知見まとめ

- 最終更新: 2026-07-31（M3 実写クエリ検証・原因調査完了時点）
- 位置づけ: 実験で**実証された事実**と**未検証のまま残っている事項**を分離して記録する。時系列の詳細は `experiments/a1_synthetic/experiment_log.md`、M1 は `experiments/m1/report.md` を参照

## 1. 実証された事実（合成条件下）

実験条件: HandaiHospital シーン（3DGS PLY、204万ガウシアン）、cam05520126 の較正値（f≈1218、5係数）、クエリ=真ポーズからの合成レンダ（ドメインギャップゼロ）、摂動 5cm/2°、マッチャー=SIFT。

### 1.1 パイプラインの力学は一巡成立する

Stage 2（レンダ）→ 3（マッチング）→ 4（ゲート）→ 5（深度3D化）→ 6（PnP）の一巡で、**初期ポーズ誤差 5cm/2° が 1.61mm/0.0295° に縮小**（31倍/68倍）。誤差伝播式からの事前予測（≤5mm・≤0.05°）の範囲内。

### 1.2 レンダリングは完全に決定的

同一入力の2回レンダは画素・深度・αすべて**完全一致**（差0）。実験の比較基盤として成立。

### 1.3 深度リフトの正確性

正しいマッチについて、深度で3D化→真ポーズ再投影の残差は**中央値 0.24px**。深度マップ（α正規化期待深度）+ undistortPoints + 逆投影の式（pipeline.md Stage 5）は正確に機能する。ただしシルエット・深度不連続の除外（bilinear 補間 + 2×2近傍の広がり5%ゲート）が前提。

### 1.4 周期構造は「ドメインギャップゼロでも」誤マッチを作る

- SIFT 生マッチ 1370件中、誤マッチ（正解から5px超）15.7%。ブラインド等の繰り返し模様が主因
- うち 2〜8px の「準誤マッチ」は RANSAC 閾値 8px（既存実装の値）をすり抜け、**インライアの 8.6% に混入**、RMSE を 0.24px 級 → 1.56px に押し上げた
- それでもポーズ誤差が予測内に収まったのは、準誤マッチの誤差方向がランダムで平均化されたため（系統的に偏れば解が引っ張られる。silent failure の現実的経路として要警戒）
- **含意**: pipeline.md の段階的引き締め（k≥1 で τ_px・RANSAC 閾値を絞る）とロバスト損失は、推測ではなく実測に基づく必要機構。実写（ドメインギャップあり）ではこの数字は悪化する前提で見る

### 1.5 ゲートの動作実績（記録値）

N=1370 → 生存1049（平坦性ゲート1059・変位ゲート1348・有効性ゲート1315 の AND）。退化診断の実測: λ3/λ1=0.269、深度レンジ4.20m、凸包面積比0.675（健全な点配置の参考値。閾値較正の材料）。

### 1.6 反復収束と到達精度（Stage 7）

- 段階的引き締め（k≥1: τ_px 250→10px、RANSAC 8→2px）で純度 91.4%→**100%**、RMSE 1.56→**0.244px**（=SIFTのノイズ床）。「準誤マッチ混入は8px閾値が原因」の説明を実証
- 反復2回の到達精度: **0.17mm / 0.0027°**。収束判定（カメラ中心差ベース）も設計通り機能

### 1.7 収束域の実測（未知Xへの最初の答え。方向固定・単一シーン・合成条件）

- 摂動グリッド25ケース（位置5〜50cm × 角度2〜30°）で、**境界は角度のみで決まる**: 角度≤10°は位置50cmでも全て成功、角度≥20°は位置5cmでも全て失敗
- 機構: 回転による画像変位 f·Δθ は**深度非依存**で全マッチが一様にずれ、20°で425px > τ_px^(0)=250px となり全滅（N≤2の明示的失敗）。並進の変位 f·B/Z は**深度依存**のため中遠距離マッチが生き残り、50cmでも成立
- **silent failure はゼロ**（25ケース中）。失敗は全て明示的
- 成功ケースは初期値の大きさによらず 0.01〜0.18mm の同じ床に収束（不動点の性質）
- 含意: M1実測の5〜6点PnP初期誤差（良好データで数cm・数度）は収束域に対して余裕十分。角度境界はゲート定数が律速なので、必要なら τ_px^(0) のスケーリングで拡張可能（誤マッチ混入とのトレードオフ）
- 限界: 摂動方向固定（seed=1）・単一シーン・ドメインギャップゼロでの結果。一般化には方向軸・実写での検証が必要

### 1.8 M1（実運用データでの少点数PnP分布、代理環境 osaka2）

- 5〜6点PnPと全点PnPの差: 良好データで中央値3〜5cm・1°未満、劣化データで中央値9〜13cm・2°超（カメラ間の差が大きい）
- n0=4 は最大数百cmの破滅的な引きがある
- ※判定基準（収束域）が未確定のため、これは**分布の実測**であり合否判定ではない（`experiments/m1/report.md` 補遺）
- **注記（2026-07-31、M3-0a の照合で判明）**: M1 の数値はすべて **intrinsics_all.toml（チェスボード較正）の K・歪みの下での値**である。同じ点データを Config_scene.toml の K・歪みで再計測すると、外れ値率は 0〜18% に収まり、n0=10 の p95 は全5カメラで位置 1.8〜2.6cm・角度 0.35〜0.46° に引き締まる（M1 値の約1/4）。M1 の高外れ値率（44〜47%）は intrinsics_all 条件下の系統的再投影誤差を大きく含んでおり、**手動点そのものの品質指標として使うのは誤りだった**。「劣化データ」「良好データ」のカメラ層別も同様に成立しない。外れ値率・分布は「どの K・歪みの下での値か」を明示しないと比較できない（`experiments/m3_realquery/experiment_log.md` M3-0a 参照）

### 1.9 M3: 実写クエリでの実測（ドメインギャップ。2026-07-31、詳細: `experiments/m3_realquery/`）

- **成立性**: criteria lock（判定基準の実験前固定）の下で **Go（PASS 3/5）**。P0（無摂動）は5カメラ中4で収束。生マッチ 258〜446件（合成の1370件から減るが十分）、収束時 RMSE 0.90〜1.24px（合成床 0.244px の4〜5倍）。20cm/5° 摂動（P3）も全カメラ成立。silent failure なし
- **実写のジッタ床は 5〜13mm/0.07〜0.27°**（合成 0.2mm の25〜65倍）。反復ごとのマッチ入れ替わり・RANSAC 抽選・準誤マッチ（実写で25〜40%）の混入変動が原因。**更新量ベースの停止判定 ε=5mm/0.05°（合成基準）はこのジッタ床より下**にあり、原理的に偽陰性を出す——cam05520129 で顕在化（解は基準ポーズ 0.26cm 以内に到達しているのに「収束せず」。収束/非収束が系列ごとのくじ引きになる）
- **K・歪み誤差の許容値は設計に未定義**だった（M2 はレンダとクエリの K/D 完全一致でのみ収束を実証）。実測では Config_scene の K はチェスボード較正値（129 の較正誤差 0.2339px）から fx +47〜+120px ずれており、手動点は最良でも中央値 2.5px でしか整合しない＝**数px 不整合の在り処は手動2D/3D データ側**。ただし K ミスマッチは5カメラ共通で、129 固有の準誤マッチ率の高さ（37〜39% vs 収束カメラ 18〜30%）は説明できない（発生源は未特定。ブラインド周期構造は診断D1 で不支持）
- **対処方針（M3-1 で検証）**: 停止判定をサンプリング型に改訂——固定 N 回反復して解（6次元: 位置3+so(3)3）を収集し、頑健な中心推定を最終解、散らばり・多峰性を診断値とする。単純平均・成分中央値は外れ値耐性がないため不採用

## 2. 実装上の確定知見

- **gsplat 1.5.3 の 3DGUT 経路（with_ut/with_eval3d）は render_mode="RGB+ED" 非対応**（channels==3 アサーション）。歪み付き深度は「z_i を色として流しαで正規化」の2パス方式（方式A）で取得する。実装例 `render_depth_alpha_distorted`（codex-08〜10 レビュー済み）
- 深度のサブピクセル参照は **bilinear 補間必須**（floor 参照はシルエットで oracle/リフトを壊す）。2×2近傍に NaN・深度広がり5%超があれば判定不能として除外
- 深度分散ゲートの分散計算は**有効画素（α・z範囲・有限）のみ**で行う（無効画素混入で判定が変わる）
- phase4 環境に scipy はない（ロバスト非線形最小二乗の本実装時は依存追加が必要。TECH_STACK 更新対象）
- SIFT は信頼度スコアを持たないため、ゲート(i)は比率テストで代替（学習ベースマッチャー導入時に有効化）

## 3. プロセス上の知見

- **「各ステップ直前に予測→実行→照合」方式は実際に欠陥を捕まえた**: (a) pipeline.md の「distort+depth 併用は実装済み」という誤断定（コードの見た目からの推測）を疎通確認が初回で検出、(b) 予測と実測の乖離（純度・RMSE）が原因特定（8px閾値と周期構造）まで一直線に進んだ
- 真値既知の合成実験では**正解変位場（oracle）による全マッチの採点**が可能で、マッチャー・ゲート・PnP の各段を定量評価できる。この採点機構は実写実験では使えない（真値がないため）——実写での品質推定は診断値（インライア数・RMSE・退化診断・摂動検算）に頼ることになる
- Codex レビューは実験スクリプトにも有効（floor 深度参照・分散計算の有効画素・失敗時クラッシュ等、実測を歪める欠陥を実行前に検出）

## 3.5 設計拡張候補: 初期ポーズ検証・粗整列段（Stage 1.5、検証実験中）

背景（ユーザーの経験則 + 実験データの整合、2026-07-31）:
- 経験則: 手動6点が画像内にまんべんなく取れれば首振り型の大角度誤差は出ないが、点が一箇所（例: 左上）に集中すると、その側へ首振り型で大きく角度がずれる
- 理屈: PnP は使った点の再投影しか拘束しないため、点群が偏ると「点群側の当てはまりを保ったまま残りの画角を振る」回転自由度が残る（てこの原理。M1 の点配置劣化・退化診断の条件3と同じ現象）
- 収束域マップの実測: 首振り型（角度）誤差こそがパイプラインを殺す唯一のモード（位置は50cmでも耐える）。かつ失敗の直接原因は変位ゲートによる全滅であり、SIFT の生マッチ自体は平行移動不変性により大角度でも取れている可能性が高い

提案（Stage 1 と Stage 2 の間に挿入する候補）:
1. 初期ポーズでレンダし、実画像との生マッチ（変位ゲートなし）を取る
2. マッチした光線ペアから**回転のみの整列**（Kabsch/SVD、トリミング付き）で首振りずれ Δθ を直接推定
3. 用途3段階: (a) Δθ が大きければ「初期ポーズ不良=点の偏りを疑え」と警告（検証）、(b) τ_px^(0) を Δθ に応じてスケール（適応）、(c) 回転を粗補正してから反復に入る（粗整列。角度収束域の拡張）

検証実験の結果（2026-07-31）: 収束域マップの失敗10ケース（位置5〜50cm × 角度20°/30°）を**10/10 全て救済**（`coarse_align_rescue.py`、codex-18〜19 レビュー済み）。

- 生マッチは30°でも244〜468件取れており「失敗はマッチングでなくゲート律速」を裏付け
- 回転のみ整列は位置ずれの視差を回転として吸収するため、補正後の残存角度誤差は B に比例して増える（0.85°@5cm→7.3°@50cm）。ただし全ケースで収束域（<10〜20°）内に収まり、続く反復が 0.2mm 床まで収束させた
- 位置づけ: 粗整列は「厳密な補正」ではなく**「収束域に投げ込む装置」**。実効収束域は角度≤10°から**角度30°・位置50cm**（実測範囲）へ拡張
- 正式仕様化（pipeline.md Stage 1.5 の候補解除）は requirements/design 段階で判断

## 4. 未検証（これからの実験対象）
