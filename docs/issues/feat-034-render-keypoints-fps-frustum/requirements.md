# feat-034 要求仕様書: render_keypoints.py FPSカメラ視錐台ワイヤフレームの重ね描き

作成日: 2026-08-13
基準: `docs/REQUIREMENTS_STANDARD.md`
入力資料: 2026-08-13 壁打ちヒアリング（オクルージョンあり・K は TOML 取得・奥行きは固定既定値＋オプション〔案a〕・無効フレーム非描画・色はお任せ→マゼンタ・正確さより「大体分かる」ことを優先、が確定済み）

## 1. プロジェクト概要

- **何を作るのか**: `phase4/render_keypoints.py` の動画モード（キーポイント重ね描き）に、FPSカメラ（頭部キーポイント由来の一人称視点カメラ）の視錐台ワイヤフレームをオクルージョン考慮で重ね描きするオプトイン機能（`--fps-frustum`）を追加する
- **なぜ作るのか**: feat-027 の一人称視点動画は、FPSカメラが「どこを向いて・どの範囲を写しているか」を客観視点で検証する手段がない。第三者視点レンダリング上に視錐台を描くことで、向きと画角を目視で大体把握できるようにする（厳密な検証ツールではない）
- **誰が使うのか**: 本プロジェクトの研究者
- **どこで使うのか**: phase4 venv（torch/gsplat/CUDA 必須）。開発・動作確認はローカル機（gtune2、RTX 5060 Ti）で行う。コマンド例に付す `TORCH_CUDA_ARCH_LIST="9.0+PTX"` はローカル機向けの値であり、他環境ではその環境に応じた値を使う（`docs/TECH_STACK.md` 参照）

## 2. 用語定義

機能設計書・コード内でも同じ用語を使う。

| 用語 | 定義 |
|---|---|
| FPSカメラ | 頭部キーポイントから計算する一人称視点カメラ。位置は両目中点（eyes_mid）、向きは `render_fps_video.compute_fps_poses()` が返す回転（feat-027 で確立した正本） |
| 頭部7点 | FPSポーズ計算に使う7マーカー: LEye, REye, LEar, REar, Nose, Head, Neck（`render_fps_video.HEAD_JOINT_NAMES` と同一） |
| 視錐台（frustum） | FPSカメラの視点（頂点）から画像4隅方向へ奥行き d まで伸ばした四角錐。稜線4本＋遠端矩形4辺の計8線分で表すワイヤフレーム |
| 錐台奥行き | 視点から遠端矩形までの、FPSカメラ光軸方向の距離 [m]。可視化上の打ち切り長であり、レンダリング範囲の物理量ではない |
| 観察カメラ | `--camera` で指定する既存の第三者視点カメラ（3DGS背景とキーポイントを描いているカメラ） |
| キャリブ座標 | PLY・TOML と同じ座標系（Z-up・メートル）。NPZ の world 座標と恒等（feat-018/032 で確認済み） |
| c2w_b | Blenderカメラ規約（カメラは −Z を向く）の camera-to-world 4x4 行列。`compute_fps_poses()` の戻り値 |
| 無効フレーム | FPSポーズが計算できないフレーム。頭部7点のいずれかが無効（欠損・NaN・residual<0）、幾何の縮退、回転行列検証失敗のいずれかに該当するフレーム |

## 3. 機能要求一覧

### FR-001: 視錐台ワイヤフレームの重ね描き（オプトイン）

- **機能名**: 視錐台ワイヤフレーム描画
- **概要**: `--fps-frustum` 指定時、動画モードの各フレームに FPSカメラの視錐台ワイヤフレーム（8線分）を重ね描きする
- **入力**: 既存のキーポイント入力（C3D または NPZ。どちらでも動作する）、`--fps-camera`（FR-003）、`--frustum-depth`（FR-004）
- **出力**: 視錐台ワイヤフレームが追加された連番PNG / MP4（既存の出力形式・ファイル名は変更しない）
- **詳細**:
  - 描画するのは次の8線分に限定する: 視点→4隅の稜線4本、遠端矩形の4辺
  - 色はマゼンタ（BGR: 255, 0, 255）、線の太さは既存ボーンと同じ `LINE_THICKNESS`（=2）
  - 描画順は「視錐台 → ボーン → キーポイント点」とし、スケルトンが視錐台の上に乗る
  - 静止画モード（`--no-keypoints`）では使用不可（FR-007）
- **受け入れ基準**: `--fps-frustum --fps-camera <名前>` を付けて実行すると、出力画像にマゼンタの視錐台が描かれる。付けない場合の出力は従来とバイト同一（FR-009）
- **優先度**: Must

### FR-002: FPSカメラポーズの計算（正本の再利用）

- **機能名**: FPSポーズ計算
- **概要**: 各フレームの頭部7点（キャリブ座標）から FPSカメラの c2w_b を計算する。計算は `render_fps_video.compute_fps_poses()` を import して再利用し、複製実装しない
- **入力**: キーポイント入力から抽出した頭部7点の座標（キャリブ座標 [m]）と有効フラグ（フレームごと）
- **出力**: フレームごとの c2w_b（4x4）と有効フラグ
- **詳細**:
  - 頭部7点のうち1点でも無効（入力に値が無い・NaN・C3D residual<0）なフレームは、座標を NaN として `compute_fps_poses()` に渡し、同関数の判定で無効フレームとする
  - 無効フレーム（NaN・縮退・回転行列検証失敗）は視錐台を描画しない。キーポイント・ボーンの描画は従来どおり行う
  - 視点位置は `compute_fps_poses()` が返す並進（eyes_mid）をそのまま使う
- **受け入れ基準**: 頭部7点が全て有効なフレームでは視錐台が描かれ、1点でも NaN のフレームでは描かれないことをユニットテストで確認できる
- **優先度**: Must

### FR-003: FPSカメラの内部パラメータ取得

- **機能名**: FPSカメラの K・解像度取得
- **概要**: 視錐台の開き角（FOV）を決める内部パラメータ K と画像サイズを、キャリブレーションTOML内のカメラから取得する。取得元の TOML ファイルは既定では位置引数 `toml_path` と同じファイルとし、`--fps-toml` で別ファイルを指定できる（2026-08-13 手動テストのヒアリング漏れ指摘により追加。イテレーション1）
- **入力**: `--fps-camera <カメラ名>`（TOML内のカメラ名）、`--fps-toml <パス>`（省略可。FPSカメラを検索する TOML ファイル。省略時は `toml_path` と同じファイル）
- **出力**: fx, fy, cx, cy, width, height
- **詳細**:
  - 画像4隅（ピクセル座標 (0,0), (W,0), (W,H), (0,H)）への光線方向を K から計算し、視錐台の形状は K・解像度に正確に従う
  - `--fps-toml` の形式は `toml_path` と同じ Calib_scene.toml 型とする
  - TOML の歪み係数・外部パラメータは視錐台計算に使用しない（ピンホール。`render_fps_video.py` と同じ扱い）
  - `--fps-camera` の検索先は、`--fps-toml` 指定時はそのファイル、省略時は `toml_path` のファイルとする
  - 指定名が検索先 TOML に存在しない場合は利用可能なカメラ名一覧を表示して終了コード 1 で終了する（既存 `select_camera` と同じメッセージ形式）
  - `--fps-toml` のファイルが存在しない・TOMLとして解釈できない場合は、パスを含むエラーメッセージを表示して終了コード 1 で終了する
  - 観察カメラ（`--camera`）と同名の指定も許容する（エラーにしない）。`--fps-toml` に `toml_path` と同じパスを指定することも許容する
- **受け入れ基準**: 観察カメラと異なる K・解像度を持つカメラを `--fps-camera` に指定したとき、視錐台計算に FPSカメラ側の K・解像度が使われる（観察カメラ側ではない）ことをユニットテストで確認できる。`--fps-toml` で指定した別ファイルのカメラの K・解像度が使われることをユニットテストで確認できる。存在しない名前・存在しないファイルでエラー終了する
- **優先度**: Must

### FR-004: 錐台奥行きの指定

- **機能名**: 錐台奥行きオプション
- **概要**: 視錐台の遠端までの奥行きを `--frustum-depth <float>`（単位 m）で指定できる。省略時の既定値は 0.5
- **入力**: `--frustum-depth <float>`（省略可）
- **出力**: 指定した奥行きの視錐台
- **詳細**:
  - 奥行きは全フレーム共通の固定値とする（人体スケール連動等の自動決定はしない。壁打ちで案a採用済み）
  - 値域は「有限な実数かつ 0 より大きい」に限定する。0 以下・nan・inf・-inf はエラーメッセージを出して終了コード 2 で終了する
- **受け入れ基準**: `--frustum-depth 1.0` で遠端矩形が視点から光軸方向 1.0m の位置に描かれる（頂点座標のユニットテストで確認）。`--frustum-depth 0`・`nan`・`inf` がエラーになる
- **優先度**: Must

### FR-005: オクルージョンの反映

- **機能名**: 視錐台のオクルージョン
- **概要**: 視錐台の8線分に、既存ボーンと同じ部分隠蔽機構（線分をサンプル点に分割し、3DGS深度と比較して可視な区間のみ描く）を適用する
- **入力**: 既存の深度マップ・αマップ（背景レンダリングで取得済みのもの）
- **出力**: 3DGS の手前にある区間のみ描かれた視錐台
- **詳細**:
  - サンプル数・判定ロジック（`compute_visibility` の判定順序、`ALPHA_THRESH`、`--occlusion-margin`、`--near-plane`）は既存ボーンと同一とする
  - `--no-occlusion` 指定時は視錐台もオクルージョンなしで全線分を描く（スケルトンと連動。視錐台だけ独立に切り替えるオプションは設けない）
  - 視点が両目中点（顔面上）にあるため、稜線の根元が頭部の 3DGS に隠れて消えることは許容する（オクルージョンありの帰結として正しい挙動）
- **受け入れ基準**: 深度マップより奥にある線分区間が描かれず、手前の区間が描かれることをユニットテスト（合成深度マップ）で確認できる
- **優先度**: Must

### FR-006: 設定YAML対応

- **機能名**: 設定YAMLキーの追加
- **概要**: feat-033 の設定YAML（`--config`）に以下の4キーを追加する
- **入力**: 設定YAML
- **出力**: CLI 指定と同じ効果
- **詳細**: 追加する設定キー（型変換・優先順位・フラグの true 方向のみ上書きの非対称性は feat-033 と同一ルール）:

| 設定キー | 対応するCLI | 型・書式 |
|---|---|---|
| `fps_frustum` | `--fps-frustum` | `true` または `false`（小文字のみ） |
| `fps_camera` | `--fps-camera` | 文字列 |
| `fps_toml` | `--fps-toml` | 文字列（パス）（イテレーション1 で追加） |
| `frustum_depth` | `--frustum-depth` | float |

- **受け入れ基準**: 4キーを設定YAMLに書くと CLI 指定と同じ動作になり（`fps_toml` は YAML 経由でも別TOML側の K・解像度が視錐台計算に使われる）、CLI 明示指定が YAML を上書きすることをユニットテストで確認できる
- **優先度**: Must

### FR-007: 引数・入力の検証

- **機能名**: 組み合わせ検証と早期エラー
- **概要**: 不正な指定を重い処理（PLY/torch ロード）の前に検出してエラー終了する
- **入力**: 統合後（CLI + 設定YAML）の引数、キーポイント入力のマーカー構成
- **出力**: エラーメッセージと終了コード
- **詳細**: 検出する誤りを以下に限定する:
  1. `--fps-frustum` 指定時に `--fps-camera` 未指定 → 終了コード 2
  2. `--fps-frustum` なしで `--fps-camera`・`--fps-toml`・`--frustum-depth` のいずれかを指定 → 終了コード 2
  3. `--frustum-depth` が 0 以下または非有限（nan / inf / -inf） → 終了コード 2
  4. `--no-keypoints`（静止画モード）と `--fps-frustum` / `--fps-camera` / `--fps-toml` / `--frustum-depth` の併用 → 終了コード 2（既存の禁止オプション検証に追加）
  5. `--fps-camera` の名前が検索先 TOML（`--fps-toml` 指定時はそのファイル、省略時は `toml_path`）に存在しない → 終了コード 1（FR-003）
  5b. `--fps-toml` のファイルが存在しない・TOMLとして解釈できない → 終了コード 1（FR-003）
  6. **`--fps-frustum` 指定時のみ**: キーポイント入力のマーカー構成に頭部7点のいずれかが存在しない → 欠けているマーカー名を列挙したエラーメッセージを出して終了コード 1（全フレームで視錐台が描けず機能が無意味になるため。フレーム単位の NaN 欠損とは区別する）。`--fps-frustum` 未指定時はこのチェックを行わず、頭部マーカーが無い入力も従来どおり描画スキップで許容する（FR-009 の既定動作不変を維持）
- **受け入れ基準**: 上記 1〜6（5b 含む）のそれぞれがユニットテストで該当の終了コード・メッセージになることを確認できる
- **優先度**: Must

### FR-008: 実行サマリの表示

- **機能名**: 視錐台描画サマリ
- **概要**: `--fps-frustum` 指定時、実行時の設定と描画結果の件数を標準出力に表示する
- **入力**: なし（実行結果から集計）
- **出力**: 標準出力への表示
- **詳細**:
  - 開始時: FPSカメラ名・解像度・錐台奥行きを1行で表示する
  - 終了時: 対象フレーム数のうち視錐台を描画したフレーム数を表示する（無効フレームが1件以上ある場合はその件数も表示する）
  - フレームごとの理由別詳細ログは出さない（NaN由来の無効は `compute_fps_poses()` が理由を返さない仕様のため、内訳表示は不完全になる）
- **受け入れ基準**: 無効フレームを含む入力で「描画 X/N フレーム（非描画 Y フレーム）」形式の表示が出ることをユニットテストで確認できる
- **優先度**: Should

### FR-009: 既定動作の不変（後方互換）

- **機能名**: オプトインと後方互換
- **概要**: `--fps-frustum` を指定しない場合、既存機能の動作（出力画像・連番PNG・MP4・進捗表示・終了コード・既存オプションの挙動）は feat-033 時点の実装と完全に同一とする
- **入力**: 従来と同じ引数
- **出力**: 従来と同一の出力
- **詳細**:
  - 既存の CLI オプション・設定YAMLキー・出力ファイル名・進捗表示は変更しない。`render_fps_video.py` 側のコードは変更しない（import のみ）
  - **対象外（変わることを許容する）**: argparse が生成する usage 行・`--help` の表示・設定YAMLの未知キーエラーに含まれるキー一覧には、新オプション（`--fps-frustum` / `--fps-camera` / `--fps-toml` / `--frustum-depth`）が追加される。これらは同一性の対象に含めない
- **受け入れ基準**: 既存テストが全件パスする
- **優先度**: Must

## 4. 非機能要求

- **パフォーマンス**: FPSポーズ・視錐台頂点の計算は全フレーム一括（ベクトル化）で行い、フレームループ内の追加処理は8線分の投影・可視判定のみとする（既存ボーン描画（最大27辺）と同オーダー以下。処理時間の増加はフレームあたり既存処理の10%以内を目安とし、上限として2倍を超えないこと）
- **対応環境**: phase4 venv（Linux、CUDA GPU 必須。既存要件と同じ）
- **信頼性**: 無効フレームがあっても処理を中断しない（該当フレームのみ視錐台を省略して継続する）

## 5. 制約条件

- 新規ライブラリは追加しない（NumPy / OpenCV / 既存の gsplat 経路のみで実装する）
- FPSポーズ計算は `render_fps_video.compute_fps_poses()` の import 再利用とし、複製実装を禁止する（正本の一元管理。feat-032/033 で確立したパターン）
- `render_fps_video.py` の既存コードは変更しない
- Closed 案件の共有関数（`compute_fps_poses` を含む）の挙動を変更しない

## 6. 優先順位

- **Must**: FR-001, FR-002, FR-003, FR-004, FR-005, FR-006, FR-007, FR-009
- **Should**: FR-008
- **Won't（本案件ではやらない）**:
  - 錐台奥行きの自動決定（人体スケール連動・シーン依存の決定）
  - 視錐台の面塗り（半透明ポリゴン）表示
  - 静止画モード（`--no-keypoints`）への対応
  - 視錐台のみオクルージョンを独立に切り替えるオプション
  - フレームごとの無効理由の詳細ログ
  - 視線方向ベクトル（光軸1本のみの矢印）表示

MVP = Must 全件。FR-008 は実装コストが小さいため同時実装を想定するが、MVP には含めない。

```bash
    data/Blender/point_cloud.ply data/Blender/Config_scene.toml data/Blender/keypoints.npz \
    --camera cam41520554 --fps-frustum --fps-camera cam41520554 \
    --mp4 --output-dir data/feat034_check

TORCH_CUDA_ARCH_LIST="9.0+PTX" uv run python render_keypoints.py \

    --camera cam41520554 --fps-frustum --fps-camera cam41520554 --frustum-depth 1.0 \

```
