# feat-034: render_keypoints.py FPSカメラ視錐台ワイヤフレームの重ね描き

## ステータス

Closed（2026-08-13 手動テスト合格・完了処理済み。イテレーション1で `--fps-toml` を追加）

## 概要

`phase4/render_keypoints.py` の動画モードに、FPSカメラ（頭部キーポイント由来の一人称視点カメラ）の視錐台（view frustum）ワイヤフレームをオクルージョン考慮で重ね描きするオプトイン機能（`--fps-frustum`）を追加する。第三者視点の映像上で「一人称カメラが今どこを向いて・どの範囲を写しているか」を目視確認できるようにする。

## 背景

- feat-027 で NPZ 直読みの一人称視点動画（`render_fps_video.py`）を実装済み。FPSカメラのポーズは頭部7点（LEye/REye/LEar/REar/Nose/Head/Neck）から `compute_fps_poses()` で計算する
- FPS動画単体では「カメラがどこを向いているか」を客観視点で検証しづらい。`render_keypoints.py` の第三者視点レンダリングに視錐台を重ねれば、向き・画角を大体で把握できる（2026-08-13 壁打ちで要件確定。正確さは求めず「大体分かる」ことが目的）
- ポーズ計算の正本は `render_fps_video.compute_fps_poses`（トップレベル import が軽量）であり、feat-032/033 と同じ import 再利用パターンが使える

## 壁打ちで確定した要件（2026-08-13）

- オクルージョン**あり**（ボーンと同じ部分隠蔽機構を流用。既定。`--no-occlusion` には連動）
- FPSカメラの内部パラメータ（FOV）は TOML から取得（`--fps-camera <名前>`）
- 錐台の奥行きは TOML から導出**できない**（K は開き角のみ決める）ため、固定既定値 0.5m ＋ オプションで変更可（案a採用）
- FPSポーズが無効なフレーム（頭部点 NaN・縮退）はワイヤフレームのみ非描画（スケルトンは従来どおり）
- 色はマゼンタ（BGR: 255, 0, 255）
- フラグ未指定時は現行動作と完全に同一（オプトイン）
