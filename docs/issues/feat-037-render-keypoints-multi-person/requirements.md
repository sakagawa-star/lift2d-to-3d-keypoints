# feat-037 要求仕様書: render_keypoints.py 複数人の3Dキーポイント重ね描き

作成日: 2026-10-18
基準: `docs/REQUIREMENTS_STANDARD.md`
入力資料: 2026-10-18 ヒアリング（結果は `README.md` の「ヒアリングで確定した要件」に記録）

## 1. プロジェクト概要

- **何を作るのか**: `phase4/render_keypoints.py` の動画モードで、1人につき1個の C3D ファイルを複数個受け取り、同じ3DGS背景の上に複数人のスケルトン（点＋ボーン）を重ねて描けるようにする
- **なぜ作るのか**: 現状はキーポイント入力が1ファイル＝1人分に限られる。病室内に患者と医療スタッフなど複数人がいる場面で、全員の3D姿勢推定結果を同じ映像の上で確認する手段がない
- **誰が使うのか**: 本プロジェクトの研究者
- **どこで使うのか**: phase4 venv（Linux、torch/gsplat、CUDA GPU 必須）。開発・動作確認はローカル機（gtune2、RTX 5060 Ti）で行う。コマンド例に付す `TORCH_CUDA_ARCH_LIST="9.0+PTX"` はローカル機向けの値（`CLAUDE.md` の「スクリプト実行」参照）

## 2. 用語定義

機能設計書・コード内でも同じ用語を使う。

| 用語 | 定義 |
|---|---|
| 人物 | キーポイント入力ファイル1個が表す1人。1ファイルに2人以上のデータは入っていない前提とする |
| 人物番号 | 位置引数（または設定YAML）に並べたキーポイントファイルの順に 1 から振る整数。人物 P1 = 1番目のファイル |
| 人物ラベル | 画像上に描く文字列 `P<人物番号>`（例: `P1`, `P2`） |
| 複数人モード | キーポイントファイルを2個以上指定した動画モード |
| 1人モード | キーポイントファイルを1個だけ指定した動画モード（feat-036 時点の動作そのもの） |
| フレーム番号 | C3D の `frame_no`（NPZ は `frame_ids`）。既存どおりの意味 |
| 対象フレーム | 全人物のフレーム番号の和集合（`--start-frame` / `--end-frame` 指定時はその範囲内に絞ったもの）。出力の1枚＝対象フレーム1個 |
| 欠席 | ある対象フレームのフレーム番号が、その人物のファイルに無いこと |
| 人物深度 | あるフレームでの、その人物の有効キーポイント（`extract_keypoints` の valid が True の点）の観察カメラ深度（カメラ座標 Z [m]）の算術平均 |
| 観察カメラ | `--camera` で指定する第三者視点カメラ（既存どおり） |
| 有効キーポイント | マーカーが入力に存在し、residual ≥ 0 かつ座標が NaN でない点（既存 `extract_keypoints` の valid 定義） |

## 3. 機能要求一覧

### FR-001: 複数キーポイントファイルの受け付け

- **概要**: 位置引数 `keypoints_path` に1個以上のファイルを並べて指定できる
- **入力**: `ply_path toml_path <ファイル1> [<ファイル2> ...]`
- **出力**: 指定ファイル数ぶんの人物を描いた連番PNG / MP4（出力ファイル名・保存先は既存どおり。人物ごとに別ファイルには分けない）
- **詳細**:
  - 指定ファイル数の上限は設けない
  - 同じパスを2回以上並べることも許容し、別々の人物として扱う（エラーにしない）
  - 位置引数はコマンド上で連続して並べる。`--camera` などのオプションの後ろに続けて位置引数を書くと argparse のエラー（終了コード 2）になる（argparse の仕様。本案件で対処しない）
- **受け入れ基準**: 2個の C3D を指定して実行すると、2人分のスケルトンが同じ画像に描かれる
- **優先度**: Must

### FR-002: 複数人モードの入力形式は C3D に限定

- **概要**: 複数人モードではすべてのファイルを C3D として扱う。NPZ は1人モードでのみ使える
- **入力**: キーポイントファイルのパス
- **出力**: エラーメッセージと終了コード
- **詳細**:
  - 判別方法は既存どおり（拡張子 `.npz`〔大小無視〕なら NPZ、それ以外は C3D）
  - ファイルが2個以上あり、そのうち1個でも NPZ と判別されたら、該当パスを列挙したエラーメッセージを出して終了コード 2 で終了する
  - 1人モードの NPZ 入力は従来どおり動作する
- **受け入れ基準**: `a.c3d b.npz` の指定で終了コード 2 になる。`a.npz` 1個の指定は従来どおり動作する
- **優先度**: Must

### FR-003: 対象フレームの決め方（和集合）

- **概要**: 全人物のフレーム番号の和集合を昇順に並べたものを対象フレームとする
- **入力**: 各人物のフレーム番号
- **出力**: 対象フレームごとの出力画像
- **詳細**:
  - 欠席の人物は、そのフレームでは点・ボーン・人物ラベルのいずれも描かない
  - `--start-frame` / `--end-frame` は和集合に対して適用する（両端含む。既存と同じ意味）。範囲内に対象フレームが1個も無い場合は既存と同じエラーメッセージで終了コード 1
  - 複数人モードで、1個のファイル内で同じフレーム番号が2回以上現れた場合は、人物番号・ファイルパス・フレーム番号を表示して終了コード 1 で終了する（1人モードではこの検査をしない。FR-013）
  - 1人モードの対象フレームは従来どおり「ファイル内のフレームの並び順」のままとする（並べ替えない。FR-013）
- **受け入れ基準**: P1 がフレーム 1〜10、P2 がフレーム 6〜15 のとき、出力は 1〜15 の15枚。1〜5 には P1 だけ、11〜15 には P2 だけが描かれる
- **優先度**: Must

### FR-004: point rate の一致検査

- **概要**: 複数人モードでは、全ファイルの C3D point rate が一致しなければエラーにする
- **入力**: 各ファイルの point rate（既存 `load_c3d_all_frames` の戻り値。取得できない場合は 0.0）
- **出力**: 不一致時のエラーメッセージと終了コード 1
- **詳細**:
  - 一致の判定は float 値の完全一致（`==`）とする。0.0 も1つの値として比較する
  - 不一致時はファイルごとの「人物番号・パス・rate」を列挙して表示する
  - 一致した場合、その共通 rate を既存の point rate と同じ用途（MP4 fps の既定値）に使う
- **受け入れ基準**: rate 30 と 60 の C3D を指定すると終了コード 1。両方 30 なら MP4 は 30fps（`--mp4-fps` 未指定時）
- **優先度**: Must

### FR-005: 人物ごとのマーカー構成とスケルトン

- **概要**: 既知28マーカーの存在判定とスケルトン構築（`build_skeleton`）を人物ごとに行う
- **入力**: 各ファイルのマーカー名リスト
- **出力**: 人物ごとのスケルトン
- **詳細**:
  - 人物ごとにマーカー構成が違ってよい（例: P1 は28点、P2 は22点）
  - 既知マーカーが1個も無いファイルがあれば、人物番号・パス・ラベル一覧を表示して終了コード 1 で終了する（既存の1人モードのエラーを人物単位に拡張したもの）
- **受け入れ基準**: マーカー構成の違う2ファイルで、それぞれの構成に応じたボーンが描かれる
- **優先度**: Must

### FR-006: 3DGS背景とのオクルージョン（人物ごと）

- **概要**: 各人物の点・ボーンに、既存の3DGS深度によるオクルージョン判定を人物ごとに適用する
- **入力**: 既存の深度マップ・αマップ
- **出力**: 3DGS に隠れた部分が描かれない各人物のスケルトン
- **詳細**: 判定ロジック・`--no-occlusion`・`--occlusion-margin`・`--near-plane` の意味は既存と同一。人物同士の関節単位の隠し合いは行わない（FR-007 の描画順のみ）
- **受け入れ基準**: 既存のオクルージョンテストが全件パスし、人物ごとに同じ判定関数が使われる
- **優先度**: Must

### FR-007: 奥の人物から描く

- **概要**: フレームごとに人物深度の大きい（カメラから遠い）人物から順に描き、手前の人物が上に重なるようにする
- **入力**: 各人物の有効キーポイントの観察カメラ深度
- **出力**: 描画順を反映した画像
- **詳細**:
  - 人物深度は有効キーポイント全点で平均する（3DGS に隠れた点、near_plane 以下の点も含める）
  - そのフレームで有効キーポイントが1個も無い人物（欠席を含む）は描かない
  - 人物深度が等しい場合は人物番号の小さい方を先に描く
  - 人物深度が有限値にならない場合（計算結果が NaN・inf）はその人物を描かない
  - 本要求（並べ替え・描かない条件）は複数人モードにだけ適用する。1人モードは従来どおり、その人物を毎フレーム描画処理に渡す（FR-013）
- **受け入れ基準**: P1 がカメラから 2m、P2 が 4m にいるフレームでは P2 → P1 の順で描かれる（P1 が上）。距離を入れ替えると順序も入れ替わる
- **優先度**: Must

### FR-008: 人物ラベルの描画（複数人モードのみ）

- **概要**: 複数人モードでは、各人物の頭部の上に人物ラベル `P<人物番号>` を描く
- **入力**: 各人物の有効キーポイントの投影位置
- **出力**: ラベル文字が追加された画像
- **詳細**:
  - 基準点: その人物の `Head` が有効かつ観察カメラ深度が `--near-plane` より大きければ `Head` の投影位置。そうでなければ、有効かつ深度が `--near-plane` より大きい点のうち画像上で最も上（v 座標が最小）の点。該当点が無ければそのフレームではラベルを描かない
  - 描画位置: 基準点の真上（v が小さい方向）に固定オフセットを空け、文字列の左右中央を基準点の u に合わせる
  - 3DGS による隠蔽・`--no-occlusion` の有無に関係なく常に描く
  - 全人物のスケルトンを描き終えた後に、全人物のラベルを描く（ラベルは最前面）
  - 文字は白、黒の縁取り付き。フォント・大きさ・太さは定数で固定し、CLI オプションは設けない
  - 1人モードではラベルを描かない
- **受け入れ基準**: 2人の入力で、各人物の頭部付近に `P1` / `P2` が描かれる。3DGS に頭部が隠れたフレームでもラベルが描かれる。1人の入力ではラベルが描かれない
- **優先度**: Must

### FR-009: FPS視錐台の対象人物の指定

- **概要**: `--fps-frustum` の視錐台を描く人物を `--fps-person <人物番号>` で1人指定できる。省略時は P1
- **入力**: `--fps-person <int>`（省略可）
- **出力**: 指定人物の頭部から計算した視錐台（他の人物の視錐台は描かない）
- **詳細**:
  - 値域は 1 以上・人物数以下の整数。範囲外は終了コード 2
  - `--fps-frustum` なしで `--fps-person` を指定すると終了コード 2（既存の `--fps-camera` 等と同じ扱い）
  - 頭部7点のマーカー構成チェック（feat-034 FR-007 の 6）は、指定人物のファイルに対してだけ行う
  - 指定人物が欠席のフレームは、頭部欠損と同じく視錐台を描かない（終了時のサマリの非描画数に含める）
  - 視錐台は全人物のスケルトンより下に描く（feat-034 の「視錐台が下」を維持）
  - 1人モードでは `--fps-person` は省略するか 1 を指定する（2 以上は範囲外で終了コード 2）
- **受け入れ基準**: 2人の入力で `--fps-person 2` を指定すると P2 の頭部から視錐台が描かれる。省略時は P1 の頭部から描かれる
- **優先度**: Must

### FR-010: 設定YAML対応

- **概要**: 設定YAML（`--config`、feat-033）で複数ファイルと `--fps-person` を指定できる
- **入力**: 設定YAML
- **出力**: CLI 指定と同じ効果
- **詳細**:
  - `keypoints_path` の値を、`;`（半角セミコロン）区切りの複数パスとして解釈する。各要素の前後の空白は取り除く。`;` を含まない値は従来どおり1個のパス（値全体）として扱い、1人モードになる
  - 空白区切りにしない理由: 既存の運用中の設定YAML（`phase4/data/run_keypoints.yaml`）に空白を含むパスが書かれており、空白区切りにすると従来の1パス指定が壊れるため（2026-10-18 調査で判明）
  - `;` を含むパスは設定YAMLの `keypoints_path` には書けない（CLI の位置引数では指定できる）
  - 区切った結果に空の要素が1個でもある場合（値が空、`a.c3d;` のような末尾の `;`、`a.c3d;;b.c3d`）は、キー名つきのエラー（終了コード 2）にする
  - `fps_person` キーを追加する（int）
  - CLI で位置引数のキーポイントファイルを1個以上書いた場合、設定YAMLの `keypoints_path` は丸ごと置き換えられる（足し合わせない）。優先順位（CLI > 設定YAML > 既定値）は feat-033 と同一
- **受け入れ基準**: `keypoints_path: a.c3d; b.c3d` で2人モードになる。空白を含む1個のパス（例: `keypoints_path: dir/a b.npz`）は従来どおり1個のパスとして扱われる。CLI で `c.c3d` を渡すと1人モード（c.c3d のみ）になる
- **優先度**: Must

### FR-011: 引数の検証

- **概要**: 不正な指定を PLY / torch のロード前に検出して終了する
- **詳細**: 本案件で追加・変更する検証を以下に限定する:
  1. `--no-keypoints` と キーポイントファイル1個以上の併用 → 終了コード 2（既存の検証。判定を「1個以上」に変える）
  2. `--no-keypoints` なしでキーポイントファイルが0個 → 終了コード 2（既存の検証。判定を「0個」に変える）
  3. `--no-keypoints` と `--fps-person` の併用 → 終了コード 2
  4. `--fps-frustum` なしで `--fps-person` を指定 → 終了コード 2
  5. `--fps-person` が 1 未満または人物数より大きい → 終了コード 2
  6. 複数人モードで NPZ が含まれる → 終了コード 2（FR-002）
  7. 複数人モードでのファイル内のフレーム番号重複 → 終了コード 1（FR-003）
  8. point rate 不一致 → 終了コード 1（FR-004）
  9. 既知マーカーが1個も無いファイル → 終了コード 1（FR-005）
  10. ファイルが存在しない・C3D として読めない → 既存の1人モードと同じ扱い（本案件で挙動を変えない）
- **受け入れ基準**: 1〜9 のそれぞれがユニットテストで該当の終了コード・メッセージになる
- **優先度**: Must

### FR-012: 実行時の表示（複数人モード）

- **概要**: 複数人モードでは、読み込み結果を人物ごとに標準出力に表示する
- **詳細**:
  - 人物ごとに、人物番号・パス・フレーム数・描画対象マーカー数・欠損マーカー名を表示する
  - 全体として、人物数・対象フレーム数（和集合）・共通 rate を表示する
  - フレームごとの進捗表示の形式は既存どおり（人物ごとの行は追加しない）
- **受け入れ基準**: 2人の入力で、P1 / P2 それぞれの読み込み結果と全体の行が表示される
- **優先度**: Should

### FR-013: 1人モードの後方互換

- **概要**: キーポイントファイルが1個のとき、動作は feat-036 時点と同一とする
- **詳細**:
  - 出力画像（連番PNG・MP4）、標準出力、終了コード、既存オプションの挙動を変えない
  - **対象外（変わることを許容する）**: argparse の usage 行・`--help` 表示（`keypoints_path` が複数可の表記になり、`--fps-person` が増える）、設定YAMLの未知キーエラーのキー一覧（`fps_person` が増える）、`parse_args_with_config` の戻り値の `keypoints_path` の型（文字列から文字列のリストに変わる）
- **受け入れ基準**: 既存テストが全件パスする（`keypoints_path` の型変更に伴う既存テストの期待値修正は設計書に列挙したものに限る）。実データで1人モードの出力が変更前とバイト同一
- **優先度**: Must

## 4. 非機能要求

- **パフォーマンス**: 背景レンダリングは従来どおり1回のみ。フレームあたりの追加処理は人物数に比例する点・ボーン描画のみとし、人物数 N のときのフレームあたり描画時間は1人時の N 倍＋ラベル描画分を目安とする
- **メモリ**: 全人物の全フレームをメモリに読み込む（既存の1人時と同じ方式を人数分）。上限は設けない
- **対応環境**: phase4 venv（Linux、CUDA GPU 必須。既存と同じ）
- **信頼性**: 欠席・有効点ゼロの人物がいても処理を中断しない（その人物をそのフレームで描かないだけ）

## 5. 制約条件

- 新規ライブラリは追加しない（NumPy / OpenCV / 既存の gsplat 経路のみ）
- 変更対象は `phase4/render_keypoints.py` とテストのみ。`render_fps_video.py` / `npz_to_c3d.py` / `render.py` は変更しない
- 色定数（`COLOR_RIGHT` / `COLOR_LEFT` / `COLOR_CENTER` / `POINT_COLOR`）・`BONE_THICKNESS` は変更しない

## 6. 優先順位

- **Must**: FR-001〜FR-011, FR-013
- **Should**: FR-012
- **Won't（本案件ではやらない）**:
  - 1個の C3D に複数人が入った入力への対応
  - 複数人モードでの NPZ 入力
  - 人物ごとの配色の変更
  - 人物ラベルの文字列の任意指定（ファイル名・任意名）
  - 人物同士の関節・ボーン単位の隠蔽
  - 複数人の視錐台の同時描画
  - point rate が違うファイル同士の時間合わせ（リサンプリング）
  - 静止画モード（`--no-keypoints`）の変更

MVP = Must 全件。

## CLI 仕様（要求レベル）

```bash
# phase4/ ディレクトリ。2人分（P1=patient.c3d, P2=staff.c3d）
TORCH_CUDA_ARCH_LIST="9.0+PTX" uv run python render_keypoints.py \
    data/Blender/point_cloud.ply data/Blender/Config_scene.toml \
    data/patient.c3d data/staff.c3d \
    --camera cam41520554 --near-plane 0.5 --output-dir data/feat037_check --mp4

# FPS視錐台を P2 の頭部から描く
TORCH_CUDA_ARCH_LIST="9.0+PTX" uv run python render_keypoints.py \
    data/Blender/point_cloud.ply data/Blender/Config_scene.toml \
    data/patient.c3d data/staff.c3d \
    --camera cam41520554 --fps-frustum --fps-camera FPSCamera --fps-toml data/Calib_FPSCamera.toml \
    --fps-person 2 --near-plane 0.5 --output-dir data/feat037_check --mp4

# 設定YAML: keypoints_path に ; 区切りで並べる
#   keypoints_path: data/patient.c3d; data/staff.c3d
#   fps_person: 2
TORCH_CUDA_ARCH_LIST="9.0+PTX" uv run python render_keypoints.py --config run_keypoints.yaml
```
