# feat-028 要求仕様書: NPZキーポイントの時間方向平滑化スクリプト

## 1.1 プロジェクト概要

- **何を作るのか**: リフトアップ済み3DキーポイントNPZ（`npz_to_c3d.py` 入力と同一フォーマット）の
  全関節軌跡を時間方向にローパスフィルタで平滑化し、新しいNPZファイルとして書き出す
  コマンドラインスクリプト `phase4/filter_npz.py` を新規作成する。
- **なぜ作るのか**: リフトアップ推定由来のキーポイントはフレームごとに独立な推定ノイズ
  （ジッター）を含む。feat-027（NPZ直読みによる一人称視点動画一括生成）では C3D・Blender
  工程を廃止するため、feat-020 `filter_c3d.py`（C3D→C3D）による既存の平滑化が使えない。
  NPZ 段階で平滑化することで、feat-027 のカメラ視線・映像内の人体の動きを滑らかにする。
- **誰が使うのか**: 本プロジェクトの開発者（一人称視点動画の大量生成を行うユーザー）。
- **どこで使うのか**: Linux（ローカル開発機 gtune2 および A100 GPUサーバー）、
  phase4 の uv 環境（`uv run --project phase4`）。Blender・GPU 不要。

## 1.2 用語定義

| 用語 | 定義 |
|---|---|
| 規約NPZ | `npz_to_c3d.py` の入力規約に従うNPZ。必須キー `x3d_world` (F, J, 3) float・ワールド座標 [m]、`frame_ids` (F,) 昇順連番の絶対フレーム番号、`joint_names` (J,) 関節名 |
| 追加キー | 規約NPZの必須3キー以外のキー（実データでの例: `pnp_ok`, `coord_system`）。意味は問わない |
| 有効サンプル | あるフレーム・ある関節の座標3成分がすべて有限（NaN/Inf でない）のサンプル |
| 無効サンプル | 有効サンプルでないサンプル（座標3成分のいずれかが NaN または Inf） |
| ゼロ位相フィルタ | 順方向・逆方向に2回フィルタを適用して位相遅れを打ち消すフィルタ（`scipy.signal.filtfilt`） |
| カットオフ周波数 | ローパスフィルタの遮断周波数 [Hz]。これより高い周波数成分を減衰させる |
| fps | 入力NPZのサンプリング周波数 [Hz]。NPZには記録されていないためCLIで与える |
| ギャップ | ある関節の時系列中で、有効サンプルに挟まれた無効サンプルの連続区間 |
| セグメント | ある関節の時系列を、長さが最大補間ギャップ長を超えるギャップで区切った連続区間。フィルタはセグメント単位で適用する |
| 最大補間ギャップ長 | 線形補間で埋めてよいギャップの最大フレーム数（`--max-gap`、デフォルト 10）。これを超えるギャップは補間せずセグメント境界とする |
| フレーム間変位 | 隣接フレーム間の座標差のノルム [mm]。ジッターの定量指標として使う |

機能設計書・コード内でも同じ用語を使う。

## 1.3 機能要求一覧

### FR-001: NPZ読み込みと規約検証

- **概要**: 入力NPZから必須3キーと追加キーをすべて読み込み、規約NPZであることを検証する。
- **入力**: NPZファイルパス（位置引数）。
- **出力**: メモリ上の (F, J, 3) 座標配列 [m]、frame_ids 配列（入力のまま）、
  関節名配列（入力のまま。表示用の文字列化は使用箇所で行う）、
  追加キーの配列（キー名→配列の辞書、入力のまま）、入力座標配列の dtype。
- **受け入れ基準**:
  - 実データ `phase4/data/session001_world_22pt.npz`（F=194279, J=22, float32,
    追加キー `pnp_ok`・`coord_system`）を読み込み、形状・キー構成が上記と一致すること。
  - 以下の場合にエラー終了すること（FR-005 の一部）: 必須キー欠落、`x3d_world` が
    3次元配列でない・第3軸が3でない・浮動小数点型でない、`frame_ids` が整数型でない、
    `frame_ids` の形状が (F,) でない、`frame_ids` が昇順連番（隣接差分がすべて1）でない、
    `joint_names` の形状が (J,) でない、F が 0、J が 0。

### FR-002: Butterworthゼロ位相ローパスフィルタによる平滑化

- **概要**: 各関節・各座標成分（X, Y, Z）の時系列に対し、2次Butterworthローパスフィルタを
  `scipy.signal.filtfilt` でゼロ位相適用する（実効4次・位相遅れなし）。feat-020
  `filter_c3d.py` の FR-002 と同一の数式・同一のパラメータ体系とする。
- **入力**: (N,) または (N, 3) の時系列（関節ごと）、カットオフ周波数 [Hz]（`--cutoff`、
  デフォルト 6.0）、サンプリング周波数 [Hz]（`--fps`、必須引数）。
- **出力**: 平滑化された同じ長さの時系列。
- **受け入れ基準**:
  - 一定値の時系列を入力すると出力が同じ一定値になること（許容誤差 1e-6 m）。
  - 低周波正弦波（カットオフの1/10の周波数）はほぼ保存され（振幅誤差5%以内）、
    高周波正弦波（カットオフの5倍の周波数、ただしNyquist未満）は振幅が10%未満に減衰すること。
  - 出力の位相遅れがゼロであること（低周波正弦波のピーク位置がずれないこと。許容1フレーム）。

### FR-003: 無効サンプル（NaN/Inf）の取り扱い

- **概要**: フィルタは連続した時系列を前提とするため、無効サンプルの扱いを以下と定める
  （feat-020 FR-003 と同一方式。2026-08-07 ユーザー確定事項「padlen 未満の短い有効区間は
  フィルタ対象から外す」を含む）。長さが最大補間ギャップ長（`--max-gap`、デフォルト 10
  フレーム）以下のギャップは線形補間で埋めてフィルタ計算に使う。それを超えるギャップは
  補間せず、時系列をギャップの前後でセグメントに分割し、セグメントごとに独立にフィルタする。
  長さがフィルタ適用に必要な最小長（`filtfilt` の既定パディング長 + 1 = 10 サンプル）未満の
  セグメントは平滑化せず入力値のまま出力する。出力では無効サンプル位置の値を入力のまま
  維持する（NaN は NaN のまま。補間値はフィルタ計算のためだけに使い、出力に書き出さない）。
- **入力**: (F, 3) 座標（関節ごと）、最大補間ギャップ長。
- **出力**: 有効サンプル位置のみ平滑化された座標。無効サンプル位置は入力値のまま。
- **受け入れ基準**:
  - 全サンプル有効の関節は全フレーム平滑化されること。
  - 最大補間ギャップ長以下の中間ギャップのある関節で、有効位置が平滑化され、
    無効位置（NaN）が出力でも NaN のままであること。
  - 最大補間ギャップ長を超えるギャップでは補間が行われず、ギャップ前後のセグメントが
    それぞれ独立に平滑化されること（一方のセグメントの値が他方のフィルタ結果に
    影響しないこと）。
  - 先頭・末尾の無効区間（有効サンプルに挟まれていない区間）は補間せず、出力でも
    入力値のままで、フィルタは各セグメント内にのみ適用されること。
  - 長さ 10 サンプル未満のセグメントは平滑化せず入力値のまま出力し、警告メッセージを
    標準出力に表示すること。

### FR-004: NPZ書き出し

- **概要**: 平滑化後の座標を新しいNPZファイルに書き出す。`frame_ids`・`joint_names`・
  すべての追加キーは入力の配列を無加工でコピーする（`pnp_ok` の意味が未確定でも情報を
  失わないため）。`x3d_world` の dtype は入力と同一にする（float32 入力なら float32 で
  書く。フィルタ計算は float64 で行い、書き出し時に入力 dtype へ変換する）。
- **入力**: 平滑化後の (F, J, 3) 座標、入力NPZの全キーの配列。
- **出力**: NPZファイル。出力パスは `--output` で指定、省略時は
  `<入力パスの拡張子除去>_filtered.npz`。
- **受け入れ基準**:
  - 出力NPZを読み戻し、以下がすべて成立すること（書き出し内で読み戻し検証を行い、
    失敗時は出力ファイルを最終パスに残さないこと）:
    キー集合が入力と一致、`x3d_world` の形状・dtype が入力と一致、無効サンプルの
    位置（非有限マスク）が入力と一致、`frame_ids`・`joint_names`・全追加キーの配列が
    入力と完全一致。
  - 一時ファイル経由の原子的書き出しであること（書き出し途中の異常終了で
    最終出力パスに不完全なファイルが残らないこと）。
  - 出力パスが入力パスと同一の場合はエラー終了すること（上書き防止）。

### FR-005: パラメータ検証とエラー終了

- **概要**: 不正な入力・パラメータを検出し、日本語エラーメッセージを stderr に出力して
  終了コード1で終了する。
- **入力**: コマンドライン引数、入力NPZの内容。
- **出力**: stderr へのエラーメッセージ、終了コード。
- **受け入れ基準**: 以下の各条件でエラー終了すること。
  - 入力NPZファイルが存在しない、またはNPZとして読み込めない。
  - FR-001 に列挙した規約違反（必須キー欠落、形状・型不正、frame_ids 非整数型・
    形状不正・非連番、joint_names 形状不正、F=0、J=0）。
  - `--fps` が 0 以下（未指定は argparse の必須引数エラーとする）。
  - カットオフ周波数が 0 以下。
  - カットオフ周波数が Nyquist周波数（fps / 2）以上。
  - `--max-gap` が 0 以下。
  - 出力パスの拡張子が `.npz` でない。
  - 出力パスが入力パスと同一（シンボリックリンク経由で同一実体を指す場合も含む）。

### FR-006: 処理結果のログ出力

- **概要**: 処理内容を標準出力に日本語で表示する。
- **入力**: なし（処理過程の情報）。
- **出力**: 標準出力。以下を表示する:
  入力パス、フレーム数、関節数、`x3d_world` の dtype、追加キー名の一覧（なければ「なし」）、
  fps、カットオフ周波数、最大補間ギャップ長、関節ごとの無効サンプル数（1件以上ある
  関節のみ）、平滑化をスキップしたセグメント（FR-003。関節名と区間）、
  平滑化による座標変位の統計（全有効サンプルの変位ノルムの平均・最大 [mm]）、
  フレーム間変位の平均（平滑化前・平滑化後 [mm]。ジッター低減の定量確認用）、
  出力パス。
- **受け入れ基準**: 正常終了時に上記項目がすべて表示されること。

## 1.4 非機能要求

- **パフォーマンス**: フレーム数 2,160,000（60fps×10時間）・関節数 22 のNPZを
  10分以内に処理する（フィルタ処理はNumPy/SciPyのベクトル演算であり、実際は
  1〜2分以内を想定）。メモリ使用量は 8GB 以下（float64 換算で座標配列1本
  約1.2GB、コピーを含め5本以内に収める）。
- **対応環境**: Linux、Python 3.10（phase4 uv 環境）。GPU不要。Blender不要。
- **信頼性**: 入力NPZは変更しない（読み取りのみ）。出力は原子的書き出しで、
  異常終了時に不完全なファイルを最終パスへ残さない。
- **セキュリティ**: 該当なし（ローカルファイル処理のみ）。

## 1.5 制約条件

- **使用必須ライブラリ**: NumPy、SciPy（`scipy.signal.butter`, `scipy.signal.filtfilt`。
  feat-020 で phase4 に導入済み・新規追加なし）。
- **使用禁止**: Blender API（bpy）、py-c3d（本スクリプトはC3Dを扱わない）。
- **ネットワーク**: 不要（オフライン動作）。
- **メモリ**: 全フレームをメモリに読み込む方式でよい（上記パフォーマンス要求の範囲内）。

## 1.6 優先順位（MoSCoW）

| 要求ID | 優先度 |
|---|---|
| FR-001 NPZ読み込みと規約検証 | Must |
| FR-002 Butterworthゼロ位相フィルタ | Must |
| FR-003 無効サンプルの取り扱い | Must |
| FR-004 NPZ書き出し | Must |
| FR-005 パラメータ検証 | Must |
| FR-006 ログ出力 | Should |

**MVP**: FR-001〜FR-005。実データ `phase4/data/session001_world_22pt.npz` を
平滑化して書き出せること。

**Won't（今回やらないこと）**:

- fps の自動推定、および出力NPZへの fps メタデータ追加（入力規約の変更になるため）。
- フィルタ種類の選択オプション（Savitzky-Golay、移動平均）。Butterworthゼロ位相のみ。
- C3D の入出力対応（feat-020 `filter_c3d.py` が既存）。
- フレーム範囲の抽出・部分処理オプション。
- 平滑化前後の可視化（グラフ・動画生成）。定量確認は FR-006 のフレーム間変位で行う。
- `pnp_ok` の意味の解釈・利用（無加工コピーのみ。扱いは feat-027 側で確定する）。
- feat-027（一人称視点レンダリング）本体。

## 手動テスト（フロー ステップ7 で使用）

- 入力: `phase4/data/session001_world_22pt.npz`（ユーザー指定、git管理外）。
- fps 指定: データ提供元への確認が完了するまでは 30 を暫定使用する（fps はカットオフの
  実効的な強さにのみ影響し、出力の形状・キー構成には影響しない）。
- 確認項目: 終了コード 0、FR-006 の全ログ項目の表示、フレーム間変位（平滑化後）が
  平滑化前より小さいこと、読み戻し検証（FR-004）の通過。
