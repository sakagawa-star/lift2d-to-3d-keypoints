# feat-028: NPZキーポイントの時間方向平滑化スクリプト

## ステータス

Closed（2026-08-07 手動テスト合格。等価性検証は `experiments/c3d-npz-equivalence/report.md`）

## 概要

リフトアップ済み3DキーポイントNPZ（`npz_to_c3d.py` 入力と同一フォーマット: `x3d_world (F,J,3)` / `frame_ids (F,)` / `joint_names (J,)`）を時間方向に平滑化し、新しいNPZとして書き出す独立スクリプト（NPZ→NPZ）を phase4 に作成する。

feat-020 の `filter_c3d.py`（C3D→C3D、Butterworth 2次 filtfilt・ゼロ位相）と同系の平滑化を NPZ 上で行うもの。feat-027（NPZ直読みによる一人称視点動画一括生成）で C3D 工程を廃止するため、平滑化も NPZ 上で行う必要がある。

主要な設計論点（詳細は feat-027 の `hearing-notes.md` を参照）:

- 入力は5〜10時間分（30fps なら54万〜108万フレーム規模）の巨大NPZ。人が不在の区間は NaN 埋め
- filtfilt は NaN をまたぐと伝播するため、feat-020 と同一方式で NaN を扱う: 長さが
  `--max-gap`（既定10フレーム）以下の NaN ギャップは線形補間してフィルタ計算にのみ使い、
  超えるギャップで**セグメント分割して独立に平滑化**する。出力では NaN を NaN のまま維持する
  （補間値を有効値として書き出さない）
- filtfilt の最小サンプル数制約（padlen）未満の短い有効区間は**平滑化せずそのまま出力する**（フィルタ対象から除外。2026-08-07 ユーザー確定）
- カットオフ周波数等のデフォルト値は `filter_c3d.py` から引き継ぐ

## テスト入力（ユーザー指定、2026-08-07）

手動テストの入力は `phase4/data/session001_world_22pt.npz` を使う（git管理外・ローカル実データ）。事実確認済みの内容:

- `x3d_world (194279, 22, 3) float32` / `frame_ids` 0〜194278 連番 / `joint_names` 22点（頭部7点を含む）
- NaN フレーム 340（全点NaNのみ。部分NaNフレームはゼロ）
- 必須3キーに加えて追加キーあり: `coord_system="world"`、`pnp_ok (F,) bool`（True 11,559 / False 182,720。NaN フレームとは不一致）
- `pnp_ok` の意味は不明（データ作成者に問い合わせ中、2026-08-07 時点で回答待ち。ユーザーも把握していない）。**本案件は追加キーを無加工で出力NPZにコピーする方針とし、意味の確定を要しない**。意味の確定が必要になるのは feat-027（False フレームを描くか黒にするか）のみ
