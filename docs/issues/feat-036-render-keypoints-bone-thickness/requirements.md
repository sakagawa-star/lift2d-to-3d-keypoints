# feat-036 要求仕様書: render_keypoints.py ボーン線の太さ変更（視錐台ワイヤフレームは現状維持）

作成日: 2026-09-15
基準: `docs/REQUIREMENTS_STANDARD.md`
入力資料: 2026-09-15 ヒアリング（変更手段は定数のみ・ボーン線 20px・キーポイント円は変更しない・視錐台は変更しない、が確定済み）

## 1. プロジェクト概要

- **何を作るのか**: `phase4/render_keypoints.py` の動画モードで描画するボーン線の太さを 20px に変更し、FPSカメラ視錐台ワイヤフレームの太さは 2px に据え置く
- **なぜ作るのか**: 現状のボーン線（2px）は出力画像・動画上で見にくい。一方で、ボーンと視錐台が同一定数 `LINE_THICKNESS` を共有しているため、この定数を変えるだけでは視錐台まで太くなる
- **誰が使うのか**: 本プロジェクトの研究者（キーポイント重ね描き画像・動画を目視確認する利用者）
- **どこで使うのか**: phase4 venv（torch/gsplat/CUDA 必須）。開発・動作確認はローカル機（gtune2、RTX 5060 Ti）で行う。コマンド例に付す `TORCH_CUDA_ARCH_LIST="9.0+PTX"` はローカル機向けの値である

## 2. 用語定義

機能設計書・コード内でも同じ用語を使う。

| 用語 | 定義 |
|---|---|
| ボーン線 | `draw_overlay()` が隣接キーポイント間（`build_skeleton()` が返す辺）に描く線分。オクルージョン有効時は `BONE_SAMPLES` 個の補間サンプルの可視な隣接ペアごとに描く短い線分の集合 |
| キーポイント円 | `draw_overlay()` が各キーポイント位置に描く黄色の塗りつぶし円（半径 `POINT_RADIUS`） |
| 視錐台ワイヤフレーム | `draw_frustum()` が描くマゼンタの8線分（feat-034、`--fps-frustum` 指定時のみ） |
| 線の太さ | `cv2.line()` の `thickness` 引数に渡すピクセル値 |

## 3. 機能要求一覧

### FR-001: ボーン線の太さを 20px にする

- **機能名**: ボーン線の太さ変更
- **概要**: `draw_overlay()` が描くボーン線の太さを 20px にする
- **入力**: なし（CLI オプション・設定YAMLキーは追加しない。ソース内の定数で定める）
- **出力**: 連番PNG / MP4 上のボーン線が 20px の太さで描かれる
- **詳細**:
  - オクルージョン有効時（既定）・無効時（`--no-occlusion`）の両方の描画経路に適用する
  - ボーンの色、描画順（ボーン → キーポイント円）、部分隠蔽の判定方法は変更しない
- **受け入れ基準**: `draw_overlay()` 内のすべての `cv2.line()` 呼び出しで `thickness` が 20 であることを、オクルージョン有効・無効の両経路についてユニットテストで確認できる
- **優先度**: Must

### FR-002: 視錐台ワイヤフレームの太さを 2px に維持する

- **機能名**: 視錐台ワイヤフレームの太さ据え置き
- **概要**: `draw_frustum()` が描く視錐台ワイヤフレームの太さを、変更前と同じ 2px に保つ
- **入力**: なし
- **出力**: `--fps-frustum` 指定時の視錐台ワイヤフレームが 2px の太さで描かれる（HEAD コミット 7f45093 時点と同一）
- **詳細**:
  - オクルージョン有効時・無効時の両方の描画経路に適用する
- **受け入れ基準**: `draw_frustum()` 内のすべての `cv2.line()` 呼び出しで `thickness` が 2 であることを、オクルージョン有効・無効の両経路についてユニットテストで確認できる
- **優先度**: Must

### FR-003: キーポイント円の大きさを維持する

- **機能名**: キーポイント円の据え置き
- **概要**: キーポイント円の半径は変更前と同じ 4px（`POINT_RADIUS = 4`）に保つ
- **入力**: なし
- **出力**: 変更前と同じ半径のキーポイント円
- **受け入れ基準**: `POINT_RADIUS == 4` であることをユニットテストで確認できる
- **優先度**: Must

### FR-004: その他の既存動作の不変

- **機能名**: 後方互換
- **概要**: 線の太さ以外の既存動作を変更しない
- **入力**: 従来と同じ引数
- **出力**: 線の太さ以外は従来と同一
- **詳細**:
  - CLI オプション・設定YAMLキー・`--help` 表示・出力ファイル名・進捗表示・終了コードは変更しない
  - 静止画モード（`--no-keypoints`、`--distort` 含む）はボーン線を描かないため、出力は従来と同一
- **受け入れ基準**: 既存テストが全件パスする
- **優先度**: Must

## 4. 非機能要求

- **パフォーマンス**: 線の太さ変更のみであり、処理時間の要件は設けない（`cv2.line` の太線描画コストの増加は、1フレームあたりのレンダリング処理全体に対して無視できる規模である）
- **対応環境**: phase4 venv（既存要件と同じ）

## 5. 制約条件

- 新規ライブラリは追加しない
- CLI オプション・設定YAMLキーは追加しない（ヒアリング確定事項）
- `draw_overlay()` / `draw_frustum()` の関数シグネチャ・描画アルゴリズムは変更しない（使用する定数の差し替えのみ）

### 既知の見た目上の影響（要件として許容する）

- ボーン線 20px に対しキーポイント円は直径 8px のため、円はボーン線の幅の内側に収まる。円はボーンの後に描くため上に重なって表示されるが、円の周囲はボーン色で囲まれる
- `cv2.line` は太さ 2 以上で線端を丸く描くため、オクルージョン有効時は可視区間の端でボーン線が最大 10px（太さの半分）隠蔽境界の外側へはみ出す
- 顔周り（Nose–LEye 等）のように画像上で短いボーンは、20px の太さでは線分ではなく塊状に見える

## 6. 優先順位

- **Must**: FR-001, FR-002, FR-003, FR-004
- **Won't（本案件ではやらない）**:
  - 太さの CLI オプション化・設定YAMLキー化
  - 画像解像度に応じた太さの自動調整
  - キーポイント円の半径変更
  - 視錐台ワイヤフレームの太さ変更

MVP = Must 全件。
