# feat-022 要求仕様書: render_keypoints.py --no-png オプション（MP4のみ出力）

## 1.1 プロジェクト概要

- **何を作るのか**: `phase4/render_keypoints.py` に `--no-png` CLIオプションを追加し、`--mp4` と併用したときに連番PNG保存をスキップしてMP4のみを出力できるようにする。
- **なぜ作るのか**: 現状は `--mp4` 指定時も連番PNGが無条件に保存される。PNG保存（`cv2.imwrite` のzlib圧縮）はフルHD 1枚あたり約30〜80msかかり、数万フレーム処理ではこれが支配的ボトルネックとなり総処理時間が数十分〜1時間超になる。MP4だけが必要な用途でこのコストを回避したい。
- **誰が使うのか**: 本プロジェクトの開発者（3DGSレンダリング＋キーポイント重ね描きの動画を確認する用途）。
- **どこで使うのか**: Linux（マシン gtune2、RTX 5060 Ti + CUDA 12.6）上の phase4 uv 環境。`TORCH_CUDA_ARCH_LIST="9.0+PTX"` を付与して実行する。

## 1.2 用語定義

| 用語 | 定義 |
|---|---|
| 連番PNG | フレームごとに `frame_<C3Dフレーム番号:06d>.png` の名前で `--output-dir` に保存される静止画。feat-017 で導入 |
| MP4出力 | `--mp4` 指定時に ffmpeg（h264_nvenc または libx264）へ rawvideo をパイプして `<output_dir>/output.mp4` を生成する機能。feat-007/017 で導入 |
| PNGスキップ | フレームループ内の `cv2.imwrite` 呼び出しを実行しないこと。MP4出力・進捗表示・その他の処理は継続する |

機能設計書・コード内でも同じ用語を使う。

## 1.3 機能要求一覧

### FR-001: --no-png オプションによる連番PNG保存のスキップ

- **機能名**: 連番PNG保存スキップオプション
- **概要**: CLIに `--no-png` フラグ（`action="store_true"`、デフォルトFalse）を追加する。`--no-png` と `--mp4` を両方指定したとき、フレームループ内の連番PNG保存を実行せず、MP4のみを出力する。
- **入力**: コマンドライン引数 `--no-png`（値なしフラグ）。
- **出力**: `--no-png --mp4` 指定時は `<output_dir>/output.mp4` のみが生成される。この実行では `frame_*.png` を1枚も新規生成しない（過去の実行で出力ディレクトリに残存する `frame_*.png` の削除は行わない。非破壊方針）。
- **受け入れ基準**:
  1. 空のディレクトリを `--output-dir` に指定して `--no-png --mp4` で実行完了後、そのディレクトリに `output.mp4` が存在し、`frame_*.png` が0枚である。
  2. `--no-png` を付けない従来コマンド（`--mp4` あり/なし両方）の出力は変更前と同一である（連番PNGが全フレーム分生成され、`--mp4` 時は `output.mp4` も生成される）。
  3. MP4の内容（フレーム数・各フレームの画）は `--no-png` の有無で同一である。
  4. 既存の `frame_*.png` を含むディレクトリを `--output-dir` に指定して `--no-png --mp4` で実行した場合、既存PNGは削除も上書きもされない（実行前後でファイル数・各ファイルの更新日時が変化しない）。

### FR-002: --no-png 単独指定のエラー化

- **機能名**: 出力なし構成の拒否
- **概要**: `--no-png` を指定し `--mp4` を指定しない場合、何も出力されない無意味な構成となるため、処理開始前（PLY読み込み・レンダリングなどの重い処理より前）にエラー終了する。
- **入力**: コマンドライン引数の組み合わせ（`--no-png` あり、`--mp4` なし）。
- **出力**: 標準エラー出力にエラーメッセージ「エラー: --no-png は --mp4 と併用してください（両方省略時は連番PNGのみ出力）」を表示し、終了コード非0（parser.error による終了コード2）で終了する。
- **受け入れ基準**:
  1. `--no-png` のみ指定して実行すると、C3D読み込み・PLY読み込みが始まる前にエラーメッセージを表示して終了コード非0で終了する。
  2. エラーメッセージに `--mp4` との併用が必要である旨が含まれる。

### FR-003: 進捗表示のPNGスキップ対応

- **機能名**: 進捗表示の文言調整
- **概要**: 現在の毎フレーム進捗表示 `[i/n] <png_path> -> mp4` はPNGパスを主体とした文言である。PNGスキップ時はPNGパスを表示せず、`[i/n] frame <C3Dフレーム番号> -> mp4` の形式で表示する。
- **入力**: なし（内部状態 `--no-png` の有無）。
- **出力**: 標準出力の毎フレーム進捗行。PNG保存時は従来どおり `[i/n] <png_path>`（`--mp4` 併用時は末尾に ` -> mp4`）、PNGスキップ時は `[i/n] frame <C3Dフレーム番号> -> mp4`。
- **受け入れ基準**:
  1. `--no-png --mp4` 実行時の進捗行に `.png` のパスが含まれない。
  2. `--no-png` なしの進捗行は変更前と同一である。

## 1.4 非機能要求

- **パフォーマンス**: `--no-png --mp4` 指定時、フレームループの1フレームあたり処理時間からPNG保存分（`cv2.imwrite` の実行時間）が完全に除去されること。それ以外の新たなオーバーヘッド（1フレームあたり1ms超の追加処理）を導入しないこと。
- **対応環境**: 既存の render_keypoints.py と同一（Linux、Python 3.10、phase4 uv 環境、CUDA GPU、ffmpeg）。新規ライブラリの追加はしない。
- **信頼性**: PNGスキップ時もMP4出力の失敗検出（ffmpeg の BrokenPipeError / 終了コード検査）は従来どおり機能すること。既存のffmpegクリーンアップ処理（try/finally）を変更しないこと。
- **セキュリティ**: 該当なし。

## 1.5 制約条件

- 使用ライブラリは現状の render_keypoints.py の依存（OpenCV, NumPy, torch/gsplat, ffmpeg 外部コマンド）から変更しない。
- 既存CLIオプションの名前・意味・デフォルト値を変更しない（後方互換を維持する）。
- プロダクションコードの変更対象は `phase4/render_keypoints.py` の1ファイルに限定する。テストは `tests/test_feat022_no_png.py` を新規追加する。
- `argparse` は `allow_abbrev=False` の現行設定を維持する。
