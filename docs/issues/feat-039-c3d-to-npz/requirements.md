# feat-039 要求仕様書: C3D → NPZ 変換スクリプト

作成日: 2026-10-21
基準: `docs/REQUIREMENTS_STANDARD.md`
入力資料: 2026-10-21 ヒアリング（結果は `README.md` の「ヒアリングで確定した要件」に記録）

## 1. プロジェクト概要

- **何を作るのか**: C3D ファイル（1ファイル = 1人分の3Dキーポイント）を、`phase4/render_fps_video.py` が入力として受け付ける NPZ 形式に変換するスクリプト `phase4/c3d_to_npz.py` を新規作成する
- **なぜ作るのか**: `render_fps_video.py` の入力は NPZ のみで、Pose2Sim が出力した C3D から FPS（一人称視点）動画を作る手段が無い。既存の変換は NPZ → C3D（`npz_to_c3d.py`）の一方向だけである
- **誰が使うのか**: 本プロジェクトの研究者
- **どこで使うのか**: phase4 venv（Linux。GPU 不要）

## 2. 用語定義

機能設計書・コード内でも同じ用語を使う。

| 用語 | 定義 |
|---|---|
| C3D raw 座標 | C3D ファイルに記録された点の座標 `(px, py, pz)`。単位 mm |
| world 座標 | NPZ の `x3d_world` の座標 `(X, Y, Z)`。単位 m。`render_keypoints.py` の `c3d_to_calib` の出力と同じ座標系（キャリブレーション TOML の座標系） |
| 座標変換 | C3D raw 座標から world 座標への変換 `(X, Y, Z) = (pz, px, py) × 0.001`。`render_keypoints.c3d_to_calib` と同一の式。`npz_to_c3d.world_to_c3d_raw` はこの逆変換 |
| 欠損点 | ある1フレームの1マーカーで、次のいずれかに当てはまる点: (a) residual が 0 以上でない（負、または NaN）、(b) 座標に NaN を含む、(c) 座標が厳密に (0, 0, 0)（3成分すべてが 0.0）。`render_keypoints.extract_keypoints`（bug-005 修正後）の無効判定と同じ |
| 有効点 | 欠損点でない点 |
| C3D フレーム番号 | py-c3d の `Reader.read_frames()` が返すフレーム番号（C3D ヘッダの開始フレームから1ずつ増える整数）。`render_keypoints.load_c3d_all_frames` の `frame_no` と同じ |
| 頭部7点 | `render_fps_video.HEAD_JOINT_NAMES` の7マーカー（`LEye`, `REye`, `LEar`, `REar`, `Nose`, `Head`, `Neck`）。`render_fps_video.py` が FPS カメラのポーズ計算に使う |

## 3. 機能要求一覧

### FR-001: C3D を NPZ に変換する

- **概要**: C3D ファイル1個を読み込み、NPZ ファイル1個を書き出す
- **入力**: 位置引数 `c3d_path`（入力 C3D パス）
- **出力**: NPZ ファイル。キーは次の3個に限定する（`npz_to_c3d.load_npz` の必須キー）
  - `x3d_world`: (F, J, 3) float64、world 座標 [m]。F = C3D のフレーム数、J = C3D のマーカー数
  - `frame_ids`: (F,) int64、C3D フレーム番号
  - `joint_names`: (J,) の文字列配列（numpy の Unicode 文字列型）。C3D のマーカー名（前後の空白を除去したもの）を C3D 内の順に並べたもの
- **詳細**:
  - C3D の全マーカーを書き出す（既知28マーカーへの絞り込みはしない）
  - 座標は「座標変換」で world 座標にする
  - 全フレームを書き出す（フレーム範囲の指定機能は持たない）
- **受け入れ基準**: 出力 NPZ を `npz_to_c3d.load_npz` で読み込むとエラーにならず、`x3d_world` の形状が (C3D フレーム数, C3D マーカー数, 3)、`joint_names` が C3D のマーカー名と一致する。有効点の `x3d_world` が、同じ点の C3D raw 座標に `render_keypoints.c3d_to_calib` を適用した値と一致する
- **優先度**: Must

### FR-002: 欠損点を NaN にする

- **概要**: 欠損点の `x3d_world` を3成分とも NaN にする
- **入力**: C3D の各点の座標と residual
- **出力**: NaN を含む `x3d_world`
- **詳細**:
  - 欠損点の判定は「欠損点」の定義（a）〜（c）に従う
  - Pose2Sim 出力の C3D（欠損を residual 0・座標 (0,0,0) で表す）と、`npz_to_c3d.py` 製の C3D（欠損を residual −1 で表す）のどちらも、欠損点が NaN になる
  - 座標の1成分以上が 0.0 でない点（例: (0, 0, 5)）は有効点として扱う
- **受け入れ基準**: residual −1 の点、residual が NaN の点、座標 (0,0,0) の点、座標に NaN を含む点が NaN になる。座標 (0, 0, 5) mm の点は NaN にならない
- **優先度**: Must

### FR-003: フレーム番号は C3D の番号をそのまま使う

- **概要**: `frame_ids` に C3D フレーム番号をそのまま書く（付け直し・オフセットはしない）
- **詳細**:
  - 例: tokyo 20261006 の Pose2Sim 出力 C3D（ファイル名 `..._0-54006.c3d`）の C3D フレーム番号は 1〜54007 であり（2026-10-21 実測）、`frame_ids` も 1〜54007 になる。ファイル名や元動画のフレーム番号（0 始まり）とは 1 ずれる。ユーザーはこのずれを了承済み（2026-10-21）
  - py-c3d の `read_frames()` は開始フレームから1ずつ増える番号を返すため、`frame_ids` は昇順の連番になる（`load_npz` の連番要件を満たす）
- **受け入れ基準**: 開始フレーム 1 の C3D からは 1 始まり、開始フレーム 100 の C3D からは 100 始まりの連番の `frame_ids` になる
- **優先度**: Must

### FR-004: 出力パス

- **概要**: 出力 NPZ のパスを決める
- **入力**: `--output <パス>`（省略可）
- **詳細**:
  - 省略時は、入力 C3D パスの拡張子を `.npz` に置き換えたパス（同じディレクトリ・同じ basename）
  - 出力パスの拡張子（大小無視）が `.npz` でなければ、エラーメッセージを出して終了コード 1
  - 出力パスが入力 C3D パスと同一（絶対パスで比較）なら、エラーメッセージを出して終了コード 1
  - 出力パスに既存ファイルがある場合は上書きする（`npz_to_c3d.py` と同じ）
  - 出力ディレクトリが存在しない場合は作成しない（書き込み失敗としてエラー終了コード 1）
- **受け入れ基準**: `a.c3d` のみ指定で `a.npz` が作られる。`--output b.txt` は終了コード 1
- **優先度**: Must

### FR-005: 書き出しの安全性

- **概要**: 書き出しに失敗したときに、不完全な NPZ を出力パスに残さない
- **詳細**: 一時ファイルに書き出し、読み戻して検証（FR-001 のキー・形状・`frame_ids`・`joint_names`・NaN の位置が書き出し前と一致）に成功した場合だけ出力パスに確定する。失敗時は一時ファイルを削除し、終了コード 1。一時ファイルから出力パスへの確定（置き換え）に失敗した場合も、一時ファイルを削除して終了コード 1 とし、出力パスにある既存のファイル・ディレクトリは変更しない。一時ファイルは出力と同じディレクトリに、既存のどのファイル名とも重ならない新しい名前で作成し、既存のファイル（シンボリックリンクのリンク先を含む）を一時ファイルとして書き換えない
- **受け入れ基準**: 読み戻し検証が失敗するように細工したテストで、出力パスにファイルが作られず、一時ファイルも残らない。出力パスが既存のディレクトリのとき、終了コード 1 で一時ファイルが残らず、ディレクトリはそのまま残る
- **優先度**: Must

### FR-006: 入力のエラー

- **概要**: 変換できない入力を検出して終了する
- **詳細**: 次の場合、エラーメッセージを標準エラーに出して終了コード 1 で終了する
  1. 入力ファイルが存在しない
  2. 入力が C3D として読めない
  3. C3D のフレームが0件
  4. C3D のマーカーが0個
  5. C3D のマーカー名に重複がある（重複している名前を表示する）
  6. C3D のマーカー名に空文字列（空白除去後）がある
  7. C3D が途中で切れている（ヘッダが宣言するフレーム数より、実際に読み込めたフレーム数が少ない）。宣言フレーム数と読み込みフレーム数を表示する。py-c3d は途中の EOF で例外を送出せず、読めたフレームだけを返すため（2026-10-21 Codex レビューで確認）、この検査が無いと欠けた NPZ が正常終了で書き出される
- **受け入れ基準**: 1〜7 のそれぞれがユニットテストで終了コード 1 になる。7 では出力パスの既存ファイルが変更されない
- **優先度**: Must

### FR-007: 実行時の表示

- **概要**: 変換の内容を標準出力に表示する
- **詳細**: 次を表示する
  - 入力パス、C3D のフレーム数・マーカー数・point rate [Hz]
  - `frame_ids` の範囲（最初と最後の番号）
  - 欠損点の数（全点数に対する件数）と、その内訳（(a) residual が 0 以上でない点数、座標 (0,0,0) の点数、座標に NaN を含む点数。1点が複数に当てはまる場合はそれぞれに数える）
  - 頭部7点のうち C3D に無いマーカーがあれば、警告（標準エラー）として列挙し、`render_fps_video.py` の入力に使えないことを示す。この場合も変換は行い、終了コードは 0
  - 完了時に出力パス
- **受け入れ基準**: 実データで各項目が表示される。頭部マーカーの無い C3D で警告が出て終了コード 0
- **優先度**: Should

## 4. 非機能要求

- **パフォーマンス**: tokyo 20261006 の C3D（54,007 フレーム × 26 マーカー）の変換が 60 秒以内に終わる（ローカル機 gtune2）
- **メモリ**: 全フレームをメモリに読み込む。上限は設けない（54,007 フレーム × 26 マーカーで `x3d_world` は約 34 MB）
- **対応環境**: phase4 venv（Linux）。GPU・torch は使わない
- **信頼性**: FR-005 のとおり、失敗時に不完全な出力を残さない

## 5. 制約条件

- 新規ライブラリは追加しない（NumPy と、phase4 venv 既存の py-c3d のみ）
- 既存ファイル（`render_fps_video.py` / `render_keypoints.py` / `npz_to_c3d.py` / `filter_npz.py`）は変更しない
- 座標変換と C3D の読み込みは既存の `render_keypoints.c3d_to_calib` / `render_keypoints.load_c3d_all_frames` と同じ結果にする

## 6. 優先順位

- **Must**: FR-001〜FR-006
- **Should**: FR-007
- **Won't（本案件ではやらない）**:
  - `render_fps_video.py` での C3D 直読み
  - フレーム番号の付け直し・オフセット指定
  - 既知28マーカーへの絞り込み・マーカー名の変換
  - フレーム範囲の切り出し
  - 平滑化（必要なら変換後に `filter_npz.py` を使う）
  - 複数 C3D の一括変換・1個の NPZ への結合
  - point rate の NPZ への保存（`render_fps_video.py` は `--fps` で別途指定する）

MVP = Must 全件。
